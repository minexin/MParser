# MParser v0.11 Scope

MParser v0.11 adds a repeatable runtime benchmark layer. It measures the HIR
interpreter and bytecode VM against the same already-parsed and already-lowered
program, then verifies that both paths produce identical runtime variables.

## Added Since v0.10

- New `RuntimeBenchmarkRunner` reusable API.
- Portable timing through C++ `std::chrono::steady_clock`.
- Configurable warmup and measured iteration counts.
- Alternating interpreter/VM measurement order to reduce ordering bias.
- Total, mean, median, minimum, and maximum runtime measurements.
- Mean bytecode instruction count per VM run.
- Exact output comparison for the currently supported runtime value kinds:
  missing, scalar number, string, vector, and matrix.
- Explicit benchmark failure when a runtime reports diagnostics, does not
  finish every iteration, or produces a different result.
- CLI option `--benchmark-runtime`.
- CLI controls `--benchmark-warmup=N` and
  `--benchmark-iterations=N`.
- New benchmark sample and smoke test.
- Project version and CLI version bumped to `0.11.0`.

## Why This Matters

Performance work now has a measurable baseline:

```text
same semantic HIR + same bytecode
             |              |
             v              v
      HIR interpreter    bytecode VM
             |              |
             +---- output comparison
             +---- timing statistics
```

Parsing, semantic analysis, and bytecode lowering are deliberately outside the
timed section. This isolates runtime execution cost and gives future typed IR
and JIT paths a stable comparison contract.

The current VM also collects a full execution profile on every run. Its v0.11
benchmark result therefore includes profiling overhead. That is useful as the
current end-to-end runtime baseline; later milestones can add a profile-off
mode and compare specialized execution against both baselines.

## CLI Example

```powershell
build\mparser.exe --benchmark-runtime `
  --benchmark-warmup=3 `
  --benchmark-iterations=20 `
  samples\runtime_benchmark_demo.m
```

The output shape is:

```text
Runtime benchmark (parse and lowering excluded):
  warmup iterations: 3
  measured iterations: 20
  HIR interpreter: completed=20, totalMs=..., meanUs=..., medianUs=...
  bytecode VM: completed=20, totalMs=..., meanUs=..., medianUs=...,
    instructionsPerRun=...
  bytecode VM speed relative to interpreter: ...x
  outputs: match (runtime outputs match)
```

Timing values depend on CPU, build type, background load, and compiler
optimization. Compare results only when those conditions are controlled.

## Current Pipeline

```text
HIR
  -> bytecode
  -> bytecode VM profile
  -> optimization plan
  -> typed IR
  -> guard evaluation

HIR interpreter ----+
                    +-> runtime benchmark + output equivalence
bytecode VM --------+
```

## Remaining Before v1.0

MParser is not ready for a v1.0 label. Major remaining work includes:

- Model executable bytecode region boundaries and side effects.
- Execute selected typed IR regions behind runtime guards.
- Fall back to bytecode execution when a guard fails.
- Add a VM mode that can disable profiling after specialization.
- Add optimized release-build benchmark presets and machine-readable results.
- Expand MATLAB runtime coverage for objects, cells, structs, complex values,
  sparse arrays, dynamic dispatch, and broader builtin behavior.

```powershell
ctest --test-dir build --output-on-failure
build\mparser.exe --version
build\mparser.exe --benchmark-runtime `
  --benchmark-warmup=1 `
  --benchmark-iterations=5 `
  samples\runtime_benchmark_demo.m
```

Expected version output:

```text
MParser 0.11.0
```

The benchmark must report completed iterations and `outputs: match`.

## Next Iteration

The next high-value milestone is executable region modeling:

- Attach bytecode begin/end PCs to optimization candidates and typed regions.
- Record region inputs, outputs, and writes.
- Reject regions with unsupported control flow or observable side effects.
- Use those contracts as the boundary for a small scalar typed executor.
