# MParser v0.13 Scope

MParser v0.13 executes the first typed optimization region. Eligible closed
scalar `for` loops can now bypass the ordinary VM body dispatch through a
transactional scalar stack executor, with automatic bytecode fallback when
entry values do not satisfy the region contract.

## Added Since v0.12

- New `ScalarTypedRegionExecutor`.
- Scalar execution for numeric `LoadName`, `LoadLiteral`, `StoreName`, unary,
  binary, scalar postfix, and `Pop` instructions.
- Numeric scalar loop ranges from scalar, vector, or matrix runtime values.
- Transactional variable frames: region writes are committed only after every
  iteration and stack-boundary check succeeds.
- Explicit `Executed` and `Fallback` outcomes with diagnostic reasons.
- Runtime checks for every external input and loaded value.
- A typed-aware `BytecodeVm::run` overload that accepts a typed IR module.
- VM dispatch replacement for eligible scalar loop regions.
- Preservation of normal loop profile counts after typed execution.
- Per-region execution reports: eligibility, attempts, executions, fallbacks,
  iterations, typed instruction count, and last reason.
- CLI option `--run-typed-bytecode`.
- Two-pass CLI execution: profile/build the typed module, then run it and
  require exact output equivalence with the baseline VM result.
- Success, dynamic fallback, transactional fallback, and static rejection
  tests.
- New fallback demonstration sample.
- Project version and CLI version bumped to `0.13.0`.

## Why This Matters

The optimization pipeline now crosses from analysis into execution:

```text
baseline bytecode run
  -> profile
  -> region analysis + typed IR
  -> second VM run
       -> eligible scalar loop: transactional typed executor
       -> failed entry/runtime check: unchanged-state bytecode fallback
       -> ineligible region: bytecode only
  -> compare final variables with baseline
```

Fallback never commits a partially executed typed frame. This is the same
correctness shape needed by a future native JIT: optimized code may either
finish and commit, or return control without corrupting interpreter state.

## Successful Execution

```powershell
build\mparser.exe --run-typed-bytecode samples\typed_region_demo.m
```

Expected signals:

```text
region=0, kind=scalar-loop, eligible=yes, attempts=1, executions=1
fallbacks=0, iterations=100, typedInstructions=600
reason=typed scalar loop executed
baseline outputs: match
```

For this sample, the ordinary VM dispatches the six-instruction loop body 100
times. The typed executor runs the same 600 scalar operations inside one region
attempt and the VM jumps directly to the loop exit.

## Dynamic Fallback

```powershell
build\mparser.exe --run-typed-bytecode `
  samples\typed_region_fallback_demo.m
```

The region is structurally eligible, but `y` is a vector at entry. The report
therefore shows one attempt and one fallback:

```text
executions=0, fallbacks=1
reason=typed region input is not scalar numeric: y
baseline outputs: match
```

## Static Rejection

```powershell
build\mparser.exe --run-typed-bytecode `
  samples\bytecode_profile_demo.m
```

The hot loop contains a local function call, so it remains ineligible and is
never attempted.

## Current Limitations

- Typed execution is a deliberate two-pass mode, not an adaptive in-process
  tiering loop yet.
- Only closed scalar `for` loop bodies are executable.
- Calls, indexing, arrays, mutation, nested control flow, and unsupported
  operations fall back or remain ineligible.
- The scalar executor is portable C++ and is not native machine code.
- Typed execution still collects the surrounding VM profile.
- Entry guards use region inputs and loop values; broader live call-site guard
  capture remains future work.

## Remaining Before v1.0

- Add typed execution to the benchmark runner and measure dispatch reduction.
- Add profile-off VM execution after specialization.
- Support adaptive hot-loop promotion within one VM lifetime.
- Lower typed scalar operations to LLVM ORC JIT on Windows and ARM Linux.
- Extend closed-region support to conditionals, calls, indexing, and arrays.
- Add deoptimization metadata for native frames and resume PCs.
- Expand MATLAB runtime coverage for objects, cells, structs, complex values,
  sparse arrays, dynamic dispatch, and broader builtin behavior.
