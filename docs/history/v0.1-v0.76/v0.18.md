# MParser v0.18 Scope

MParser v0.18 adds explicit and persistent runtime workspaces. Adaptive
execution can now observe changing external state, invalidate an incompatible
specialization, retrain from new values, and successfully promote a replacement
typed module.

## Added Since v0.17

- `BytecodeVmOptions::initialWorkspace` for injecting outer-frame variables.
- Initial workspace support in both profiled and profile-off VM runs.
- `BytecodeWorkspaceInputProfile` with kind, shape, count, and stability.
- Full profile output for injected workspace values.
- Cross-invocation merging of workspace entry observations.
- Adaptive `preserveWorkspace` policy.
- Adaptive initial workspace configuration.
- Session workspace inspection and replacement APIs.
- Reset restores the configured initial workspace.
- Retraining evidence now considers only assignments executed before the region.
- Workspace entry evidence is used when no preceding assignment defines an
  external region input.
- CLI option `--adaptive-persist-workspace`.
- Repeatable CLI option `--adaptive-workspace=name=value`.
- CLI parsing for scalar numbers, quoted strings, and numeric row vectors.
- A persistent script sample that changes a loop input from scalar to vector and
  back to scalar.
- Tests for single-run workspace injection, entry profiling, profile-off
  behavior, persistent state, invalidation, retraining, replacement promotion,
  and final typed execution.
- Project version and CLI version bumped to `0.18.0`.

## VM Workspace Contract

`BytecodeVmOptions::initialWorkspace` is copied into the outer frame before
script execution begins:

```text
initial workspace
  -> outer VM frame
  -> script/function execution
  -> result variables
```

For full profiling, each injected variable also produces an entry observation.
Profile-off execution receives the same values but does not allocate or return
workspace profiles.

Entry injection is most directly useful for scripts. A function entry may still
initialize declared outputs or create isolated local call frames according to
the existing function semantics.

## Persistent Adaptive Session

With `preserveWorkspace=true`, every successful invocation replaces the
session workspace with its complete result variables. The next invocation uses
that snapshot as its initial workspace. Diagnostics do not commit a new
workspace snapshot.

This gives adaptive tiering a controlled source of changing external values:

```text
result workspace N -> initial workspace N+1
```

## Full Retraining Cycle

```powershell
build\mparser.exe --run-adaptive-bytecode --adaptive-runs=7 `
  --adaptive-hot-loop=10 --adaptive-fallback-limit=2 `
  --adaptive-persist-workspace --adaptive-workspace=phase=0 `
  samples\adaptive_workspace_demo.m
```

The sample changes `y` according to the persistent `phase` value:

- invocations 1-2: scalar `y`, cumulative profiling, first promotion;
- invocations 3-4: vector `y`, two typed fallbacks, invalidation;
- invocations 5-6: scalar `y`, fresh profiling, replacement promotion;
- invocation 7: profile-off typed success.

Expected event order:

```text
promotion
typed-fallback
typed-fallback
invalidation
promotion
typed-execution
```

Expected final values:

```text
i = 6
phase = 7
y = 91
```

The first promotion and replacement promotion refer to the same bytecode source
region but are built from different post-invalidation profile generations.

## Retraining Evidence Order

For each external region input, adaptive retraining uses:

1. all observed assignments to that name with `pc < region.sourcePc`;
2. the workspace entry observation when no preceding assignment was observed.

Every selected observation must remain stable scalar numeric. Assignments in
the loop body are no longer treated as proof of the value present at region
entry.

## Current Limitations

- The workspace API copies values between invocations.
- Persistent mode commits the complete outer frame rather than a selective
  export set.
- Function parameters cannot yet be supplied by name through the workspace.
- CLI workspace literals cover numbers, strings, and one-dimensional numeric
  vectors only.
- There is no persistent handle/object identity or reference semantics.
- Tiering and retraining still occur synchronously at invocation boundaries.
- The typed executor is portable scalar C++, not native machine code.

## Remaining Before v1.0

- Add parameterized entry-function invocation and output selection.
- Separate script workspace persistence from function argument frames.
- Add persistent cells, structs, objects, and handle identity.
- Add per-region replacement without invalidating unrelated regions.
- Add native LLVM ORC compilation on Windows and ARM Linux.
- Define native frame maps, deoptimization values, and resume PCs.
- Extend typed regions to conditionals, calls, indexing, arrays, and matrices.
- Expand MATLAB class/object and builtin compatibility.

## Next Iteration

The next milestone should expose reusable function invocation:

- Select an entry function by name.
- Pass positional runtime arguments without rewriting source.
- Return declared outputs separately from diagnostic workspace variables.
- Preserve profile/tiering state across calls with different argument values.
- Use parameter observations as first-class typed-region guards.
