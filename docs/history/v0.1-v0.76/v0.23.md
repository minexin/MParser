# MParser v0.23 Scope

MParser v0.23 establishes the first executable Cell and variadic-function
runtime layer. It extends the v0.22 call contract without changing the public
entry, module, or adaptive runtime APIs.

## Added Since v0.22

- Recursive `RuntimeValueKind::Cell` values with one-dimensional shape metadata.
- Cell literal execution for `{a, b, ...}` in both the HIR interpreter and bytecode VM.
- Scalar one-based brace reads, `C{n}`.
- Scalar one-based brace writes, `C{n} = value`, including Cell growth.
- `MakeCell`, `BraceIndex`, and `StoreBraceIndex` bytecode execution.
- Shared function signatures distinguish fixed parameters/outputs from
  `varargin`/`varargout`.
- Variadic entry and local-function arguments bind excess inputs into
  `varargin` Cells.
- Variable outputs are collected from `varargout{n}` when requested output
  count exceeds fixed outputs.
- Named variable outputs are reported as `varargout1`, `varargout2`, and so on.
- `CompiledModule` preflight and adaptive module sessions accept variadic calls.
- `samples/cell_varargs_demo.m` and a fifteenth CTest target covering Cells,
  variadic entries, local calls, requested output counts, and adaptive runtime
  reuse.
- Project and CLI version bumped to `0.23.0`.

## Variadic Contract

```text
function [fixed, varargout] = f(required, varargin)

actual inputs beyond required -> varargin{1}, varargin{2}, ...
requested outputs beyond fixed -> varargout{1}, varargout{2}, ...
```

`nargin` remains the number of actual arguments and `nargout` remains the
requested output count. A function without `varargin` still requires exactly
its fixed input count; a function without `varargout` still rejects excessive
output requests before execution.

## CLI Example

```powershell
build\mparser.exe --run-bytecode `
  --entry-function=cell_varargs_demo --argument=1 --argument=2 --argument=3 `
  --outputs=4 samples\cell_varargs_demo.m
```

Expected public results:

```text
Function outputs (cell_varargs_demo):
  input_count = 3
  first_extra = 2
  varargout1 = 3
  varargout2 = 4
```

## Current Limitations

- Cell values are one-dimensional; multi-subscript `C{row, column}` is not executable.
- Cell literals preserve a flat element sequence; Cell row/column separators do
  not yet establish multidimensional shape.
- `C{n}` accepts one scalar numeric subscript only.
- Comma-separated-list expansion is not implemented for calls, assignments, or
  Cell arguments. `varargin` and `varargout` are the supported Cell bridge.
- Missing unassigned `varargout` slots return the runtime missing value.
- Classes, objects, method dispatch, structs, sparse arrays, complex values,
  and native machine-code JIT remain outside this milestone.

## Validation

```powershell
cmake -S . -B build -G Ninja
cmake --build build --clean-first
ctest --test-dir build --output-on-failure
build\mparser.exe --version
build\mparser.exe --run-bytecode `
  --entry-function=cell_varargs_demo --argument=1 --argument=2 --argument=3 `
  --outputs=4 samples\cell_varargs_demo.m
```

Expected version output:

```text
MParser 0.23.0
```

## Next Iteration

- Add multidimensional Cell shape and multi-subscript brace indexing.
- Implement comma-separated-list expansion at call and assignment boundaries.
- Lower statement calls with a true zero-output local request.
- Add per-signature specialization caches with bounded eviction.
- Add package/path lookup and executable method/constructor entry resolution.
- Introduce native LLVM ORC compilation for Windows and ARM Linux.
