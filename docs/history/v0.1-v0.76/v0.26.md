# MParser v0.26 Scope

MParser v0.26 turns retained superclass metadata into executable same-file
class hierarchies. It adds inherited state and dispatch while keeping hierarchy
resolution separate from class collection, so declaration order does not
change behavior.

## Added Since v0.25

- Semantic member lookup walks superclass graphs after HIR lowering and repairs
  delayed member/call bindings when a superclass is declared later in the file.
- Inherited property declarations are merged into each derived object layout.
- Instance and static methods are inherited through the resolved hierarchy.
- Subclass methods override inherited methods and profile under the class that
  actually declared the executed implementation.
- Constructors remain class-local and are not inherited as ordinary methods.
- Handle ownership propagates transitively through user-defined superclasses.
- Multiple inheritance accepts a shared property or method declaration reached
  through a common ancestor without duplicating it.
- A method override from a more specific branch dominates the common ancestor
  implementation regardless of superclass list order.
- A subclass override resolves otherwise unrelated inherited method conflicts.
- Unresolved method/property conflicts, missing same-file superclasses, cyclic
  hierarchies, and inherited-property redeclarations produce source diagnostics.
- `samples/class_inheritance_demo.m` and an eighteenth CTest target cover
  forward superclass declarations, inherited state, instance/static dispatch,
  overrides, handle aliases, valid diamonds, ambiguity, missing bases, and
  cycles.
- Project and CLI version bumped to `0.26.0`.

## Example

```powershell
build\mparser.exe --run-bytecode samples\class_inheritance_demo.m
```

Expected values:

```text
alias = <CounterEntity>
base_property = 8
derived_property = 4
inherited_value = 8
item = <CounterEntity>
override_value = 12
static_value = 10
```

## Resolution Contract

- A member declared by the most-derived class wins.
- Repeated paths to the exact same common-ancestor declaration are merged.
- Between different inherited method definitions, a declaring class that is a
  strict subclass of the other declaring class wins.
- Unrelated inherited method definitions are ambiguous unless the derived class
  declares its own method with that name.
- Independent same-name property declarations are conservatively ambiguous;
  only the same declaration inherited through a common ancestor is merged.
- The built-in `handle` root contributes ownership semantics but no executable
  lifecycle or comparison methods yet.

## Current Limitations

- Only classes present in the same compiled source are runtime-resolvable.
  Package folders, class folders, imports, and MATLAB path lookup are not yet
  connected to the class registry.
- Superclass constructors are neither called implicitly nor expressible with
  `obj@Superclass(...)`; derived constructors must currently initialize
  inherited fields directly.
- Explicit superclass method calls such as `method@Superclass(obj, ...)` are
  not parsed or executed.
- Independent properties with textually equivalent definitions are not yet
  merged because defaults, validation, and full property attributes are not in
  runtime metadata.
- Access, `Abstract`, `Sealed`, and `HandleCompatible` rules are not enforced.
- Property defaults, validation, events, enumerations, dependent properties,
  overloaded operators, object arrays, and handle lifecycle remain future work.
- Class execution remains a bytecode-VM feature; the reference HIR interpreter
  does not execute objects.
- Native machine-code JIT and non-scalar object layout remain future work.

## Next Iteration

- Parse and execute explicit superclass constructor and method calls.
- Add implicit no-argument superclass construction with deterministic state
  initialization.
- Preserve property defaults, validation, and access metadata in runtime class
  descriptors.
- Enforce `Abstract`, `Sealed`, access, and handle-compatibility constraints.
- Add package/path class discovery and reusable class module entries.
- Introduce native LLVM ORC compilation on Windows and ARM Linux.
