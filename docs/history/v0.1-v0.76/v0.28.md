# MParser v0.28 Scope

MParser v0.28 turns MATLAB property declarations into executable runtime
contracts. Property syntax is no longer retained only as raw text: dimensions,
class constraints, validation functions, attributes, and default expressions
now cross the syntax, HIR, bytecode, and class-runtime boundaries.

## Major Capability

- `PropertySpec` records ordered dimensions, class names, validators and their
  literal arguments, explicit-default state, source spans, and property-block
  attributes.
- Default expressions remain structured expression children and lower into
  dedicated `EnterPropertyInitializer`/`LeavePropertyInitializer` ranges.
- The runtime evaluates an explicit default lazily on first class use and only
  once per declaring property within a bytecode run. Cached handle-object
  defaults remain shared;
  cached value data is copied into each object.
- Effective inherited property layouts preserve declaration order. A common
  property reached through a diamond retains one descriptor and one default
  cache.
- All effective defaults are installed before superclass or derived
  constructor bodies execute.
- Supported implicit defaults include shaped numeric/logical zeros, shaped
  character data, Cells, scalar strings, and scalar same-file class objects.
- Direct member assignment runs class conversion, size adaptation, and
  validators in order. A failure leaves the previous field value unchanged.
- Project and CLI version are `0.28.0`; CTest now contains 20 targets.

## Supported Validation Subset

Class constraints currently execute for `double`, `logical`, `char`, scalar
`string`, `cell`, `handle`, and same-file user classes. User-class validation
accepts derived objects.

One- and two-dimensional declarations retain positive integer and `:`
dimensions. The runtime supports exact shape checks, numeric scalar expansion,
and row/column reshaping when the element count is compatible.

These validators execute left to right:

- Numeric: `mustBePositive`, `mustBeNonpositive`, `mustBeNonnegative`,
  `mustBeNegative`, `mustBeFinite`, `mustBeNonNan`, `mustBeNonzero`,
  `mustBeInteger`, `mustBeReal`, `mustBeFloat`, `mustBeNumeric`,
  `mustBeNumericOrLogical`, `mustBeNonsparse`, and `mustBeSparse` (which
  diagnoses because sparse values are not represented yet).
- Shape/text: `mustBeNonempty`, `mustBeScalarOrEmpty`, `mustBeVector`,
  `mustBeRow`, `mustBeColumn`, `mustBeMatrix`, `mustBeText`,
  `mustBeTextScalar`, `mustBeNonzeroLengthText`, and `mustBeNonmissing`.
- Numeric comparisons: `mustBeGreaterThan`, `mustBeLessThan`,
  `mustBeGreaterThanOrEqual`, and `mustBeLessThanOrEqual`, with the property
  name followed by one numeric literal.

MATLAB applies class conversion, size validation, and validator functions in
that order. It also evaluates class property default expressions once when the
value is first needed. The v0.28 runtime follows those ordering and caching
rules for its supported value kinds:

- <https://www.mathworks.com/help/matlab/matlab_oop/validate-property-values.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/property-size-and-class-validation.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/property-validator-functions.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/properties-containing-objects.html>

## Example

```powershell
build\mparser.exe --run-bytecode samples\property_validation_demo.m
```

Expected values include:

```text
first_sum = 12
second_sum = 6
shared_code = 9
gain = 2
label = "sensor"
```

The `Samples(1,3)` write demonstrates scalar expansion. Two `Measurement`
instances also receive the same cached `SharedState` handle default, so a
mutation reached through the first instance is visible through the second.

## Current Limitations

- Property block attributes are retained on each property but access control,
  `Constant`, `Dependent`, `Transient`, observation, and custom get/set methods
  are not enforced yet.
- Custom validators and built-ins requiring richer literal sets, including
  `mustBeMember`, `mustBeBetween`, and `mustBeA`, report an explicit runtime
  diagnostic.
- Numeric class conversion is limited to the runtime's double/logical model;
  integer and single-precision storage classes are not represented separately.
- Runtime size enforcement supports at most two dimensions. Non-scalar string
  arrays and general object arrays are not represented.
- Cross-file/package class lookup and default expressions that depend on class
  constant properties still need a module/path loader and class-load scope.
- Default caches currently live for one bytecode run. A persistent class-loader
  cache is still required to preserve defaults across repeated module invokes.
- The reference HIR interpreter still does not execute class objects; property
  behavior belongs to the bytecode runtime and later tiers.

## Next Iteration

- Enforce `GetAccess`/`SetAccess`, immutable constant properties, and class
  context for protected/private visibility.
- Add property get/set methods, dependent-property dispatch, and validation
  ordering around set methods.
- Execute custom validators and richer literal comparison/member sets.
- Generalize runtime arrays to N dimensions and distinct MATLAB storage types.
