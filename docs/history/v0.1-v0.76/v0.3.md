# MParser v0.3 Scope

MParser v0.3 makes the bytecode VM capable of executing same-file local
functions instead of only running a single top-level body. This is the first VM
iteration with real call frames and output-count metadata, which are required
before profiling and JIT work can specialize function bodies or hot loops.

## Added Since v0.2

- Bytecode `resultCount` metadata for calls that produce multiple outputs.
- Bytecode `Pop` instruction for ignored output targets such as `~`.
- VM function table built from HIR signatures plus bytecode function ranges.
- Isolated bytecode VM call frames for same-file local functions.
- Local function parameter binding and function-output initialization.
- First-output local function calls in expressions, such as `y = helper(x)`.
- Multi-output local function assignment, such as `[a, b] = helper(x)`.
- Multi-output `size` builtin assignment, including ignored outputs.
- `samples/bytecode_call_demo.m` as the v0.3 call-frame demo.
- Project version and CLI version bumped to `0.3.0`.

## Bytecode VM Supported Subset

The v0.3 VM can execute:

- Single scripts and single no-argument entry functions.
- Same-file local function calls from scripts or functions.
- Isolated local function frames with positional parameters and named outputs.
- First-output expression calls and multi-output assignment calls.
- Scalar double values, strings, numeric vectors, and numeric matrices.
- Variable assignment and ignored output targets.
- Core control flow: `if`/`elseif`/`else`, `for` ranges, `while` loops,
  `break`, `continue`, and `return`.
- Matrix and vector literals.
- Numeric arithmetic, comparison, logical `&`/`|`, and scalar `&&`/`||`
  evaluation after lowering.
- Colon ranges with the two-term form `a:b`.
- Transpose.
- 1-based one-subscript and scalar two-subscript indexing.
- Selected builtins: `sin`, `cos`, `sqrt`, `abs`, `sum`, `size`, `length`,
  `numel`, `any`, `all`, `zeros`, `ones`, `eye`, `linspace`, and `strcmp`.

## VM Gaps

The VM still intentionally reports diagnostics for features that need richer IR
or runtime metadata:

- `switch` and `try` control execution.
- Indexed assignment.
- `end` and colon subscripts inside indexing.
- Dynamic function handles and unresolved function dispatch.
- Classes, object dispatch, member assignment, cells, brace indexing, structs,
  tables, sparse arrays, and complex values.
- JIT compilation and deoptimization.

These remain covered, where implemented, by the HIR interpreter.

## Validation

Validated on Windows with MSVC Build Tools:

```powershell
cmake --build build
ctest --test-dir build --output-on-failure
build\mparser.exe --version
build\mparser.exe --run-bytecode samples\bytecode_vm_demo.m
build\mparser.exe --run-bytecode samples\bytecode_control_demo.m
build\mparser.exe --run-bytecode samples\bytecode_call_demo.m
build\mparser.exe --run-bytecode samples\local_function_demo.m
```

Expected version output:

```text
MParser 0.3.0
```

The v0.3 call-frame demo should execute through bytecode local calls:

```powershell
build\mparser.exe --run-bytecode samples\bytecode_call_demo.m
```

Expected variables:

```text

  cols = 2
  doubled = 20
  rows = 2
  scope = 3
  total = 10
  y = 37
```

## Next Iterations

The next high-value v0.4 work is to expand mutation and dynamic dispatch in the
bytecode VM:

- Add bytecode execution for indexed assignment into numeric arrays.
- Add runtime handling for `end` and colon subscripts inside indexing.
- Improve dynamic call/index dispatch for unresolved names.
- Move shared numeric runtime helpers out of `interpreter.cpp` and
  `bytecode_vm.cpp`.
- Add profiling counters to bytecode functions and loops, then lower stable hot
  regions toward a typed optimizing IR.
