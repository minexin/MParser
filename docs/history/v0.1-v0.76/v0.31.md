# MParser v0.31 Scope

MParser v0.31 makes MATLAB selective class visibility and restricted
inheritance executable in the bytecode VM. Class-valued attributes now keep a
structured meta-class representation, member access can name trusted classes,
and `AllowedSubclasses` validates direct inheritance edges during class
resolution.

## Major Capability

- Attribute parsing recognizes a single meta-class reference such as
  `?Reader`, an empty cell list `{}`, and comma-separated lists such as
  `{?Reader, ?pkg.Writer}`.
- `AttributeSyntax` retains normalized meta-class names alongside its raw
  lossless value, so semantic and runtime layers no longer reparse attribute
  text.
- Property `Access`, `GetAccess`, and `SetAccess` accept one class or a cell
  array of classes in addition to `public`, `protected`, and `private`.
- Method block `Access` class lists apply to instance methods, static methods,
  and constructors through the existing common invocation path.
- The defining class always has access. A resolved listed class and every
  subclass of that listed class also have access.
- Descendants of the defining class do not gain access merely because their
  base owns the member. The defining class must appear in the list when that
  broader behavior is wanted.
- Unresolved list entries are removed. An empty effective access list has
  private semantics, while the defining class retains access.
- A subclass may override a class-list method only when the inherited policy
  grants that subclass access. The override must preserve the complete
  resolved `Access` policy.
- Class `AllowedSubclasses` accepts the same single-reference and cell-list
  forms and restricts only direct subclass edges.
- A class below an allowed direct subclass is governed by that subclass's own
  policy, so allowing an extension point does not automatically seal its
  descendants.
- Empty or fully unresolved `AllowedSubclasses` lists act as `Sealed`.
- Malformed class lists and unauthorized access, inheritance, and override
  attempts produce source-aware diagnostics.
- Project and CLI version are `0.31.0`; CTest now contains 23 targets.

## Policy Model

The parser and runtime now share a stable structured boundary:

```text
AttributeSyntax
  raw value: "{?Reader, ?pkg.Writer}"
  meta-class names: [Reader, pkg.Writer]
                 |
                 v
same-source class resolution
  remove unresolved names
                 |
        +--------+------------------+
        |                           |
        v                           v
MemberAccessPolicy          AllowedSubclasses policy
  level + class names         permitted direct bases
```

Access checks use the declaring class and currently executing requesting
class. This makes the same policy work for property reads/writes, instance and
static methods, constructors, and qualified superclass calls. A listed base
class grants access to its descendants through the resolved inheritance graph.

`AllowedSubclasses` is checked on each `Child < Base` edge. A list containing
`?ExtensionPoint` permits `ExtensionPoint < Base`; a later
`Plugin < ExtensionPoint` edge is controlled by `ExtensionPoint`, not by
`Base`.

The behavior follows MATLAB's documented class access and subclass-control
rules:

- <https://www.mathworks.com/help/matlab/matlab_oop/selective-access-to-class-methods.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/property-attributes.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/method-attributes.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/control-allowed-subclasses.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/modifying-superclass-methods-and-properties.html>

## Example

```powershell
build\mparser.exe --run-bytecode samples\class_access_policy_demo.m
```

Expected values include:

```text
extension_code = 23
initial = 7
secret = 107
updated = 11
```

The sample uses a factory-only constructor, separate reader and writer
classes, access inherited by a reader subclass, a restricted extension root,
and a permitted descendant below the named extension point.

## Diagnostics Covered

- External property reads and writes outside their class lists.
- External and unlisted-class method calls.
- Direct construction outside a constructor access list.
- A subclass of the defining class that was not independently authorized.
- Malformed property, method, or class access lists.
- Direct subclasses omitted from `AllowedSubclasses`.
- Subclassing classes with empty or fully unresolved allowed lists.
- Unauthorized class-list method overrides.
- Class-list overrides that do not preserve exact access.

## Current Limitations

- Class loading remains limited to definitions in one compiled source.
  Package-qualified meta-class names are preserved by the parser but cannot be
  resolved until package and path-based class loading exists.
- Removing an unresolved list entry follows MATLAB policy, but only same-source
  classes can currently become resolved entries.
- Private inherited property redeclaration is still rejected even though
  MATLAB permits a subclass-local property with the same name. The object
  layout needs declaring-class-local field identity before this is safe.
- Runtime metadata introspection such as `metaclass` and dynamic class loading
  is not implemented.
- Events, listeners, dynamic properties, handle lifecycle callbacks, object
  arrays, and user-defined operator dispatch remain outside this class subset.
- The reference HIR interpreter and typed/JIT tiers do not execute class
  objects. Selective policies currently execute in the bytecode VM.
- Native machine-code JIT remains future work; current optimization tiers use
  portable typed-region execution and bytecode fallback.

## Next Iteration

- Give inherited private properties declaring-class-local field identity and
  allow legal subclass redeclaration without aliasing storage.
- Introduce persistent class-loader state for cross-file and package-qualified
  class discovery, then resolve retained meta-class names against it.
- Expose effective class and member policies through runtime metadata.
- Continue multidimensional Cell and comma-separated-list semantics while
  preserving bytecode fallback for future native JIT tiers.
