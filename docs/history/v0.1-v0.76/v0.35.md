# MParser v0.35 Scope

MParser v0.35 makes MATLAB namespace folders executable for the current class
subset. Classes discovered in `+namespace` directories receive canonical full
identities, so qualified construction, static access, inheritance, access
policy, and object dispatch no longer collapse classes that share a short name.

## Major Capability

- `SourceUnit` now records an optional namespace name in addition to its file
  name, content, and stable source ID.
- `pkg.ClassName` maps to `+pkg/ClassName.m` below an entry or class-path root.
- Nested names such as `pkg.inner.ClassName` map to
  `+pkg/+inner/ClassName.m`.
- The parent of the top-level `+namespace` folder is treated as the search root,
  matching MATLAB's path model.
- Dotted call/member candidates are considered longest-first. This lets
  `pkg.ClassName.staticMethod()` load `pkg.ClassName` before considering shorter
  ambiguous prefixes.
- Multiple roots containing the same namespace participate in one logical
  namespace; the first root containing a requested class member wins.
- `CompiledModule` qualifies a class using its source namespace before duplicate
  detection and semantic lowering.
- Classes with the same short name in different namespaces coexist. Repeating
  the same full name remains a compile diagnostic attached to the second file.
- A known dotted class syntax chain is collapsed to one class-bound HIR name
  after the module has declared every loaded class.
- Constructor declarations retain MATLAB's short source spelling while their
  HIR function name, method table key, object type, and runtime call target use
  the full class name.
- The shared function-signature parser reads the final segment of a qualified
  constructor name without weakening the canonical runtime key.
- Qualified constructors and static methods execute in the baseline bytecode
  VM.
- Qualified superclass lists and `obj@pkg.Base(args)` calls execute across
  namespace boundaries.
- Namespace-qualified meta-class attribute lists resolve against the same class
  identities; the demo base restricts `AllowedSubclasses` to its qualified
  child.
- Declaring-class private property/method identity and visible dynamic dispatch
  continue to work across those boundaries.
- `--module-info` displays the namespace attached to every loaded source.
- Project and CLI version are `0.35.0`; CTest contains 29 tests.

## Identity Model

Physical layout supplies the namespace while `classdef` supplies the short
class name:

```text
<class-root>/+pkg/+inner/Counter.m
                         classdef Counter
                                  |
                                  v
runtime identity = pkg.inner.Counter
```

The constructor follows MATLAB source syntax:

```matlab
function obj = Counter(value)
```

but the compiler registers it as the constructor method for
`pkg.inner.Counter`. This separation keeps source parsing faithful while all
semantic and runtime lookup uses one collision-free identity.

Qualified expressions remain ordinary dotted syntax until deferred semantic
resolution:

```text
MemberAccess(MemberAccess(pkg, Counter), tag)
  -> MemberAccess(ClassRef(pkg.Counter), tag)
```

The same class reference then feeds constructor calls, static methods, constant
properties, superclass metadata, and class-list access policies.

## MATLAB Alignment

MATLAB defines a namespace with a folder whose name starts with `+`, requires
the parent of the top-level namespace on the path, and references namespace
members with a dotted full name. The class definition itself contains only the
short class name. MParser v0.35 follows that class-file subset and supports
nested namespace folders:

- <https://www.mathworks.com/help/matlab/matlab_oop/namespaces.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/organizing-classes-in-folders.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/subclass-syntax.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/importing-classes.html>

## Example

The demo contains two different namespace classes named `Counter`, a base class
in a third namespace, and a static class in a nested namespace:

```powershell
build\mparser.exe --run-bytecode `
  --class-path=samples\package_classes `
  samples\package_classes\app\run_demo.m
```

Expected values include:

```text
base_code = 105
child_code = 207
dynamic_code = 2
static_code = 35
nested_code = 44
other_code = 309
```

The first three values cover cross-namespace superclass construction, private
identity, and visible virtual dispatch. `static_code` covers a qualified static
method, `nested_code` covers `+pkg/+inner`, and `other_code` proves that
`pkgsibling.Counter` remains independent from `pkgchild.Counter`.

Inspect the physical-to-logical mapping with:

```powershell
build\mparser.exe --module-info `
  --class-path=samples\package_classes `
  samples\package_classes\app\run_demo.m
```

## Diagnostics And Precedence Covered

- Same short class name in two different namespaces is valid.
- Same canonical class name in two source units is rejected.
- A duplicate diagnostic retains the second source's file identity.
- Reversing two class paths reverses which same-named namespace member is
  selected.
- A malformed or unrelated file outside the dependency closure remains ignored.
- Existing simple-class lookup and all pre-v0.35 class semantics remain covered
  by the full regression suite.

## Current Limitations

- `import pkg.ClassName` and wildcard imports are parsed only as unsupported
  ordinary statements; they do not create aliases.
- Namespace functions are not discovered or invoked. Dotted resolution in this
  milestone targets classes and their supported static members.
- `@class` folders and methods implemented in separate files are not loaded.
- Enumeration members, namespace-private folders, and MATLAB's complete
  function/class precedence rules are not modeled.
- Dependency discovery is conservative and syntax-driven. It can load an
  existing class candidate for a dotted expression that semantic analysis later
  resolves as variable member access; local bindings still win in HIR.
- A namespace folder itself should not be supplied as `--class-path`; supply its
  parent root, matching MATLAB's path requirement.
- The loader rebuilds the source graph for every invocation. Persistent file
  hashes, invalidation, and compiled module caches remain future work.
- The reference interpreter and typed/JIT regions still do not execute class
  objects; package class execution currently uses the baseline bytecode VM.
- Native machine-code JIT remains future work. Current specialization uses
  portable typed regions with bytecode fallback.

  namespace/class graphs do not require lexing and parsing on every compile.
- Add namespace function nodes and explicit import scopes without conflating
  them with static class lookup.
