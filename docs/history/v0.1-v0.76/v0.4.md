# MParser v0.4 Scope

MParser v0.4 moves the bytecode VM from function/control-flow execution into
array mutation semantics. This is a larger compatibility step because MATLAB
scripts commonly combine loops, `end`, colon subscripts, vector subscripts, and
in-place updates.

## Added Since v0.3

- Bytecode `BeginIndexContext` and `BeginIndexArgument` instructions so `end`
  and `:` can be evaluated against the array currently being indexed.
- VM index-context stack with isolation across local function call frames.
- `end` support inside bytecode indexing expressions, including expressions
  such as `end - 1`.
- Colon subscripts inside bytecode indexing, including `A(:, 2)`, `A(1, :)`,
  `A(:)`, and range forms such as `A(2:end, :)`.
- Vector subscripts for one- and two-dimensional bytecode indexing.
- Column-major linear indexing for matrices, matching MATLAB-style `A(k)`.
- Indexed assignment into existing numeric vectors and matrices.
- Scalar-fill assignment for vectorized targets such as `v(:) = 7`,
  `v([1 3]) = 7`, and `A(:, 3) = 10`.
- `samples/bytecode_indexing_demo.m` as the v0.4 bytecode indexing demo.
- Project version and CLI version bumped to `0.4.0`.

## Bytecode VM Supported Subset

The v0.4 VM can execute everything in v0.3 plus:

- 1-based linear indexing with scalar, vector, colon, and `end` subscripts.
- 1-based row/column matrix indexing with scalar, vector, colon, and `end`
  subscripts.
- Numeric indexed assignment into existing vectors and matrices.
- Scalar right-hand-side assignment broadcast over the selected target slots.

This brings the bytecode VM close to the current reference interpreter for
numeric array indexing and mutation while still keeping unsupported dynamic
features explicit.

## VM Gaps

The VM still intentionally reports diagnostics for features that need richer IR
or runtime metadata:

- `switch` and `try` control execution.
- Automatic array growth during indexed assignment.
- Non-scalar right-hand-side indexed assignment shape matching.
- Dynamic function handles and unresolved function dispatch.
- Classes, object dispatch, member assignment, cells, brace indexing, structs,
  tables, sparse arrays, and complex values.
- JIT compilation, profiling guards, and deoptimization.

These remain covered, where implemented, by the HIR interpreter.

```powershell

build\mparser.exe --run-bytecode samples\bytecode_vm_demo.m
```

## Next Iterations

The next high-value work is to make the VM less special-case heavy and prepare
for hot-loop optimization:

- Extract shared numeric runtime helpers from the HIR interpreter and bytecode
  VM into a common runtime module.
- Add profiling counters to bytecode function bodies, loops, and call/index
  sites.
- Add shape/type guards for stable numeric loop bodies.
- Extend indexed assignment to shape-checked non-scalar right-hand sides.
- Start a small optimizing IR for straight-line numeric loop regions before
  attaching LLVM ORC or another JIT backend.
