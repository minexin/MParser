# MParser v0.40 Scope

MParser v0.40 makes MATLAB enumeration classes executable across the frontend,
bytecode VM, package source graph, and CLI. Enumeration members are no longer
opaque declaration lines: they have semantic identities, dedicated lazy
initializer regions, class construction, singleton state, and runtime query
operations.

## Major Capability

- Enumeration lines split same-line comma-separated members without splitting
  commas nested inside constructor arguments, matrices, or Cells.
- `...` continuation markers are removed before member splitting.
- A member optionally retains structured constructor argument expressions.
- Enumeration block attributes are copied to every member; `Hidden` is
  executable metadata.
- HIR, bindings, and symbols expose `EnumerationMember` as a distinct kind.
- Bytecode gives each member an
  `EnterEnumerationMemberInitializer`/`LeaveEnumerationMemberInitializer`
  region with an explicit argument count.
- `Class.Member`, package-qualified members, and explicitly imported members
  resolve to the same runtime member identity.
- Members are constructed lazily on first use and cached for the rest of that
  VM run. Recursive initialization is diagnosed.
- Explicit constructors initialize enumeration properties, including through
  private constructors. A class with no explicit constructor supports simple
  no-argument members.
- `Class()` selects the first member and `Class('Member')` converts a member
  name to its cached value.
- Enumeration methods, `==`, `~=`, and `switch/case` use class-qualified member
  identity rather than comparing mutable fields.
- Value-enumeration properties are immutable after construction.
- An enumeration derived from `handle` retains a shared mutable member object;
  repeated member access observes the same property storage.
- Enumeration classes are implicitly sealed and reject subclass edges.
- Member names that collide with the class, a property, method, event, or
  another enumeration member are compile diagnostics.
- `isenum`, `class`, `isa`, `char`, and `string` understand enumeration values.
- `enumeration(value)` and `enumeration('Class')` support one or two outputs.
  The second output contains member names, and `Hidden` members are omitted.
- Generic `length`, `numel`, `size`, and `isempty` now accept Cell and object
  runtime values in addition to numeric values.
- Static `enumeration('pkg.Class')` calls add the named class to the source
  dependency graph even when no other class reference appears in the script.
- Project and CLI version are `0.40.0`; CTest contains 47 tests.

## Runtime Model

Each loaded enumeration class owns an ordered map of member descriptors:

```text
class
  -> member name and attributes
  -> initializer bytecode range and argument count
  -> evaluation-active recursion guard
  -> evaluated flag and cached RuntimeValue
```

The first member access executes its argument expressions in an isolated class
lexical frame. The VM then invokes the normal class constructor through an
internal enumeration-construction path, adds the member name to the resulting
object identity, and caches it. Later accesses return that value directly.

Value and handle classes intentionally diverge after construction:

```text
value enum member  -> cached logical identity; property writes rejected
handle enum member -> cached identity plus shared property storage
```

Equality compares `className` and `enumerationMemberName`. This keeps equality
and `switch` stable even when a handle-enumeration property changes.

## Query Representation

MParser does not yet have homogeneous object arrays, so the current query
boundary is explicit:

```matlab
[members, names] = enumeration(value);
first = members{1};
count = numel(members);
```

Both outputs are row Cells. `members` contains enumeration objects and `names`
contains strings. This preserves order, heterogeneity, brace access, and the
two-output contract without pretending a Cell is a MATLAB object array.

## MATLAB Alignment

The implemented rules follow MATLAB's documented enumeration model: members
can pass constructor arguments, simple enumerations can omit them, enum classes
are implicitly sealed, value-enum properties are immutable, member names must
not collide with other class members, and `enumeration` can return member names.

- <https://www.mathworks.com/help/matlab/matlab_oop/enumerations.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/enumeration-class-restrictions.html>

## Example

Run the package enumeration demo with:

```powershell
build\mparser.exe --run-bytecode `
  --class-path=samples\enumeration_classes\lib `
  samples\enumeration_classes\app\run_demo.m
```

The entry script explicitly imports `palette.Status.Ready`, converts
`palette.Status('Busy')`, calls an enum method, dispatches a `switch`, queries
the visible members, and reads constructor-initialized properties.

Expected highlights:

```text
busy = <palette.Status.Busy>
members = {<palette.Status.Ready>, <palette.Status.Busy>}
names = {"Ready", "Busy"}
summary = 56
visible_count = 2
```

Inspect source loading and semantic identities with:

```powershell
build\mparser.exe --module-info `
  --class-path=samples\enumeration_classes\lib `
  samples\enumeration_classes\app\run_demo.m

build\mparser.exe --hir `
  --class-path=samples\enumeration_classes\lib `
  samples\enumeration_classes\app\run_demo.m
```

## Regression Coverage

- Same-line, no-argument, argument-bearing, and continued declarations.
- Constructor argument counts in syntax, HIR, and bytecode.
- Block-level `Hidden` propagation.
- Lazy construction, repeated member access, and default-first conversion.
- String conversion and invalid member-name diagnostics.
- Private enum constructors and recursive initialization rejection.
- Constructor-initialized properties and enum instance methods.
- Equality, inequality, `switch`, `class`, `isa`, `char`, `string`, and
  `isenum`.
- One- and two-output `enumeration` queries by object and class name.
- Hidden query filtering and Cell shape/count operations.
- Value property immutability and handle singleton mutation.
- Implicit sealed-class enforcement.
- Property, method, event, class-name, and duplicate-member collisions.
- Package source discovery and explicit member imports.

## Current Limitations

- `enumeration` returns Cells rather than homogeneous object and string arrays.
- Enumeration arrays, concatenation, colon ranges, ordering comparisons, and
  comma-separated-list expansion are not represented yet.
- Built-in numeric, logical, and character enumeration superclasses are not
  executable because the class hierarchy currently special-cases only
  `handle`; user-defined constructor-backed and handle enumerations execute.
- `Hidden` is the first executable enumeration attribute. Richer reflection,
  display metadata, and `meta.class` enumeration tables remain future work.
- Enumeration singleton caches live for one VM run; compiled-module lifetime
  class-state persistence is not implemented.
- The reference HIR interpreter still does not execute class objects. Use
  `--run-bytecode` for enumeration scripts.
- Events, listeners, object lifecycle callbacks, serialization, and native JIT
  compilation remain outside this milestone.
