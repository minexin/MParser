# MParser v0.42 Scope

MParser v0.42 makes N-dimensional shape a shared runtime contract instead of a
two-dimensional convention attached separately to each subsystem. Numeric
arrays and Cells now retain complete dimensions through interpretation,
bytecode execution, class property validation, profiling, optimization
planning, typed IR guards, benchmark comparison, and CLI inspection.

## Major Capability

- `RuntimeValue` carries canonical dimensions with at least two entries and
  normalized trailing singleton dimensions.
- A shared `runtime_shape` module owns checked dimension products, folded
  subscript dimensions, column-major linear indices, and physical storage
  offsets.
- The existing row-major payload remains compatible with earlier matrix code
  while all MATLAB-visible indexing follows column-major order.
- `zeros`, `ones`, and `cell` accept arbitrary scalar dimension lists and
  numeric shape vectors in both baseline runtimes.
- `size(A)`, `size(A,dim)`, `size(A,[dims])`, multi-output `size`, `ndims`,
  `numel`, `length`, and `isempty` operate on the complete shape.
- Numeric reads accept scalar, vector, and colon subscripts in any number of
  dimensions. Fewer subscripts fold remaining dimensions into the final
  subscript; extra trailing subscripts address singleton dimensions.
- Numeric indexed assignment supports scalar fill across N-dimensional
  selections without changing the target shape.
- N-dimensional Cell construction and scalar brace reads/writes use the same
  linear, folded, `end`, and trailing-singleton rules.
- Elementwise unary and binary numeric operations preserve complete shape.
- Matrix multiplication and transpose reject non-2-D operands explicitly
  instead of silently discarding dimensions.
- Class property declarations such as `Tensor(2,3,2) double` and
  `Slots(2,1,2) cell` create N-dimensional implicit defaults and validate
  assignments. Reshaping preserves column-major linear element order.
- Shape validators no longer misclassify arrays with significant dimensions
  beyond the second as vectors, rows, columns, or matrices.
- VM observations, adaptive profile merging, optimization guards, typed IR,
  guard evaluation, benchmark equality, and CLI profile text retain the full
  dimension vector.
- Project and CLI version are `0.42.0`; CTest contains 54 tests.

## Runtime Shape Contract

The canonical model is:

```text
RuntimeValue
  -> dimensions = normalize([d1, d2, ..., dn])
  -> rows = dimensions[0]
  -> columns = dimensions[1]
  -> row-major payload retained internally
  -> MATLAB column-major logical indexing at the runtime boundary
```

Normalization supplies a second dimension when necessary and removes trailing
ones only after the second dimension. Thus `zeros(2,3,1)` has shape `2x3` and
`ndims` returns 2, while `zeros(2,1,3)` has shape `2x1x3` and `ndims` returns 3.

For `A` with shape `2x3x2`, linear index 10 and subscript `(2,2,2)` identify
the same element. With two subscripts, `(2,5)` is also equivalent because the
third dimension is folded into the second effective dimension. Every mapping
is overflow-checked before a storage offset is used.

## Shape Queries

The implemented query forms include:

```matlab
A = zeros(2, 3, 2);
shape = size(A);              % [2 3 2]
picked = size(A, [1 3 4]);    % [2 2 1]
[rows, tail] = size(A);       % rows = 2, tail = 6
[d1, d2, d3, d4] = size(A);  % 2, 3, 2, 1
rank = ndims(A);              % 3
count = numel(A);             % 12
longest = length(A);          % 3
```

When `size` has fewer outputs than significant dimensions, the final output is
the product of all remaining dimensions. Extra outputs receive 1.

## Indexing And Mutation

Numeric arrays support linear and multidimensional selection:

```matlab
A = zeros(2, 3, 2);
for k = 1:numel(A)
    A(k) = k;
end

same = A(10) + A(2, 5) + A(2, 2, 2);
slice = A(:, 2:3, :);
A(:, 2:3, 2) = 5;
last = A(end);
```

Cells support scalar brace access with equivalent dimension handling:

```matlab
C = cell(2, 3, 2);
C{2, 2, 2} = 42;
folded = C{2, 5};
linear = C{10};
last = C{end};
```

The bytecode lowerer now places brace arguments inside the same index context
used by numeric parentheses, so `end` receives the correct effective dimension.

## Class Property Shapes

The bytecode class runtime accepts N-dimensional property constraints:

```matlab
classdef TensorRecord
    properties
        Tensor(2,3,2) double {mustBeFinite}
        Slots(2,1,2) cell
    end
end
```

Implicit defaults allocate the complete declared shape. A scalar numeric value
may expand to every element. Numeric and Cell values with a matching element
count may be reshaped, including one inferred `:` dimension, while preserving
their MATLAB linear order. Multiple wildcard dimensions are accepted only when
the existing value already has an exact compatible shape.

## Optimization Contract

Earlier profiles represented shape only as `rows` and `columns`. v0.42 adds the
complete dimension vector to assignment, entry, parameter, result, receiver,
and instruction observations. Stable observations copy that vector into
optimization guards and typed values. Adaptive merging clears the shape when
runs disagree, and runtime guard evaluation compares every dimension.

This does not yet compile N-dimensional kernels to native code. It prevents a
future JIT from entering a specialization built for `2x3x2` when it receives a
different value that merely shares the first two dimensions.

## Example

Run the same N-dimensional script through both baseline runtimes:

```powershell
build\mparser.exe --run-bytecode samples\nd_arrays_demo.m
build\mparser.exe --run samples\nd_arrays_demo.m
build\mparser.exe --profile-bytecode samples\nd_arrays_demo.m
build\mparser.exe --plan-bytecode samples\nd_arrays_demo.m
```

Both execution modes should finish with:

```text
summary = 171
```

Array and Cell values are printed with complete shapes, for example
`array(2x3x2)[...]` and `cell(2x3x2){...}`. Profile and guard output uses the
same `2x3x2` spelling.

## Regression Coverage

- Numeric constructor dimension lists and shape vectors.
- Trailing singleton normalization and significant third dimensions.
- Full, dimension-specific, vector-dimension, and multi-output `size`.
- `ndims`, `numel`, `length`, and `isempty` for numeric arrays and Cells.
- Column-major linear equivalence, folded dimensions, extra singleton
  subscripts, `end`, scalar/vector/colon selections, and out-of-bounds errors.
- N-dimensional slice shape, payload order, elementwise arithmetic, and
  scalar-fill assignment.
- N-dimensional Cell construction, scalar brace reads/writes, folded and
  linear indexing, and `end`.
- Numeric and Cell class property defaults, reshaping, logical order, and
  shape validators.
- Complete dimensions in profiles, optimization candidates, typed IR guards,
  adaptive merging, CLI output, and benchmark result equality.
- Reference interpreter and bytecode CLI parity on `samples/nd_arrays_demo.m`.

## Current Limitations

- Numeric indexed assignment still requires a scalar right-hand side. General
  shape matching and non-scalar assignment are not implemented.
- Numeric indexed assignment cannot grow an array. Cell linear growth remains
  limited to existing one-dimensional row Cells.
- Linear indexing with a vector currently returns a row vector regardless of
  the index shape. In particular, `A(:)` is not yet forced to a column vector.
- `size(A,[dims])` is implemented, but the separate-input form
  `size(A,dim1,dim2,...)` and its multi-output form are not yet implemented.
- Cell brace access returns one scalar value. Vector-valued brace selections,
  comma-separated lists, and Cell parenthesis indexing are not implemented.
- `reshape`, `permute`, concatenation across arbitrary dimensions, `repmat`,
  broadcasting, and dimension-aware reductions are not implemented.
- `eye`, transpose, and matrix multiplication remain two-dimensional.
- Character arrays, string arrays, object arrays, enumeration arrays, and
  listener arrays do not yet use the N-dimensional payload representation.
- Class execution and property validation remain bytecode-VM features; the HIR
  reference interpreter does not execute classes.
- Native machine-code JIT remains future work. Existing optimization uses
  profiled bytecode, typed regions, guards, fallback, and retraining.
- Because `RuntimeValue` gained shape metadata, an incremental build mixing old
  and new object files is ABI-incompatible. A clean rebuild is required when
  moving to v0.42.

## Next Iteration

- Reuse canonical dimensions for object and listener arrays, including class
  construction, indexing, assignment, and method dispatch over scalar elements.
- Add Cell parenthesis indexing and comma-separated-list expansion before
  extending `varargin`, `varargout`, and multi-output calls to N-dimensional
  selections.
- Keep every new collection type on `runtime_shape` so native lowering sees one
  indexing and guard contract rather than parallel class-specific layouts.
