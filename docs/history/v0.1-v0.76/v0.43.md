# MParser v0.43 Scope

MParser v0.43 completes the first general numeric-array mutation contract on
top of the N-dimensional shape model introduced in v0.42. The HIR interpreter
and bytecode VM now share one indexed-assignment engine, so non-scalar values,
growth, repeated indices, and MATLAB column-major assignment order have the
same behavior in both runtimes. Numeric elementwise operators also support
MATLAB-compatible implicit expansion across two-dimensional and N-dimensional
arrays.

## Major Capability

- Numeric indexed assignment accepts scalar or array right-hand values.
- Linear assignment requires matching element counts, with scalar expansion.
- Multi-subscript assignment compares nonscalar subscript lengths with the
  nonsingleton dimensions of the right-hand value.
- Right-hand values and subscript arrays are consumed in MATLAB column-major
  order, independent of the runtime's row-major physical payload.
- Repeated indices are applied sequentially, so the final write to an element
  wins.
- Out-of-bounds assignment grows row vectors, column vectors, matrices, and
  N-dimensional arrays and fills newly created numeric elements with zero.
- Scalar numeric targets promote to arrays when assignment grows their shape.
- Existing coordinates and logical values survive physical payload reallocation
  during growth.
- Fewer subscripts still use the folded trailing-dimension view. Growth through
  that final folded dimension materializes the effective view as the new shape.
- Basic elementwise numeric operators perform dimension-wise implicit
  expansion when each pair of dimensions is equal or one side has size 1.
- Empty dimensions participate in compatibility checks without attempting to
  access payload storage.
- Matrix-shaped subscript arrays are now read in column-major order for both
  indexed assignment and indexed reference.
- Project and CLI version are `0.43.0`; CTest contains 56 tests.

## Shared Mutation Contract

Both baseline runtimes call `runtimeAssignNumericIndexed`. The operation is
split into four checked stages:

```text
subscripts -> positive integer selections in column-major order
           -> MATLAB assignment-shape compatibility
           -> checked target growth and zero-filled payload remap
           -> sequential writes using logical right-hand order
```

All shape validation happens before growth. A shape error therefore leaves the
target unchanged. Growth copies old values by logical linear index into their
corresponding coordinates in the enlarged shape, rather than copying raw
row-major storage bytes.

## Indexed Assignment

Non-scalar and scalar-expanded assignment work in linear and subscript forms:

```matlab
A = zeros(2, 2);
A(3:4, 3:4) = [1 2; 3 4];
A(1, 4) = 8;                 % A grows to 4x4

v = [1 2];
v([4 6]) = [40 60];         % [1 2 0 40 0 60]

N = zeros(2, 2, 2);
N(:, 1, 2) = [5; 6];
N(3, 2, 3) = 7;             % N grows to 3x2x3
```

For `A(J,K,...) = B`, selection dimensions equal `numel(J)`, `numel(K)`, and
so on. Dimensions of size 1 are removed from both the selection shape and the
right-hand shape before comparison. A scalar right-hand value expands to every
selected location.

Repeated index order is observable:

```matlab
R = zeros(1, 2);
ids = [1 2; 2 1];
R(ids) = [10 20; 30 40];
```

Both `ids` and the right-hand matrix are traversed down columns first. The
result is `[40 20]` because later writes replace earlier writes to the same
location.

## Implicit Expansion

Elementwise arithmetic, comparison, and elementwise logical operators now
expand singleton dimensions:

```matlab
E = [1; 2] + [10 20 30];
% E = [11 21 31; 12 22 32]

Z = ones(2, 1, 2) + [10 20 30];
% size(Z) is [2 3 2]
```

Dimensions are aligned by MATLAB dimension number. Missing trailing dimensions
have size 1. If two corresponding dimensions differ and neither is 1, the
operation reports an incompatible-dimensions diagnostic.

## Example

Run the complete mutation and expansion demo through both baseline runtimes:

```powershell
build\mparser.exe --run-bytecode samples\array_assignment_demo.m
build\mparser.exe --run samples\array_assignment_demo.m
```

Both modes should finish with:

```text
summary = 860
```

## Regression Coverage

- Exact-shape block assignment and scalar expansion.
- Row-vector, matrix-linear, scalar-to-array, matrix, and N-dimensional growth.
- Zero fill and preservation of old coordinates across payload remapping.
- Column-major right-hand traversal and repeated subscript-array writes.
- MATLAB nonscalar-subscript versus nonsingleton-right-hand shape checks.
- Two-dimensional and N-dimensional implicit expansion.
- Incompatible assignment-shape and expansion diagnostics in both runtimes.
- Reference interpreter and bytecode CLI parity on
  `samples/array_assignment_demo.m`.

## Current Limitations

- Logical indexing and logical-mask assignment are not implemented.
- Empty right-hand assignment does not yet delete selected rows, columns, or
  elements.
- Indexed assignment still requires an existing named numeric target; it does
  not create a previously undefined variable from an indexed left-hand side.
- Linear indexed reference with a vector returns a row vector regardless of
  the index shape; `A(:)` is not yet forced to a column vector.
- Cell parenthesis indexing, Cell array growth beyond the existing scalar brace
  subset, vector-valued brace selections, and comma-separated lists remain
  future work.
- `reshape`, `permute`, general concatenation, `repmat`, and dimension-aware
  reductions are not implemented.
- Implicit expansion currently covers basic numeric binary operators. Matrix
  division, matrix power, page-wise matrix operations, and sparse arithmetic
  require richer numeric dispatch.
- Character, string, object, enumeration, and listener arrays do not yet use
  the numeric mutation engine.
- Class execution remains a bytecode-VM feature; the HIR interpreter does not
  execute classes.
- Native machine-code JIT remains future work. Existing optimization uses
  profiled bytecode, typed regions, guards, fallback, and retraining.
