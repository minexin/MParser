# MParser v0.44 Scope

MParser v0.44 adds a shared N-dimensional array-transformation layer above the
canonical shape and column-major logical-order contracts from v0.42 and v0.43.
The HIR interpreter and bytecode VM now execute the same numeric and Cell
implementations of `reshape`, dimension permutation, replication, and general
concatenation. Class-property size coercion also reuses the shared reshape
primitive instead of maintaining a second element-remapping loop.

## Major Capability

- `reshape(A, sz)` accepts a numeric row-vector size.
- `reshape(A, d1, d2, ...)` accepts separate dimensions and at most one empty
  `[]` dimension whose extent is inferred from `numel(A)`.
- Reshape preserves MATLAB column-major logical order while translating to the
  runtime's row-major physical payload.
- `permute(A, order)` validates a complete consecutive dimension permutation
  and moves each coordinate to its requested output dimension.
- `ipermute(A, order)` applies the exact inverse mapping.
- `squeeze(A)` removes singleton dimensions while preserving MATLAB's minimum
  two-dimensional result and column orientation for a single remaining extent.
- `repmat(A, factors)` and separate-factor forms perform checked
  N-dimensional tiling. A scalar factor repeats both rows and columns, and
  nonpositive factors produce an empty extent.
- `cat(dim, ...)`, `horzcat(...)`, and `vertcat(...)` concatenate numeric or
  Cell inputs while requiring every non-concatenated dimension to agree.
- Numeric and Cell empty arrays retain their meaningful zero extents.
- Dimension products, individual dimensions, permutation orders, inferred
  dimensions, and concatenated extents are validated before payload creation.
- Project and CLI version are `0.44.0`; CTest contains 59 tests.

## Shared Transformation Contract

Both baseline runtimes dispatch these builtins through
`runtimeArrayOperationBuiltin`:

```text
MATLAB arguments -> checked dimensions/order/factors
                 -> output shape and element-count validation
                 -> coordinate or logical-linear remapping
                 -> numeric/Cell result with canonical shape metadata
```

`runtimeReshapeValue` is also the single logical-order primitive used when a
class property declaration coerces a numeric or Cell value to its declared
size. This keeps runtime builtins and property assignment from diverging as
later array kinds are added.

## Reshape And Permutation

Reshape consumes the source down columns first and fills the target down
columns first:

```matlab
A = zeros(2, 3, 2);
for k = 1:numel(A)
    A(k) = k;
end

R = reshape(A, 3, [], 2);   % size(R) is [3 2 2]
P = permute(R, [3 1 2]);    % size(P) is [2 3 2]
I = ipermute(P, [3 1 2]);   % I has R's shape and values
S = squeeze(reshape(1:6, 1, 1, 6)); % a 6x1 column vector
```

Trailing singleton dimensions continue to use the canonical shape
normalization established in v0.42. A permutation may mention extra trailing
singleton dimensions, but it must include every significant input dimension
exactly once in a consecutive order.

## Replication And Concatenation

Replication maps each output coordinate modulo the corresponding source
extent. Concatenation preserves source coordinates and offsets only the
selected output axis:

```matlab
T = repmat([1 2; 3 4], [2 1 2]);
C = cat(3, A, A + 100);     % size(C) is [2 3 4]
H = horzcat([1; 2], [3; 4]);
V = vertcat([1 2], [3 4]);
E = repmat([1 2], 0, 3);    % size(E) is [0 6]
Z = reshape([], 0, 2);      % size(Z) is [0 2]
```

The same operations accept Cells. Cell payloads remain heterogeneous and are
copied by value into the transformed storage while missing cells remain
missing.

## Regression Coverage

- Separate and row-vector reshape dimensions, including one inferred extent.
- Exact physical payload checks proving column-major logical-order retention.
- N-dimensional permutation and inverse-permutation round trips.
- Squeezed column-vector orientation.
- Numeric and Cell replication, reshape, permutation, and concatenation.
- Higher-dimensional concatenation and two-dimensional horizontal/vertical
  wrappers.
- Empty reshape and zero-factor replication shapes.
- Incompatible element counts, duplicate permutation dimensions, and
  concatenation-shape diagnostics in both runtimes.
- Existing N-dimensional class-property reshape behavior after shared-kernel
  migration.
- Interpreter and bytecode CLI parity on
  `samples/array_transform_demo.m`.

## Current Limitations

- The shared transformation layer currently accepts numeric arrays and Cells;
  character, string, object, enumeration, listener, sparse, and table arrays
  require richer runtime array representations.
- Concatenation does not perform singleton expansion or numeric type promotion;
  all current numeric payloads are doubles.
- Matrix and Cell literal construction remains two-dimensional even though the
  resulting values can be transformed into N-dimensional shapes.
- Logical indexing, logical-mask assignment, and empty-right-hand deletion
  assignment are not implemented.
- Dimension-aware reductions and transformation functions such as `shiftdim`,
  `circshift`, `flip`, and `repelem` remain future work.
- Cell parenthesis indexing, vector-valued brace selections, and
  comma-separated lists are not implemented.
- Class execution remains a bytecode-VM feature; the HIR interpreter does not
  execute classes.
- Native machine-code JIT remains future work. Existing optimization uses
  profiled bytecode, typed regions, guards, fallback, and retraining.
