# MParser v0.48 Scope

MParser v0.48 adds a shared array-scan layer above the canonical N-dimensional
shape model. The HIR interpreter and bytecode VM now execute cumulative sums,
products, minima, and maxima, plus first- and higher-order numeric differences,
through one implementation with MATLAB column-major logical traversal.

## Milestone Contract

- Project and CLI version are `0.48.0`.
- `cumsum`, `cumprod`, `cummin`, and `cummax` operate along the first
  non-singleton dimension by default and preserve the complete input shape.
- Cumulative operations accept one positive scalar dimension and return the
  input unchanged when that dimension is beyond `ndims`.
- `"forward"` and `"reverse"` select scan direction without physically
  permuting or reversing the array.
- `"includenan"`/`"includemissing"` and
  `"omitnan"`/`"omitmissing"` control missing values. Sums and products include
  NaN by default; cumulative minima and maxima omit NaN by default.
- Logical `cumsum` and `cumprod` results are double. Logical `cummin` and
  `cummax` results remain logical.
- `diff(X)`, `diff(X,n)`, and `diff(X,n,dim)` support positive orders, `[]` as
  the default order placeholder, arbitrary N-dimensional numeric input, and
  shape-correct empty results.
- `diff(X,n)` applies every order along the initially selected dimension. An
  order larger than that dimension returns an empty array instead of continuing
  along another dimension.
- Reduction, scan, and difference results share one checked
  column-major-logical-to-runtime-payload constructor.
- CTest contains 71 tests, including a dedicated scan/diff regression and CLI
  execution of the v0.48 sample through both baseline runtimes.

## Shared Scan Runtime

`runtime_scan` receives evaluated arguments and the requested output count from
either runtime dispatcher. It selects a dimension, replaces that dimension
with one to enumerate independent lines, then visits each line in forward or
reverse coordinate order. The output retains the original dimensions.

```matlab
A = reshape(1:12, 2, 3, 2);

columnSums = cumsum(A);
rowProducts = cumprod(A, 2);
reversePages = cumsum(A, 3, "reverse");
unchanged = cumsum(A, 5);
```

Each scan line owns its accumulator and missing-value state. Arithmetic scans
start from `0` or `1`. With an omit policy, a leading NaN therefore produces
the corresponding identity until a numeric value is encountered. Extrema scans
have no arithmetic identity: with their default omit policy, leading NaNs stay
NaN until the first numeric value establishes the accumulator.

An include policy makes the accumulated result NaN at and beyond the first NaN
in the selected traversal direction. Reverse scans use the same rule starting
at the last element of each line.

## Numeric Differences

`diff` uses the same first-non-singleton selection as cumulative operations,
unless a positive scalar dimension is supplied. Each pass subtracts adjacent
elements along that one dimension and reduces its length by one:

```matlab
first = diff([1 4 9 16]);                  % [3 5 7]
second = diff([0 5 15 30 50], 2);         % [5 5 5]
columns = diff([1 3 6; 10 15 21], 1, 2);  % [2 3; 5 6]
```

The two-input form follows the current MATLAB fixed-dimension contract. For a
`2x3` matrix, `diff(A,3)` returns a `0x3` result. It does not consume one order
on dimension one and then continue on dimension two. This is encoded directly
in the regression suite so a later refactor cannot accidentally restore the
historical cascading behavior.

If `dim` is beyond the current rank, singleton dimensions are exposed through
that dimension and the result has a zero length there. For example, applying a
first difference along dimension five of a `2x3x2` array produces a
`2x3x2x1x0` empty array. A scalar default difference is `0x1`; a `0x0` input
remains `0x0`.

Logical differences return double values because subtraction can produce `-1`
as well as `0` and `1`. This milestone implements numeric finite differences;
symbolic differentiation is a separate overload and is not inferred from
dynamic arguments.

## Common Result Construction

v0.47 originally kept its logical-order result constructor private to the
reduction module. v0.48 promotes it to
`runtimeNumericValueFromLogicalOrder`. Reductions, cumulative operations, and
differences now share these checks:

- normalize and validate complete dimensions;
- validate the logical element count;
- coerce every result element to the selected numeric class;
- map column-major logical coordinates into the runtime payload layout;
- preserve row-vector orientation, empty shapes, and significant trailing
  dimensions.

This keeps array algorithms independent of physical storage and gives future
numeric classes and native kernels one conversion boundary.

## Current Limitations

- Integer, single, complex, sparse, datetime, duration, table, object, and
  user-defined overloads need broader runtime storage and dispatch.
- `diff` implements numeric finite differences only. Symbolic expression and
  function differentiation require a symbolic layer.
- Moving-window operations such as `movsum`, `movprod`, `movmin`, `movmax`,
  and `movmean` are not implemented yet.
- The cumulative and difference calls remain outside closed scalar typed-loop
  regions. Native LLVM ORC lowering is future work.
- Class execution remains a bytecode-VM feature; the HIR interpreter does not
  execute classes.

## Next Iteration

- Add a shared moving-window runtime with scalar or two-sided windows, endpoint
  policy, dimensions, NaN policy, and shape-preserving output.
- Extend the common array substrate toward Cell parenthesis indexing,
  comma-separated lists, and object/listener arrays.
- Lower stable typed scalar operations into a native backend while preserving
  the existing guard, commit, and fallback contract.
