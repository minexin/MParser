# MParser v0.56 Scope

MParser v0.56 makes positional MATLAB `arguments` blocks structured and
executable in the bytecode runtime. Function and class APIs can enforce the
same dimensions, runtime classes, and validation functions already used by
structured class properties.

## Milestone Contract

- Project and CLI version are `0.56.0`.
- Each line in an `arguments` block is represented as `ArgumentDecl` syntax
  and `Argument` HIR, retaining its name, dimensions, class constraint,
  validators, source span, and parsed default expression.
- Required positional argument contracts execute before the function frame is
  initialized. This covers script-local functions, entry functions,
  constructors, instance methods, static methods, package functions, and
  path-loaded functions through the shared bytecode call path.
- Class conversion, shape checking, wildcard dimensions, and built-in
  validators reuse the property validation engine. Successfully converted
  values, rather than the unvalidated originals, enter the function frame.
- Validation diagnostics identify the callable and parameter, for example
  `argument validation failed for scale.factor`.
- Argument names that are not present in the function signature and duplicate
  declarations are semantic diagnostics.
- Block attributes such as `(Repeating)` or `(Output)`, default argument
  values, and name-value invocation syntax are structurally retained but
  explicitly diagnosed as not executable. They are not silently treated as
  ordinary statements.
- The HIR reference interpreter continues to parse and retain argument
  contracts but does not enforce them yet; executable validation in this
  milestone belongs to the bytecode VM and its JIT fallback path.

## Supported Examples

```matlab
function y = scale(x, factor)
arguments
    x (1,:) double {mustBeFinite}
    factor (1,1) double {mustBePositive, mustBeInteger}
end
y = x * factor;
end
```

The same declarations may appear in a class constructor or method. The
currently executable validators are the validation functions already listed
for v0.28 property contracts, including sign, finite/integer, shape/text, and
literal comparison validators.

## Validation

```powershell
cmake --build build -j 8
ctest --test-dir build --output-on-failure
```

`argument_validation_smoke` covers accepted and rejected local function
calls, scalar shape constraints, validators with literal comparison values,
constructors, instance methods, semantic declaration errors, and direct entry
function invocation.

## Next Iteration

- Move property/argument validation into a runtime-neutral service and enforce
  contracts in the HIR interpreter as well.
- Execute trailing default positional arguments in declaration order.
- Add `(Repeating)` and name-value argument groups with MATLAB-compatible
  duplicate-name and partial-name rules.
