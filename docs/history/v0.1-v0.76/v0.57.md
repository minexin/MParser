# MParser v0.57 Scope

MParser v0.57 makes positional `arguments` contracts runtime-neutral. The HIR
reference interpreter and bytecode VM now apply one validation service before
creating a function frame, so compatible scripts no longer change behavior
when switching execution backends.

## Milestone Contract

- Project and CLI version are `0.57.0`.
- `runtime_argument_validation` owns parameter class conversion, dimension
  checking and reshaping, wildcard inference, scalar expansion, and built-in
  validation functions.
- Both the HIR interpreter and bytecode VM validate local function arguments
  before binding parameters. Converted values are installed in the frame.
- The VM also uses the shared service for entry functions, constructors,
  instance methods, static methods, package functions, and path functions.
- `double`, `logical`, `char`, `string`, `cell`, `handle`, and object class
  constraints are supported. The VM supplies class availability and recursive
  inheritance queries; the class-free reference interpreter accepts exact
  object class matches.
- Fixed dimensions and one `:` wildcard follow the same shape contract in both
  runtimes. More than one wildcard is rejected because its shape is ambiguous.
- Sign, finite/NaN/integer, numeric, sparse, empty/scalar, vector/row/column/
  matrix, text, nonmissing, and literal comparison validators share one
  implementation.
- Diagnostics preserve the callable and parameter identity, such as
  `argument validation failed for scale.factor`.
- Default values, `(Repeating)`, output arguments blocks, and name-value calls
  retain the explicit v0.56 unsupported diagnostics.

## Examples

```matlab
answer = scale(3);

function y = scale(x)
arguments
    x (1,1) double {mustBePositive, mustBeInteger}
end
y = x * 2;
end
```

The example returns `6` through both:

```powershell
build\mparser.exe --run example.m
build\mparser.exe --run-bytecode example.m
```

## Validation

`argument_validation_smoke` runs accepted and rejected numeric contracts
through both runtimes and includes string-scalar validation, VM entry calls,
constructors, methods, malformed declarations, and unsupported defaults.
`runtime_argument_validation_smoke` directly covers every supported validator
family, numeric conversion, wildcard dimensions, and object inheritance hooks.
The complete repository suite remains the release gate.

## Next Iteration

- Execute trailing positional defaults in declaration order with access to
  previously validated parameters.
- Add runtime-neutral class metadata so the reference interpreter can validate
  inherited object constraints when its class execution support arrives.
- Add `(Repeating)` and name-value parameter groups without weakening existing
  positional arity diagnostics.
