# MParser v0.58 Scope

MParser v0.58 executes trailing positional defaults declared in MATLAB
`arguments` blocks. Defaults use the normal HIR or bytecode expression engine,
run once per omitted argument, and are bound in parameter order before the
function body starts.

## Milestone Contract

- Project and CLI version are `0.58.0`.
- The HIR interpreter and bytecode VM accept calls down to the last required
  positional parameter. Extra arguments remain rejected unless the signature
  declares `varargin`.
- An omitted parameter evaluates its declared default in the callee frame.
  Previously bound and validated parameters, `nargin`, and `nargout` are
  visible to later default expressions.
- Explicitly supplied values bypass default evaluation. Both supplied and
  defaulted values pass through the shared v0.57 conversion, shape, and
  validator service before they become visible to later parameters.
- `nargin` reports the number of values supplied by the caller, not the number
  of parameters after defaults are filled.
- Constructors, instance and static methods, local functions, path/package
  functions, and named VM entry functions share the same VM binding path.
- A required positional parameter after an optional parameter is rejected
  during semantic analysis.
- Bytecode defaults use `EnterArgumentDefault`/`LeaveArgumentDefault` regions.
  Normal function execution skips those regions; omitted-argument binding
  executes exactly the selected region and requires one result value.

## Example

```matlab
answer = scale(3);

function y = scale(x, factor, offset)
arguments
    x (1,1) double {mustBePositive}
    factor (1,1) double {mustBePositive} = x + 1
    offset (1,1) double {mustBePositive} = factor * 2
end
y = x + factor + offset;
end
```

Both `--run` and `--run-bytecode` return `answer = 15`.

## Cross-platform CI

All CLI tests now name the CMake `mparser` target directly. CTest can therefore
prepend `CMAKE_CROSSCOMPILING_EMULATOR` for Linux AArch64 runs. The diagnostic
helper also accepts the emulator command explicitly. This fixes the ARM job
failure where the x64 host attempted to launch an AArch64 executable without
the QEMU sysroot.

## Validation

`argument_validation_smoke` covers dependent defaults, explicit overrides,
default validation failures, actual `nargin`, named entry calls, constructors,
and methods through both execution backends where available. The complete
repository suite remains the local release gate; Windows x64, Linux x64, and
Linux AArch64/QEMU jobs remain the remote release gate.

## Next Iteration
