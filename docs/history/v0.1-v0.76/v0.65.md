# MParser v0.65 Scope

MParser v0.65 adds MATLAB per-instance dynamic properties to the executable
class runtime. It builds on the v0.63-v0.64 metadata model and keeps the same
portable C++20 representation on Windows x64, Linux x64, and Linux AArch64.

## Milestone Contract

- Project and CLI version are `0.65.0`.
- A loaded class may derive from the built-in `dynamicprops` handle
  superclass. Its instances retain normal handle aliasing semantics and are
  also recognized by `isa(obj, 'dynamicprops')` and `isa(obj, 'handle')`.
- `addprop(obj, name)` and `obj.addprop(name)` create a property only on that
  scalar instance and return a `matlab.metadata.DynamicProperty` descriptor.
- Property names must be identifiers and cannot duplicate a declared or live
  dynamic property on the same instance.
- Newly created properties contain a numeric empty value. Ordinary dot reads
  and writes use the owner's shared handle storage.
- `findprop(obj, name)` and `obj.findprop(name)` return a live dynamic
  descriptor first, a declared `matlab.metadata.Property` descriptor second,
  or an empty Property array when no property exists.
- `delete(descriptor)` and `descriptor.delete()` remove the value and property
  from the owner. `isvalid` becomes false for every alias of the deleted
  descriptor. A descriptor also becomes invalid when no owner alias remains.
- `properties(obj)` includes public non-hidden dynamic properties, while
  `isprop` reports hidden dynamic properties too. `methods` and `ismethod`
  expose the inherited `addprop`, `findprop`, and `isvalid` operations.
- Dynamic property descriptors participate in metadata equality, indexing,
  display, `class`, `metaclass`, and `isa`. The old
  `meta.DynamicProperty` spelling aliases
  `matlab.metadata.DynamicProperty`, which derives from
  `matlab.metadata.Property` and `matlab.metadata.MetaData`.

## Descriptor Attributes

The descriptor exposes the same common fields as Property metadata. `Name`,
`Description`, `DetailedDescription`, `Dependent`, `Constant`, `Abstract`,
`HasDefault`, `DefaultValue`, and `DefiningClass` are read-only. Dynamic
properties have no defining class, so `DefiningClass` is an empty Class array.

The following fields are writable:

- `GetAccess` and `SetAccess`: `public`, `protected`, `private`, or Class
  metadata selectors
- `GetMethod` and `SetMethod`: a function handle or an empty value
- `AbortSet`, `GetObservable`, `SetObservable`, `Hidden`, `Transient`,
  `NonCopyable`, and `WeakHandle`: scalar logical values
- `PartialMatchPriority`: a positive finite scalar

Without a callback, a member read or write uses the descriptor's stored value.
`GetMethod` receives the owner and produces one result. `SetMethod` receives
the owner and incoming value and is invoked for side effects. `AbortSet`
compares the current getter result with the incoming value before invoking the
setter. Reentrant callback access falls back to the stored slot so an accessor
can deliberately maintain the dynamic value without unbounded recursion.

## Runtime Representation

Each dynamic owner stores reserved descriptor and value entries in the same
shared map already used by handle objects. The descriptor stores its mutable
attributes in a separate shared map, giving descriptor aliases immediate
visibility of updates.

The VM registry contains only weak references from a descriptor ID to the
owner and descriptor maps. A descriptor never retains its owner, so adding a
property cannot create an owner/descriptor reference cycle. Initial workspace
objects are scanned when a VM starts, and owner access also lazily rebinds
descriptors. This preserves ordinary dynamic values, deletion, and future ID
allocation across a continued workspace.

Descriptor identities and internal keys contain no native pointers. The
implementation is independent of SLJIT, operating-system APIs, pointer width,
host endianness, and executable-memory behavior.

## Example

Run the checked-in demo with:

```powershell
build\mparser.exe --run-bytecode samples\dynamic_properties_demo.m
```

The demo covers handle aliases, instance isolation, a hidden property,
GetMethod and SetMethod callbacks, static and dynamic `findprop`, metadata
inheritance, method-form operations, and descriptor deletion. The final value
is `summary = 68`.

## Validation

`dynamic_property_smoke` covers:

- direct and method-form `addprop`, `findprop`, `delete`, and `isvalid`
- handle alias sharing and per-instance isolation
- stored, computed, and callback-written values
- writable descriptor attributes and read-only metadata diagnostics
- access enforcement, invalid names, and duplicate rejection
- static/dynamic lookup, hidden-property filtering, and method queries
- current and legacy metadata names and Property inheritance
- descriptor invalidation after deletion
- initial-workspace rebinding, deletion, and collision-free ID continuation

`dynamic_property_bytecode_cli_smoke` executes the complete sample. Both are
included in the focused portable Linux AArch64 QEMU CI selection as well as the
normal Windows x64 and Linux x64 suites.

For a local Windows release check:

```powershell
cmake --build build --config Release --clean-first --parallel
ctest --test-dir build -C Release --output-on-failure
build\mparser.exe --version
build\mparser.exe --run-bytecode samples\dynamic_properties_demo.m
```

## Remaining Boundary

- Dynamic property execution is authoritative in the bytecode VM. The HIR
  reference interpreter still does not execute class objects or metadata.
- `GetObservable` and `SetObservable` are retained descriptor attributes, but
  property pre/post-set and get listeners are not implemented yet.
- Function-handle accessor callbacks are executable during the VM run that
  created them. Function-handle registry reconstruction from a serialized or
  independently created workspace is not implemented.
- General handle-object destruction, `ObjectBeingDestroyed`, destructor
  methods, and object arrays remain outside this milestone. `delete` executes
  event-listener and DynamicProperty lifecycle only.
- MATLAB's complete metadata listener behavior, heterogeneous metadata array
  mutation, serialization rules, and all release-specific DynamicProperty
  attributes are not reproduced yet.
- Dynamic descriptors use run-local numeric IDs. Continuing one workspace is
  supported; merging objects created by unrelated VM runs is not yet an
  identity contract.
