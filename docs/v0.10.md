# MParser v0.10 Scope

MParser v0.10 adds runtime guard evaluation for typed IR regions. The typed IR
still does not execute optimized code, but guards can now be checked against
real runtime values and produce explicit enter/fallback decisions.

## Added Since v0.9

- New `BytecodeTypedIrGuardEvaluator`.
- New guard-check data structures:
  `BytecodeTypedIrEvaluation`, `BytecodeTypedIrRegionEvaluation`, and
  `BytecodeTypedIrGuardCheck`.
- CLI option `--check-typed-ir-bytecode`.
- Runtime kind/shape checks for guards that can be bound to final runtime
  variables, currently loop-variable guards and assignment-value guards.
- Explicit skipped checks for guards without live values, such as call-site
  argument/result guards after execution.
- Per-region counts for checked, passed, failed, and skipped guards.
- Per-region `enterTypedPath` decision.
- Expanded typed IR smoke coverage for guard pass and skip behavior.
- Project version and CLI version bumped to `0.10.0`.

## Why This Matters

v0.9 could describe typed regions. v0.10 starts validating whether a typed
region is safe to enter for the current runtime state:

```text
typed IR region -> guard evaluation -> enter typed path or fallback
```

This is still not full deoptimization. It is the guard-checking contract that a
future typed IR interpreter or LLVM JIT path can reuse before executing
specialized code.

## CLI Example

```powershell
build\mparser.exe --check-typed-ir-bytecode samples\bytecode_profile_demo.m
```

Expected guard-check signal:

```text
Bytecode typed IR guard checks:
  regions: 4
    region=0, kind=scalar-loop, target=i, checked=1, passed=1
      pass source=loop, role=variable, reason=matched number(1x1)
    region=1, kind=scalar-call-site, target=kernel, checked=0, skipped=2
      skip source=call-site, role=arg0
    region=2, kind=scalar-assignment, target=y, checked=1, passed=1
      pass source=assignment, role=value, reason=matched number(1x1)
```

## Current Pipeline

The optimization-facing pipeline is now:

```text
HIR
  -> bytecode
  -> bytecode VM profile
  -> optimization plan
  -> typed IR
  -> guard evaluation
```

The bytecode VM remains the execution baseline. Typed IR regions can now be
validated, but they are not executed as replacements yet.

## Remaining Before v1.0

I still do not consider this ready for a v1.0 label. The missing pieces are
substantial:

- Execute selected typed IR regions.
- Implement runtime fallback when guard checks fail.
- Model loop body ranges and region side effects.
- Expand MATLAB runtime coverage for objects, cells, structs, complex values,
  sparse arrays, and dynamic dispatch.
- Add performance benchmarking against the bytecode VM and reference
  interpreter.


Expected version output:

```text
MParser 0.10.0
```

## Next Iterations

The next high-value work is a tiny typed IR interpreter for scalar numeric
regions:

- Start with scalar assignment and scalar call-site regions.
- Keep each optimized execution behind guard evaluation.
- Fall back to bytecode VM behavior when a guard fails or a region is not
  executable.
- Add micro-benchmark output so performance claims become measurable.
