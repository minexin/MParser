# MParser v0.30 Scope

MParser v0.30 makes retained MATLAB `Abstract` and `Sealed` class metadata
executable. Abstract method prototypes and properties now form inherited
contracts, concrete classes are identified from the resolved hierarchy, and
sealed classes and methods prevent extension at class-load time.

## Major Capability

- Class `Abstract` and `Sealed` attributes accept implicit `true`, explicit
  `true`/`false`, and negated logical syntax through the existing attribute
  representation.
- A method signature in `methods (Abstract)` becomes a non-executable method
  contract. A prototype outside an abstract block and a function body inside
  an abstract block produce diagnostics.
- Abstract method requirements propagate through same-file single, multiple,
  and diamond inheritance. A concrete method with the same name satisfies the
  requirement; its parameter names, signature, access, and other attributes do
  not have to match the prototype.
- Properties declared in `properties (Abstract)` allocate no field and cannot
  define a default or get/set access methods. A concrete subclass implements
  the property by redeclaring it without `Abstract`.
- Concrete abstract-property implementations must preserve `GetAccess` and
  `SetAccess`. Validation belongs to the abstract declaration, is inherited by
  the effective concrete descriptor, and executes for defaults and later
  assignments. The implementation cannot declare a second validation block.
- A class becomes effectively abstract when its own `Abstract` attribute is
  true or any inherited method/property requirement remains unresolved. This
  matches MATLAB's automatic abstractness for classes that declare abstract
  members even without `classdef (Abstract)`.
- Direct construction of an abstract class fails and lists unresolved method
  and property names. Abstract bases can still run their concrete constructor
  portions while a concrete most-derived object is being built.
- A class with `Sealed = true` cannot be named as a superclass. A method with
  `Sealed = true` cannot be redefined by a subclass.
- A sealed class cannot be explicitly abstract or retain abstract members, and
  a method cannot be both abstract and sealed.
- A concrete member inherited from one base can satisfy an abstract contract
  inherited from another base before the final abstractness decision.
- Project and CLI version are `0.30.0`; CTest now contains 22 targets.

## Resolution Model

Class resolution keeps executable members and unresolved contracts in separate
tables:

```text
declared methods/properties
        |
        +-- concrete -> executable dispatch/layout tables
        |
        +-- abstract -> inherited requirement tables
                            |
                            +-- same-name concrete member -> requirement met
                            +-- no implementation -> effective Abstract class
```

Method contracts resolve by name. Abstract property contracts additionally
carry read/write access and the existing structured validation specification.
This keeps the runtime layout free of abstract fields while preserving the
validation order established in v0.28.

The implemented behavior follows MATLAB's documented class contracts:

- <https://www.mathworks.com/help/matlab/matlab_oop/abstract-classes-and-interfaces.html>
- <https://www.mathworks.com/help/matlab/matlab_oop/property-attributes.html>
- <https://www.mathworks.com/help/matlab/ref/matlab.metadata.method-class.html>
- <https://www.mathworks.com/help/matlab/ref/matlab.metadata.class-class.html>

## Example

```powershell
build\mparser.exe --run-bytecode samples\abstract_contract_demo.m
```

Expected values include:

```text
evaluated = 15
kind_code = 9
scale = 3
```

The sample declares a protected abstract method, an abstract validated
property, a concrete inherited method that dynamically dispatches to the
implementation, a sealed concrete method, and a sealed final subclass.

## Diagnostics Covered

- Constructing an explicit or automatically abstract class.
- Missing abstract method or property implementations.
- Abstract property defaults and property access methods.
- Mismatched abstract/concrete `GetAccess` or `SetAccess`.
- Validation redeclared by a concrete abstract-property implementation.
- Multiple inherited abstract property validations or incompatible access
  contracts.
- Method prototypes outside `methods (Abstract)`.
- Function implementations inside `methods (Abstract)`.
- Abstract constructors and abstract/sealed method combinations.
- Subclassing a sealed class or overriding a sealed method.
- Sealed classes that are explicitly or effectively abstract.

## Current Limitations

- Class loading remains limited to class definitions in one compiled source;
  cross-file, package, and path-based superclass discovery are unavailable.
- Class-list access policies and `AllowedSubclasses` are retained as attribute
  syntax but are not executable. Only unrestricted subclassing or `Sealed` is
  available.
- Private inherited property redeclaration is still rejected even though
  MATLAB permits a subclass-local property with the same name. Abstract
  property implementation is the only supported inherited redeclaration.
- Abstract-property validation supports the current v0.28 scalar and
  two-dimensional subset. N-dimensional arrays and additional validators
  remain future work.
- Runtime metadata introspection such as `matlab.metadata.abstractDetails`,
  `metaclass`, and dynamic class loading is not implemented.
- Events, listeners, dynamic properties, handle lifecycle callbacks, object
  arrays, and user-defined operator dispatch remain outside this class subset.
- The reference HIR interpreter and typed/JIT tiers do not execute class
  objects. Class contracts currently execute in the bytecode VM.
- Native machine-code JIT remains future work; current optimization tiers use
  portable typed-region execution and bytecode fallback.

## Next Iteration

- Execute class-list access policies such as `Access = ?Friend` and cell-array
  friend lists for classes, methods, and properties.
- Add `AllowedSubclasses` as the selective counterpart to `Sealed`.
- Support private inherited property redeclaration with declaring-class-local
  field identity.
- Continue toward persistent class-loader state and cross-file/package class
  discovery.
