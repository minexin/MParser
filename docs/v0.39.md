# MParser v0.39 Scope

MParser v0.39 completes the executable `.m` helper-function model for MATLAB
class folders. Functions under `@ClassName/private` now have the defining
class's lexical access rights without becoming methods, entering virtual
dispatch tables, or receiving an implicit object argument.

## Major Capability

- The source loader recognizes a `private/*.m` dependency immediately below a
  selected `@ClassName` folder.
- Namespace class folders such as `+securepkg/@Vault/private/readSecret.m`
  receive the canonical owner `securepkg.Vault`.
- `SourceUnit::classPrivateFunctionOwner` preserves that owner separately from
  `classMethodOwner` and the hidden function identity.
- `--module-info` prints `private-of=<qualified-class>` for each class-private
  helper source.
- Semantic HIR functions carry `lexicalClassName`; `--hir` prints it as
  `lexical-class=<qualified-class>`.
- Helpers remain hidden functions with identities such as
  `$private3>readSecret` and stay out of `CompiledModule::functions()`.
- No implicit object receiver is inserted. Helpers receive exactly their
  declared parameters and can also be called from static methods without an
  object.
- Helpers can read and write private properties and invoke private members of
  their defining class through the bytecode VM.
- One private helper can dependency-load and call another helper in the same
  `private` folder.
- Only methods of the defining class receive source binding edges. Subclasses
  and unrelated files cannot resolve the helper by its short name.
- Explicit `--path` roots whose final component is `private` are ignored, so
  the general symbol loader cannot bypass private-folder visibility.
- Project and CLI version are `0.39.0`; CTest contains 42 tests.

## Source Graph Model

The visible class, separate method, and helper sources retain different roles:

```text
<root>/+securepkg/@Vault/Vault.m
    class definition: securepkg.Vault

<root>/+securepkg/@Vault/reveal.m
    method-of: securepkg.Vault

<root>/+securepkg/@Vault/private/readSecret.m
    function: $private3>readSecret
    private-of: securepkg.Vault
```

The short name is never made globally visible. A method source that references
`readSecret` receives a source-specific edge:

```text
bind readSecret -> $private3>readSecret
```

The helper itself can receive another edge when it calls a sibling helper.
Different class folders can therefore contain the same helper filename without
sharing identity or privilege.

## Name Precedence

For a name used as a function call, the relevant semantic order is:

```text
variable
explicit import
same-source local function
wildcard import
class-private helper
class method or other lexical symbol
ordinary path function
builtin
```

This implements MATLAB's class-folder dispatch distinction:

```matlab
value = choose(obj);   % @Vault/private/choose.m
value = obj.choose(); % Vault method choose
```

The private helper wins only for function notation. Dot notation still creates
a member access and selects the class method. A local function later in the
same method file and a wildcard-imported function both retain their higher
precedence over the private helper.

## Lexical Access Frames

The bytecode runtime previously kept the active class method on a dynamic
stack. An ordinary function called from that method could therefore observe the
caller's class while checking private access. v0.39 makes the rule explicit:

1. Every function invocation pushes an access frame.
2. A method frame carries its declaring class.
3. A class-private helper frame carries `classPrivateFunctionOwner` through
   HIR and `FunctionInfo`.
4. An ordinary function frame carries an empty class identity.
5. The exact previous frame is restored on return.

This gives private helpers the intended lexical privilege while denying it to
ordinary path functions, even when a privileged method is their caller.

## MATLAB Alignment

MATLAB documents class-folder private functions as non-method helpers that are
callable only by methods of the defining class. They can access private class
members, do not require an object argument, and are not inherited by
subclasses. MATLAB also gives a private helper precedence for function notation
while preserving method precedence for dot notation. v0.39 implements those
rules for dependency-discovered `.m` files:

- <https://www.mathworks.com/help/matlab/matlab_oop/organizing-classes-in-folders.html>
- <https://www.mathworks.com/help/matlab/matlab_prog/private-functions.html>
- <https://www.mathworks.com/help/matlab/matlab_prog/function-precedence-order.html>

## Example

Run the class-private helper demo with:

```powershell
build\mparser.exe --run-bytecode `
  --path=samples\class_private_functions\lib `
  samples\class_private_functions\app\run_demo.m
```

Expected values:

```text
bumped_value = 6
dot_choice = 1006
function_choice = 16
private_after_bump = 6
private_value = 5
static_value = 7
```

The `Vault` demo reads and writes a private property through helper functions,
calls a no-object helper from a static method, and contrasts same-named helper
and method dispatch.

Inspect the seven-source graph and lexical HIR with:

```powershell
build\mparser.exe --module-info `
  --path=samples\class_private_functions\lib `
  samples\class_private_functions\app\run_demo.m

build\mparser.exe --hir `
  --path=samples\class_private_functions\lib `
  samples\class_private_functions\app\run_demo.m
```

## Regression Coverage

- Inline and separate class methods can call the same private helper.
- A private helper can call a second private helper.
- Private property reads and writes execute with the defining class identity.
- Static methods can call helpers that declare no object parameter.
- Function notation selects a same-named private helper.
- Dot notation selects the same-named class method.
- Same-source local functions win over private helpers.
- Wildcard imports win over private helpers.
- A subclass cannot call its superclass's private helper.
- A direct `private` search root does not expose helper files.
- An ordinary path function called by a method does not inherit private access.
- Source metadata, HIR metadata, module inspection, and the public function
  catalog retain their distinct contracts.

## Current Limitations

- Only dependency-discovered `.m` helper files are supported. `.mlx`, `.p`, and
  MEX helper precedence is not implemented.
- Command-form calls and executable function handles do not yet add source
  graph dependencies.
- The reference HIR interpreter still does not execute class objects. This
  milestone's class behavior uses `--run-bytecode`.
- Private-helper parameters remain dynamically typed unless ordinary HIR type
  evidence is available. Runtime object dispatch performs the final member
  selection and access check.
- Parsed-source metadata and dependency fingerprints are not cached yet.
- Native machine-code JIT remains future work. Current specialization uses
  portable typed regions with bytecode fallback.
