# MParser v0.45 Scope

MParser v0.45 introduces first-class logical scalars and arrays across the HIR
interpreter, bytecode VM, array runtime, and profile-driven optimization
pipeline. Logical values still use the portable numeric payload, but their
runtime class is now explicit and cannot be confused with double `0` and `1`.

## Milestone Contract

- Project and CLI version are `0.45.0`.
- `RuntimeValue` records `RuntimeNumericClass::Double` or
  `RuntimeNumericClass::Logical` for every numeric scalar or array.
- Comparisons, `~`, `&`, `|`, `&&`, `||`, `strcmp`, `any`, `all`, `isempty`,
  `islogical`, `isa`, and other implemented predicates return logical values.
- `true` and `false` create logical scalars or shaped logical arrays.
- `logical(A)` converts zero to false and nonzero finite or infinite values to
  true. Converting NaN is diagnosed. `double(A)` preserves values and shape
  while changing the numeric class.
- `class`, `isa`, and `islogical` distinguish logical and double data.
- Both baseline runtimes execute linear and multi-subscript logical indexing
  and logical-mask assignment.
- Runtime profiles, optimization guards, Typed IR, guard evaluation, and
  adaptive retraining preserve the numeric class. The existing scalar typed
  executor remains a double-only path.
- CTest contains 62 tests, including a dedicated logical indexing regression
  executable and both CLI execution modes for the new sample.

## Logical Indexing

`runtime_index` is the shared selection layer used by the interpreter, VM, and
indexed-assignment engine. It distinguishes a numeric subscript from a logical
mask before interpreting the payload:

```text
numeric subscript -> positive one-based integer -> optional assignment growth
logical mask      -> true logical positions     -> never grows the target
```

Logical positions are scanned in MATLAB column-major order even though the
current payload is physically row-major. A shorter mask may select the covered
prefix of the target. False entries beyond the target extent are ignored, but
any true entry beyond that extent produces a diagnostic. This rule applies to
both reads and writes.

Linear result shape follows MATLAB's vector rules:

- If the target and subscript are vectors, the result follows the target's row
  or column orientation.
- A logical selection from a non-vector target produces a column vector.
- A scalar selection produces a scalar and an empty selection retains the
  corresponding zero-length orientation.

Each dimension of a multi-subscript access may independently use a logical
mask. The selected Cartesian product keeps the same checked shape and
column-major value ordering used by numeric subscripts.

## Logical Assignment

`runtimeAssignNumericIndexed` resolves every subscript before mutation and
converts every right-hand element to the target numeric class before growth or
writes. This gives logical storage a transactional assignment contract:

- Scalar expansion and shape-compatible non-scalar assignment are supported.
- Zero becomes false and nonzero becomes true when writing a logical target.
- NaN conversion fails before any target element changes.
- Logical masks cannot grow an array; out-of-range true entries fail and
  out-of-range false entries do nothing.
- Numeric subscripts retain the existing checked automatic-growth behavior.

Logical arrays keep their class through transpose, indexing, reshape,
permutation, inverse permutation, squeeze, replication, and concatenation.
Mixed numeric concatenation is coerced to the first numeric input's class.

## Optimization Safety

`BytecodeValueObservation`, `BytecodeOptimizationGuard`, and
`BytecodeTypedValue` now carry a numeric-class field in addition to runtime
kind and full dimensions. Adaptive profile merging treats a class change as an
unstable mixed observation. Guard evaluation checks class and shape together,
and benchmark output comparison also includes numeric class.

The scalar typed-region executor currently specializes stable double inputs
and loop ranges. Its internal stack still preserves logical results from
comparisons and logical operators, so a loop may store a logical temporary and
then consume it in later arithmetic without losing its runtime class. A
logical scalar guard creates a generic typed candidate rather than a
`scalar-loop`, and logical loop ranges fall back to the ordinary bytecode VM.
Both baseline runtimes preserve the numeric class of a scalar `for` loop
variable so profiling sees the value that the script actually produced.

## User-Facing Builtins

The following forms are executable in both baseline runtimes:

```matlab
mask = A > 5;
picked = A(mask);
A(mask) = 100;

flags = logical([0 2 0 3]);
asDouble = double(flags);
logicalName = class(flags);
isLogical = islogical(flags);
isExpectedClass = isa(flags, "logical");

shaped = true(2, 3, 2);
cleared = false([2 3]);
```

The runnable sample is `samples/logical_index_demo.m`; it finishes with
`summary = 996` in both execution modes.

## Current Limitations

- Empty-right-hand deletion assignment is not implemented.
- Integer, single, character, string, sparse, object, enumeration, listener,
  and table arrays need richer common array-class storage.
- Dimension-aware logical reductions and functions such as `find` are future
  work.
- Cell parenthesis indexing, vector-valued brace selection, and
  comma-separated lists are not implemented.
- Matrix literal whitespace around unary signs still needs full MATLAB lexical
  disambiguation.
- Class execution remains a bytecode-VM feature; the HIR interpreter does not
  execute classes.
- Native machine-code JIT remains future work. The current optimized tier uses
  profile-driven Typed IR, guarded scalar execution, fallback, invalidation,
  and retraining.

## Next Iteration

- Add MATLAB empty-right-hand deletion for linear, row, and column selections
  on the shared transactional assignment layer.
- Add dimension-aware reductions while reusing canonical shape and logical
  iteration helpers.
- Continue expanding array classes without weakening numeric-class-aware JIT
  guards.
