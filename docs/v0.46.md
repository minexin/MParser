# MParser v0.46 Scope

MParser v0.46 combines a MATLAB array-semantics milestone with a visible
typed-loop performance gain. Both baseline runtimes now execute direct empty
indexed deletion, while the profile-driven scalar tier can keep statically
bound pure math calls inside a closed loop region. Command-form session
builtins make the new timing sample directly runnable.

## Milestone Contract

- Project and CLI version are `0.46.0`.
- Literal `[]` is a numeric 0-by-0 array.
- Direct `A(...)=[]` syntax deletes vector elements, complete matrix rows or
  columns, and complete N-dimensional slices in the HIR interpreter and VM.
- Numeric and logical deletion subscripts are supported. Repeated indices are
  removed once, empty selections do nothing, and the target numeric class is
  preserved.
- An empty value flowing through a variable or expression remains an ordinary
  assignment value. It cannot accidentally acquire deletion semantics.
- Bytecode records the bound callee name, direct-null-assignment marker,
  direct-colon mask, and nondeterministic timing assignment marker explicitly.
- `clear`, `clc`, `tic`, and `toc` execute in command form in both baseline
  runtimes.
- Closed scalar loops may directly execute statically bound calls to `abs`,
  `acos`, `asin`, `atan`, `cos`, `exp`, `log`, `sin`, `sqrt`, and `tan`.
- CTest contains 65 tests, including a dedicated deletion regression and CLI
  execution of the deletion sample through both baseline runtimes.

## Empty Deletion

MATLAB gives direct empty syntax a special meaning in indexed assignment. It
is not equivalent to assigning an arbitrary empty array. MParser preserves
that distinction before values reach the runtime:

```matlab
A(:, 3) = [];          % delete a complete column

empty = [];
A(:, 3) = empty;       % ordinary assignment, diagnosed for size mismatch
A(:, 3) = zeros(0, 0); % ordinary assignment, also a size mismatch
```

`BytecodeInstruction::nullAssignment` records the first form only.
`colonSubscripts` records which target subscripts were direct `:` syntax, so
the runtime does not infer slice deletion from a dynamically computed vector
that happens to contain every index.

`runtimeDeleteNumericIndexed` resolves every selection before mutation. Its
supported forms are:

```matlab
v([2 4]) = [];
v(logical([0 1 0 1])) = [];
A([1 3], :) = [];
A(:, [2 4]) = [];
B(:, :, 1) = [];
A(:) = [];
```

For a multi-subscript deletion, exactly one subscript is non-colon. All other
subscripts select complete dimensions. Selected indices are sorted and
deduplicated, then the result is rebuilt by mapping MATLAB column-major logical
coordinates into the runtime's row-major payload. This preserves coordinates,
full dimensions, and `double` or `logical` storage class.

The first N-dimensional implementation requires one explicit subscript per
significant dimension. Folded trailing-dimension deletion is diagnosed rather
than assigned an uncertain shape. Linear deletion accepts vectors, or a
selection that removes every element of a non-vector array.

## Session Commands

The semantic builtin registry and both runtime dispatchers recognize bare
command forms:

```matlab
clear;
clc;
tic;
elapsed = toc;
```

`clear` clears the current runtime frame, `clc` is a no-op in the noninteractive
CLI, `tic` stores a steady-clock timestamp, and `toc` returns elapsed seconds.
Calling `toc` before `tic` is a diagnostic. This milestone provides one timer
per runtime context; timer handles and nested timer selection remain future
work.

Assignments whose HIR contains the `toc` builtin are marked nondeterministic
in bytecode. `--run-typed-bytecode` ignores only those marked targets when it
compares the profiling run with the typed run. Every deterministic variable
must still match exactly.

## Pure Math Typed Regions

Earlier region analysis rejected every `CallOrIndex` instruction. This kept
dynamic MATLAB behavior safe, but it also prevented loops containing simple
calls such as `sin(i)` from entering the typed tier. v0.46 adds an explicit
pure-unary contract shared by all runtime paths:

```text
bound builtin + one scalar argument + one result + allowlisted pure name
    -> typed scalar math operation

anything else
    -> general call boundary and baseline fallback
```

Call lowering stores `calleeName`, so region analysis and execution do not
guess the target from stack position or source spelling. The typed executor
consumes the scalar argument directly and applies the same `runtime_math`
function used by the interpreter and baseline VM. Nested allowlisted calls
remain stack-correct. Calls to reductions such as `sum`, user functions,
methods, constructors, handles, and dynamically resolved targets are still
ineligible.

This is the existing portable profile-driven typed execution tier, not native
machine-code generation. It establishes a stable pure-call operation that a
later LLVM ORC backend can lower without changing frontend or bytecode
semantics.

## Timing Loop

`samples/timing_loop_demo.m` is the million-iteration script used to validate
the new path:

```matlab
clear;
clc;
tic;
for j = 1:1000
    for i = 1:1000
        k = abs(i) + 9;
        m = sin(i);
        n = k * m;
    end
end
a = toc
```

On the Windows x64 Release build used for this milestone, the baseline
bytecode VM reported about 14.1 seconds. The typed steady run reported about
1.8 seconds, with all 1,000,000 inner iterations executed by the scalar region
and no fallback. The exact elapsed value is machine- and run-dependent. The
`--run-typed-bytecode` command first performs an unreported profiling run, so
wall-clock command duration includes both profiling and typed execution; the
script's `toc` value in the final output measures the typed run itself.

Final deterministic values remain:

```text
i = 1000
j = 1000
k = 1009
m = 0.826879540532003
n = 834.32145639679
```

## Current Limitations

- Folded trailing-dimension null assignment is not implemented; N-dimensional
  deletion must provide one subscript per significant dimension.
- Cell parenthesis deletion, object-array deletion, string arrays, tables,
  structs, sparse arrays, and integer/single numeric classes need broader
  common array storage.
- `clear` currently clears the complete active frame and does not yet implement
  MATLAB name lists, wildcard forms, `clearvars`, global state, or persistent
  variables. `clc` has no visible effect in the noninteractive CLI.
- `tic`/`toc` provide one implicit timer and do not yet return or consume timer
  handles.
- The typed tier handles straight-line scalar loop bodies. General calls,
  indexed mutation, branches, nested control flow inside the selected region,
  and non-double guards fall back to bytecode.
- Native LLVM ORC machine-code generation remains future work.
- Class execution remains a bytecode-VM feature; the HIR interpreter does not
  execute classes.

## Next Iteration

- Add dimension-aware reductions and `find`, reusing canonical shape and
  logical-order traversal.
- Expand empty deletion to Cell parenthesis indexing and folded trailing
  dimensions without weakening direct-syntax metadata.
- Lower the stable pure-math typed operation into a native backend while
  preserving the same guard, commit, and fallback contract.
