# MParser v0.47 Scope

MParser v0.47 replaces the runtime's earlier scalar/global reduction shortcuts
with one shared, dimension-aware contract. The HIR interpreter and bytecode VM
now agree on reduction dimensions, result shapes, column-major traversal,
empty inputs, NaN policy, output classes, extrema indices, and `find` output
orientation.

## Milestone Contract

- Project and CLI version are `0.47.0`.
- `sum`, `prod`, `mean`, `min`, `max`, `any`, and `all` reduce the first
  non-singleton dimension by default.
- A positive scalar dimension, unique positive dimension vector, or `"all"`
  may select the dimensions to reduce. Dimensions beyond `ndims` behave as
  trailing singleton dimensions.
- `"omitnan"`/`"omitmissing"` and `"includenan"`/`"includemissing"` control
  missing numeric values. `min` and `max` omit NaN by default; ordinary
  numeric reductions include it by default.
- Ordinary numeric reductions accept `"default"`, `"double"`, and `"native"`.
  `any` and `all` always return logical values; `mean` remains double.
- `min` and `max` support a second index output, the `"linear"` option, an
  all-dimensions result, and elementwise two-input operation with implicit
  expansion.
- `find(X)`, `find(X,n)`, and `find(X,n,"first"|"last")` support one to three
  outputs, including N-dimensional trailing-subscript folding.
- Empty identities and shapes are explicit: `sum([])` is `0`, `prod([])` is
  `1`, `mean([])` is `NaN`, and `min([])`/`max([])` remain empty.
- CTest contains 68 tests, including a dedicated reduction/find regression and
  CLI execution of the sample through both baseline runtimes.

## Shared Reduction Runtime

`runtime_reduction` receives already-evaluated runtime values and requested
output count. Both dispatchers call it, so option parsing, shape selection, and
numeric behavior have one implementation. The runtime walks inputs in MATLAB
column-major logical order, groups values by the selected dimensions, and maps
the logical result coordinates back into the existing payload layout.

Default dimension selection is MATLAB-style first non-singleton behavior:

```matlab
A = reshape(1:24, 2, 3, 4);
columnTotals = sum(A);        % 1-by-3-by-4
rowTotals = sum(A, 2);        % 2-by-1-by-4
pageTotals = sum(A, [1 2]);   % 1-by-1-by-4
grandTotal = sum(A, "all");   % scalar 300
```

This is a deliberate compatibility correction. Before v0.47, the small
runtime treated bare `sum(A)` as a global total. Existing samples that need a
global total now use `sum(A, "all")`, which records the intended semantics and
avoids another migration when more numeric classes arrive.

Empty groups use the operation's identity where one exists. A mean with no
included values is NaN. Empty extrema preserve an empty result shape. Invalid
zero, fractional, or repeated dimensions are diagnosed before any result is
committed.

## Extrema

Reduction-form extrema use the MATLAB placeholder and dimension forms:

```matlab
[values, indices] = max(X, [], 2);
[values, linearIndices] = max(X, [], 2, "linear");
[maximum, linearIndex] = max(A, [], "all");
```

For one selected dimension, the second output is the position along that
dimension. `"linear"` reports the input's one-based linear index. A
multi-dimension vector request with a second output must explicitly request
`"linear"`; MParser diagnoses the ambiguous form instead of inventing an
index convention. Two nonempty inputs select elementwise minima or maxima and
use the same N-dimensional implicit-expansion contract as arithmetic.

`min` and `max` preserve the input numeric class for values and return double
indices. Their default policy omits NaN; an include flag makes the first NaN in
logical traversal order the selected result.

## Find

`find` scans the canonical logical order and supports the common selection and
output forms:

```matlab
linear = find(X);
lastTwo = find(X, 2, "last");
[rows, columns] = find(X);
[rows, columns, values] = find(X, 2, "last");
```

The single-output form preserves row-vector orientation when the input is a
row vector; ordinary array results are columns. For N-dimensional multi-output
calls, the first output is the row subscript and the second folds dimensions
two through N into one column subscript, matching MATLAB's two-subscript view.
The third output preserves the input's numeric class.

## Current Limitations

- Weighted means, cumulative and moving reductions, `median`, `mode`, `std`,
  and `var` are not implemented yet.
- Integer, single, complex, sparse, string, table, object, and user-defined
  reduction dispatch need broader runtime storage and overload resolution.
- A vector-dimension `min`/`max` call with a second output currently requires
  `"linear"`; comparison methods and the wider MATLAB option matrix remain
  future work.
- `any` and `all` support dimensional selection but not missing-value flags.
- Native LLVM ORC machine-code generation remains future work. Reduction calls
  stay outside the current closed scalar typed-loop regions.
- Class execution remains a bytecode-VM feature; the HIR interpreter does not
  execute classes.

## Next Iteration

- Add shared cumulative array operations such as `cumsum`, `cumprod`, and
  `diff`, retaining dimensions, NaN policy, and column-major traversal.
- Extend the common array substrate toward Cell parenthesis indexing,
  comma-separated lists, and object/listener arrays.
- Lower the stable typed scalar operations into a native backend while
  preserving the existing guard, commit, and fallback contract.
