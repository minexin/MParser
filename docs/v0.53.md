# MParser v0.53 Scope

MParser v0.53 hardens the SLJIT scalar-loop tier for long-lived processes. The
previous unbounded structural cache is now a bounded, thread-safe LRU with
explicit configuration, lifecycle operations, metrics, CLI controls, and
cross-platform regression coverage.

## Milestone Contract

- Project and CLI version are `0.53.0`.
- The repository continues to vendor SLJIT revision
  `3907e69005ba6e30b225000f24aaef3632f88347`; default builds perform no
  dependency download.
- The process-wide native cache defaults to 256 entries and 16 MiB of generated
  SLJIT code.
- Both entry count and code-byte limits are enforced using least-recently-used
  eviction. A hit refreshes recency.
- A zero limit retains no generated code but still permits native compilation
  and immediate execution.
- A kernel larger than the byte budget executes uncached rather than forcing
  unrelated entries out of the cache.
- Reconfiguration applies immediately. Shrinking limits evicts least-recently
  used entries until both constraints hold.
- Clear, statistics reset, and statistics snapshot are independent operations.
- Concurrent lookup, installation, reconfiguration, clear, and statistics
  access are data-race free. Active executions retain their generated code
  across eviction or clear.
- Cache insertions, bypasses, evictions, and evicted bytes propagate through
  typed-region and bytecode VM profiles.
- CLI users can configure limits and print process cache statistics.
- Native-enabled CTest contains 80 tests; native-disabled CTest contains 77.
- CI builds and tests Windows x64 and Linux x64, then cross-compiles Linux
  AArch64 and executes focused native and portable cache paths under QEMU.

## Cache Policy

The cache key remains the structural identity of a validated scalar kernel.
Resident entries are held by shared ownership and linked into an LRU list. A
lookup takes the cache mutex briefly, updates hit/miss statistics, and promotes
a hit to most recently used. SLJIT compilation happens after a miss and outside
the mutex.

Installation checks for a same-key winner before applying limits. Concurrent
misses may therefore compile the same kernel, but only one copy becomes
resident; the other callers use that resident code and duplicate compilations
are counted. This avoids holding the global cache lock during code generation.

Evicted or cleared code is moved out of the cache while locked and destroyed
after unlocking. An executing caller owns a separate reference, so another
thread may safely shrink or clear the cache without freeing live machine code.
The byte budget counts `sljit_get_generated_code_size` results; C++ key and
container metadata are not included.

The public lifecycle surface is:

```cpp
void configureNativeScalarJitCache(
    const NativeScalarJitCacheLimits& limits);
void clearNativeScalarJitCache();
void resetNativeScalarJitCacheStatistics();
NativeScalarJitCacheStatistics nativeScalarJitCacheStatistics();
```

`resetNativeScalarJitCacheStatistics` preserves limits and resident entries.
`clearNativeScalarJitCache` preserves limits and activity counters while adding
clear totals. Native-disabled builds expose the same control surface and report
an unavailable backend with an empty cache.

## Metrics

The snapshot reports current limits, resident entries and code bytes, lookups,
hits, misses, successful and failed compilations, insertions, duplicate
compilations, bypasses, evictions, evicted bytes, clears, cleared entries, and
cleared bytes.

Each native typed execution also reports whether it compiled, hit, inserted, or
bypassed the cache, plus evictions caused by that installation. The typed-region
executor and bytecode VM accumulate those fields without changing portable or
fallback behavior.

## CLI and Sample

The CLI options are:

```text
--native-cache-entries=N
--native-cache-bytes=N
--native-cache-stats
```

`--native-cache-stats` prints a snapshot when the process exits. It can be used
alone to inspect backend availability and default limits, or alongside an
execution mode. The following command promotes three functions into a
two-entry cache:

```powershell
build\mparser.exe --run-module-runtime --adaptive-hot-loop=5 `
  --typed-backend=native --native-cache-entries=2 `
  --native-cache-bytes=1048576 --native-cache-stats `
  --module-call=cache_add:2 --module-call=cache_add:2 `
  --module-call=cache_add:2 --module-call=cache_multiply:2 `
  --module-call=cache_multiply:2 --module-call=cache_multiply:2 `
  --module-call=cache_absolute:2 --module-call=cache_absolute:2 `
  --module-call=cache_absolute:2 samples\native_cache_demo.m
```

The three results are `52`, `72`, and `22`. The final cache snapshot contains
two entries and reports one LRU eviction.

## Build and Validation

Windows native Debug:

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug `
  -DMPARSER_ENABLE_NATIVE_JIT=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure --interactive-debug-mode 0
```

Portable native-disabled build:

```powershell
cmake -S . -B build-nojit -G Ninja -DCMAKE_BUILD_TYPE=Debug `
  -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit --parallel
ctest --test-dir build-nojit --output-on-failure --interactive-debug-mode 0
```

The cache smoke test covers deterministic LRU refresh and eviction, code-budget
bypass, immediate dynamic shrink, explicit clear, statistics reset, and an
eight-thread same-key race. The test is compiled in both native-enabled and
native-disabled builds. The module-runtime CLI smoke forces a real SLJIT cache
eviction through three independently promoted MATLAB functions.

The checked-in Linux AArch64 toolchain and CI use only portable C++20, CMake
Threads, SLJIT public APIs, and QEMU user-mode execution. There are no Windows
or x86-specific cache calls. Physical ARM64 Linux hardware remains required for
authoritative performance and long-duration executable-memory qualification.

## Current Limitations

- The native cache is process-local and is not serialized across runs.
- The byte budget excludes key strings and container/control metadata.
- Concurrent same-key misses can perform duplicate compilation; installation
  is convergent but not single-flight.
- Typed regions still specialize scalar numeric loop values. Arrays, complex
  values, integer payloads, objects, Cells, sparse values, dynamic calls, and
  indexing remain outside this native executor.
- Promotion still occurs between adaptive invocations rather than through
  loop-midpoint on-stack replacement.
- Linux AArch64 performance has not been measured on physical hardware in this
  Windows workspace.

## Next Iteration

- Broaden typed regions toward contiguous numeric arrays and vectorizable
  elementwise loops.
- Add optional single-flight compilation if real workloads show material
  duplicate-compilation pressure.
- Evaluate persistent cache metadata behind the same structural-key and
  backend boundary without coupling frontend IR to SLJIT.
- Run long-duration native JIT stress and performance tests on physical Linux
  AArch64 hardware.
