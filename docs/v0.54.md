# MParser v0.54 Scope

MParser v0.54 adds the first array data path to the typed loop executor. Hot
closed `for` regions may now read and update scalar elements of preallocated
dense double vectors through both the portable register kernel and SLJIT native
code. The implementation preserves the existing bytecode fallback boundary and
does not weaken MATLAB indexing semantics to obtain native execution.

## Milestone Contract

- Project and CLI version are `0.54.0`.
- The repository continues to vendor SLJIT revision
  `3907e69005ba6e30b225000f24aaef3632f88347`; default builds perform no
  dependency download.
- Region analysis distinguishes direct linear index reads and writes from
  calls, member mutation, brace indexing, multi-subscript indexing, deletion,
  and other unsupported mutation.
- Eligible array inputs are dense double `Vector` or `Matrix` values with at
  most one non-singleton dimension and a payload size matching their shape.
- Typed indexes are scalar, finite, positive, integer-valued, 1-based, and must
  remain inside the preallocated payload.
- `LoadArrayElement` and `StoreArrayElement` are backend-neutral typed kernel
  operations. Scalar arithmetic, comparisons, branches, nested loops, and pure
  unary math builtins can surround those operations.
- Portable and native execution copy array payloads before entering the region.
  Written arrays and scalar slots are committed together only after every
  iteration succeeds.
- Invalid indexes, unsupported runtime kinds/shapes, binding type changes, and
  growth requirements return to an unchanged bytecode frame.
- Native code calls checked array helpers through SLJIT's public mixed
  pointer/word/double call ABI. No Windows, x86, or AArch64 register convention
  is encoded in MParser.
- The native cache key includes array slot structure but excludes runtime
  values, pointers, lengths, and dimensions.
- Optimization-plan and typed-IR output report linear index read/write counts.
- Native-enabled CTest contains 82 tests; native-disabled CTest contains 78.
- CI builds Windows x64 and Linux x64, then cross-compiles Linux AArch64 and
  executes focused native and portable linear-array paths under QEMU.

## Supported Typed Array Shape

The current runtime stores general multidimensional payloads in row-major
storage while MATLAB linear indexes are column-major. Those offsets are
identical for row vectors, column vectors, and shapes with only one
non-singleton dimension. v0.54 therefore specializes exactly that subset.

Examples that can enter the typed array path include:

```matlab
x = 1:1000;
y = zeros(1, 1000);
for i = 1:1000
    y(i) = sin(x(i)) + 2 * x(i);
end
```

```matlab
x = (1:1000)';
y = zeros(1000, 1);
for i = 1:1000
    y(i) = x(i) * 3;
end
```

A general matrix such as `zeros(20, 30)` remains on the bytecode VM even when
used with one linear subscript. Multi-subscript reads/writes, colon and vector
subscripts, logical masks, deletion, brace indexing, and automatic growth also
remain on the VM.

## Transactional Execution

Compilation imports scalar inputs into scalar slots and supported array inputs
into separate array slots. Array loads produce scalar registers. Array stores
modify the kernel-owned payload and mark its array slot written. The workspace
is reconstructed only after the outer loop and every nested control span have
completed.

If an access fails after earlier iterations wrote elements, the executor
returns no candidate workspace. `BytecodeVm::executeTypedLoop` therefore keeps
the original frame and stack and executes the full loop through ordinary
bytecode. This also preserves MATLAB automatic growth: the typed attempt rejects
the first out-of-bounds access, then the VM reruns from the untouched
preallocated value and performs normal growth.

## Native ABI and Cache

Generated code passes `NativeContext*`, the structural array slot, and one or
two doubles to checked C++ helpers declared with `SLJIT_FUNC`. Calls use:

```text
SLJIT_ARGS3(F64, P, W, F64)
SLJIT_ARGS4V(P, W, F64, F64)
```

SLJIT assigns the correct registers and stack locations for Windows x64, Linux
x64, and Linux AArch64. Helpers set a runtime status for non-integer,
non-positive, out-of-bounds, or invalid-slot accesses. Generated code branches
to a common failure return before committing any state.

Cached code reads all payload pointers and lengths from `NativeContext`. The
cache key records scalar slot count, array slot count, instruction stream, and
each instruction's array slot. It intentionally omits current pointers, values,
shapes, and lengths, so one compiled structural kernel can safely execute over
different conforming vectors.

## CLI and Sample

Run the sample through either backend:

```powershell
build\mparser.exe --run-typed-bytecode --typed-backend=portable `
  samples\typed_linear_array_demo.m
build\mparser.exe --run-typed-bytecode --typed-backend=native `
  samples\typed_linear_array_demo.m
```

Expected values are:

```text
first = 2.8414709848079
last = 40.9129452507276
checksum = 420.99822188442
```

Both commands report `baseline outputs: match`. The portable reason is
`predecoded linear-array scalar kernel executed`; the native reason identifies
a compiled or cached SLJIT linear-array scalar kernel.

Use `--plan-bytecode` or `--typed-ir-bytecode` with the sample to inspect
`linearIndexReads`, `linearIndexWrites`, `linear-index-reads`, and
`linear-index-writes`.

## Build and Validation

Windows native Debug:

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug `
  -DMPARSER_ENABLE_NATIVE_JIT=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure --interactive-debug-mode 0
```

Portable native-disabled build:

```powershell
cmake -S . -B build-nojit -G Ninja -DCMAKE_BUILD_TYPE=Debug `
  -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit --parallel
ctest --test-dir build-nojit --output-on-failure --interactive-debug-mode 0
```

Focused tests cover row and column vectors, write-then-read flow, nested loops
with structured branches, portable and native output equivalence, cache-
compatible structural lowering, automatic-growth fallback, multidimensional-
shape fallback, and transaction preservation after a late bounds failure. CLI
tests execute the checked-in sample with both backends. The Linux AArch64 CI
runs those paths under QEMU with native JIT both enabled and disabled.

## Current Limitations

- The typed array path supports dense double payloads only. Logical, integer,
  complex, sparse, Cell, object, and string arrays remain outside it.
- Only scalar direct linear indexing is specialized. General matrix/N-D linear
  offset conversion and multiple/colon/vector/logical subscripts remain on the
  VM.
- Arrays must already exist and cannot grow, shrink, or change binding type in
  the typed region.
- The native emitter currently performs one checked helper call per indexed
  load or store. It does not yet inline bounds checks, hoist loop invariants,
  vectorize, or emit SIMD operations.
- Transactional array copies favor correctness and a stable deoptimization
  contract; copy elision and ownership-aware buffers are future work.
- Physical Linux AArch64 hardware remains required for authoritative
  performance and long-duration executable-memory qualification.

## Next Iteration

- Inline and hoist validated array bounds where loop induction proves safety.
- Add elementwise vector kernels and SIMD lowering behind the same typed IR.
- Generalize column-major offset handling without exposing runtime layout to
  frontend or semantic layers.
- Preserve the same transactional fallback contract while reducing array-copy
  cost for large preallocated buffers.
