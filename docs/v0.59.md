# MParser v0.59 Scope

MParser v0.59 makes MATLAB `arguments` groups part of the stable frontend and
executes repeating input groups in both runtimes. Functions can now receive
zero or more complete repetitions, with each declared repeating parameter
bound as a Cell and validated element by element.

## Milestone Contract

- Project and CLI version are `0.59.0`.
- `arguments`, `arguments (Input)`, `arguments (Repeating)`,
  `arguments (Input,Repeating)`, `arguments (Output)`, and
  `arguments (Output,Repeating)` have explicit `ArgumentBlockKind` values.
- Syntax and HIR retain a dedicated argument-block node. Dotted declarations
  such as `options.Scale` are no longer truncated to the structure name.
- `FunctionSignature` classifies named parameters as positional, repeating, or
  name-value and records the required positional prefix after defaults.
  Interpreters do not infer the calling convention from raw text.
- A repeating input block may declare one or more parameters. Calls provide
  zero or more complete copies of the whole group; an incomplete copy fails
  before function execution.
- Each repeating declaration receives a one-dimensional Cell. Every supplied
  element independently passes the shared class conversion, dimension check,
  and validator service. Diagnostics identify the failing occurrence, for
  example `collect.x{2}`.
- Fixed positional defaults still evaluate and validate in order before the
  repeating values. Callers cannot skip an optional positional parameter and
  then start a repeating group.
- A repeating block containing `varargin` must contain no other declaration.
  Each excess input is validated before the ordinary `varargin` Cell is bound.
- Local functions and the HIR interpreter, bytecode local/path/package calls,
  constructors and methods, and named VM entry functions share the same group
  layout. Static class-method coverage is included in the release test.
- `CompiledModule` preflight, ordinary reusable invocations, and
  `AdaptiveModuleRuntime` sessions share the fixed/default/repeating arity
  contract. They accept zero repetitions and reject partial groups before a
  session is created.
- `nargin` in the function body reports the number of values supplied by the
  caller, including every value in all repetitions.

## Semantic Rules

The semantic pass now rejects multiple repeating input or output blocks,
argument blocks after executable code, input blocks after output blocks,
repeating declarations with defaults, partial or reordered repeating
signatures, positional declarations after repeating or name-value groups,
name-value fields inside a repeating block, and invalid `varargin` or
`varargout` group shapes.

MATLAB workspace-sensitive functions such as `nargin`, `eval`, and `load` are
not permitted inside an `arguments` default expression. v0.59 corrects the
temporary v0.58 extension that exposed `nargin` while evaluating a default;
`nargin` remains available normally in the function body.

Name-value and output groups are parsed, lowered, classified, and checked for
signature ownership and ordering. Their runtime calling conventions are not
implemented in v0.59, so invoking such a function produces a precise runtime
diagnostic instead of silently omitting validation.

## Example

```matlab
[count, firstX, lastY] = summarize(1, 10, 20, 30, 40);

function [count, firstX, lastY] = summarize(seed, x, y)
arguments
    seed (1,1) double
end
arguments (Repeating)
    x (1,1) double {mustBePositive}
    y (1,1) double {mustBeInteger}
end
count = numel(x);
firstX = x{1};
lastY = y{count};
end
```

Both commands execute two repetitions:

```powershell
build\mparser.exe --run samples\repeating_arguments_demo.m
build\mparser.exe --run-bytecode samples\repeating_arguments_demo.m
```

The demo reports `summary = 2145`.

## Validation

`repeating_argument_smoke` uses explicit failure returns in Release builds and
covers group metadata, name-value classification, zero and multiple
repetitions, incomplete groups, occurrence-specific validation failures,
repeating `varargin`, static class methods, named entry functions, compiled
module preflight and invocation, adaptive module sessions, and semantic
restrictions. Two CLI tests execute the checked-in demo through both runtimes.
The complete CTest suite remains the local release gate; Windows x64, Linux
x64, and Linux AArch64/QEMU GitHub jobs remain the remote release gate.

## Next Iteration

- Execute name-value calls, including defaults, duplicate/unknown names, and
  modern `Name=value` syntax.
- Validate fixed and repeating output arguments after function execution.
- Consolidate the remaining per-runtime value binding and diagnostics behind a
  reusable invocation object without changing the shared signature contract.
