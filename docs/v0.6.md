# MParser v0.6 Scope

MParser v0.6 closes the largest remaining bytecode VM control-flow gap by
executing `switch/case/otherwise` and `try/catch`. This moves two MATLAB
control constructs from reference-interpreter-only support into the bytecode
path used by profiling and future JIT work.

## Added Since v0.5

- Bytecode ops for switch dispatch:
  `SwitchBegin`, `SwitchCase`, `SwitchOtherwise`, and `SwitchEnd`.
- Bytecode lowering for `switch` with scalar, string, vector, and matrix case
  values.
- VM switch context stack with MATLAB-style equality matching through the
  existing runtime equality helper.
- Bytecode ops for exception-style recovery: `TryBegin` and `TryEnd`.
- Bytecode lowering for `try/catch`, including catch variable extraction.
- VM try context stack that records diagnostic base, stack depth, loop depth,
  index-context depth, and switch-context depth.
- Diagnostic recovery into `catch` blocks, including assignment of the catch
  variable to the captured diagnostic message.
- Local function calls isolate try/switch context so callee diagnostics return
  to the caller and are caught at the caller's active try site.
- Bytecode smoke coverage for new switch/try ops.
- Bytecode VM smoke coverage for switch case matching, otherwise dispatch,
  try/catch recovery, and catch variable binding.
- Project version and CLI version bumped to `0.6.0`.

## Bytecode VM Supported Subset

The v0.6 VM can execute the v0.5 numeric/string subset and additionally handle:

- `switch` selectors over numbers, strings, vectors, and matrices.
- `case` equality matching and `otherwise` fallback.
- `try` bodies that recover runtime diagnostics into `catch` blocks.
- Catch variables containing the diagnostic message as a string.

This materially increases the number of MATLAB scripts that can run through
bytecode instead of falling back to the HIR interpreter.

## VM Gaps

The VM still intentionally reports diagnostics for features that need richer IR
or runtime metadata:

- Automatic array growth during indexed assignment.
- Non-scalar right-hand-side indexed assignment shape matching.
- Dynamic function handles and unresolved function dispatch.
- Classes, object dispatch, member assignment, cells, brace indexing, structs,
  tables, sparse arrays, and complex values.
- Actual JIT compilation, type/shape guards, optimized IR generation, and
  deoptimization.

These remain covered, where implemented, by the HIR interpreter.

## Validation

Validated on Windows with MSVC Build Tools:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
build\mparser.exe --version
build\mparser.exe --run-bytecode samples\switch_demo.m
build\mparser.exe --run-bytecode samples\try_catch_demo.m
build\mparser.exe --profile-bytecode samples\bytecode_profile_demo.m
build\mparser.exe --run-bytecode samples\bytecode_indexing_demo.m
```

Expected version output:

```text
MParser 0.6.0
```

Expected bytecode switch demo result:

```text
y = 4332
```

Expected bytecode try/catch demo result:

```text
message = "unknown bytecode runtime variable: missingName"
y = 13
```

## Next Iterations

The next high-value work is to enrich profile data with runtime type and shape
observations:

- Record value kind and shape for stable call/index sites.
- Record loop variable and assigned target shapes inside hot loops.
- Use those observations as the first guard input for a small optimizing IR.
- Continue reducing duplicate numeric helper logic between the HIR interpreter
  and bytecode VM.
