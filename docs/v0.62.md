# MParser v0.62 Scope

MParser v0.62 makes MATLAB class-derived name-value declarations executable.
An `arguments` declaration such as `options.?PlotOptions` now expands the
loaded class contract instead of remaining unsupported syntax.

## Milestone Contract

- Project and CLI version are `0.62.0`.
- Syntax and HIR retain the name-value structure root and qualified source
  class separately.
- A shared argument-contract catalog resolves inherited class properties once
  from the loaded HIR graph.
- Public settable properties become ordinary `options.Property` invocation
  contracts. Constant, private, protected, and class-list-restricted
  properties are excluded.
- `SetAccess=immutable` properties are available only inside the constructor
  of their declaring class.
- Explicit dotted declarations override class-derived validation regardless of
  whether they appear before or after `options.?ClassName`.
- Property dimensions, class constraints, and validators are reused. Property
  defaults are not copied into the options Struct, so omitted fields remain
  absent. Define an explicit `options.Field = value` declaration when the
  function needs that field to have a default.
- The HIR interpreter, bytecode VM, named entries, `CompiledModule` preflight,
  adaptive sessions, constructors, instance methods, and static methods use
  the same expanded name-value set.
- Existing exact and partial matching, ambiguity diagnostics,
  last-value-wins duplicates, modern `Name=value`, legacy string/value tails,
  and positional-only `nargin` semantics remain unchanged.

## Semantic Rules

A function can contain only one class-property name-value source. The source
root must be a declared function parameter and can appear only in an ordinary
input `arguments` block. The source class must be present in the loaded source
graph.

Expanded field names remain globally unique across every name-value Struct in
the function and cannot collide with positional or repeating parameters.
Explicit `options.Field` declarations suppress the corresponding derived
field before collision checks and runtime binding.

## Example

```matlab
answer = configure(Width=3, Height=4);

function y = configure(options)
arguments
    options.?PlotOptions
    options.Height (1,1) double {mustBeNonnegative}
end
y = options.Width * 10 + options.Height;
end

classdef PlotOptions
properties
    Width (1,1) double {mustBePositive} = 100
    Height (1,1) double {mustBePositive} = 200
end
end
```

The explicit `Height` declaration permits zero and overrides the class
validator. The class defaults `100` and `200` do not populate `options`.

Run the checked-in inheritance and override demo with:

```powershell
build\mparser.exe --run samples\class_property_arguments_demo.m
build\mparser.exe --run-bytecode samples\class_property_arguments_demo.m
```

Both runtimes report `answer = 34` and `partial = 52`.

## Validation

`class_property_argument_smoke` covers syntax/HIR retention, inherited public
properties, private/protected/constant filtering, class-default omission,
order-independent explicit overrides, exact and partial matching, duplicate
handling, derived validator execution, unknown and ambiguous names, unavailable
classes, multiple sources, root and field collisions, compiled-module
preflight/invocation, and immutable constructor properties. Two CLI tests run
the sample through the interpreter and bytecode VM.

The complete CTest suite remains the local release gate. Windows x64, Linux
x64, and Linux AArch64/QEMU GitHub jobs remain the remote release gate.

## Platform Hardening

The Windows CLI sets process error mode and Windows Error Reporting flags before
runtime initialization. Fatal process failures still produce a nonzero exit
and diagnostic records but do not display a blocking system crash dialog.
Linux and ARM builds do not compile or link the Windows-specific path.

## Remaining Boundary

Class-property expansion is based on the statically loaded HIR class graph; it
does not yet use dynamic MATLAB metaclass reflection. User-defined validators
remain limited by the executable validator subset, and richer object/array
name-value values still follow the current runtime type coverage.
