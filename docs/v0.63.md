# MParser v0.63 Scope

MParser v0.63 makes the loaded MATLAB class model available to executable
introspection code. The bytecode VM can now create, index, compare, and query
read-only metadata values instead of treating `?ClassName` as syntax-only HIR.

## Milestone Contract

- Project and CLI version are `0.63.0`.
- `?ClassName` returns a `matlab.metadata.Class` value for a loaded user class
  or a supported built-in class.
- `metaclass(obj)` returns the runtime class of an object. Passing a character
  vector describes `char`, matching MATLAB rather than treating the text as a
  class name.
- `matlab.metadata.Class.fromName("ClassName")` and
  `meta.class.fromName("ClassName")` return the named descriptor or a 0-by-1
  empty metadata array when the class is unavailable.
- Runtime values use current `matlab.metadata.*` names. The renamed
  `meta.class`, `meta.property`, `meta.method`, `meta.event`,
  `meta.EnumerationMember`, and `meta.package` names remain accepted by
  `isa` and static lookup.
- Class descriptors expose `Name`, class attributes, namespace, direct
  superclasses, and property, method, event, and enumeration-member lists.
- Property, method, event, enumeration-member, and namespace descriptors
  expose their implemented read-only attributes and defining-class links.
- Metadata arrays share the normal runtime dimensions, `numel`, `isempty`, and
  MATLAB column-major parenthesis-indexing rules.
- Scalar class descriptors support `==`, `~=`, `<`, `<=`, `>`, and `>=`.
  Ordering operators express subclass and superclass relationships.
- `properties`, `methods`, and `events` return inherited visible names.
  `isprop` tests declared property existence, including hidden or inaccessible
  properties, while `ismethod` reports only non-hidden public methods.
- `metafunction("ClassName/MethodName")` returns a
  `matlab.metadata.Method` descriptor for a loaded class method.
- Metadata properties are read-only and assignment produces a runtime
  diagnostic.

## Runtime Representation

`runtime_metadata` stores a scalar descriptor as an ordinary object-shaped
`RuntimeValue` with a canonical metadata class and a stable identity string.
Arrays contain scalar descriptors in `RuntimeValue::cells`. Member access uses
the identity to query the bytecode VM class catalog on demand, so metadata
values do not retain pointers into VM-private class tables.

This representation is platform-neutral C++20. It does not depend on Windows
APIs, pointer size, executable memory, or the native JIT backend, and therefore
uses the same code on Windows x64, Linux x64, and Linux AArch64.

## Visibility Rules

`properties` includes inherited properties that are not hidden and have public
`GetAccess`. `methods` includes inherited methods that are not hidden, are not
property accessors, and have public access. `events` includes inherited events
that are not hidden and have public `ListenAccess`.

The metadata lists are broader than those convenience functions. A class
`PropertyList` includes properties declared by the class plus inherited public
and protected properties. A `MethodList` includes the class's declared methods
plus inherited public and protected methods. `EventList` preserves inherited
event descriptors regardless of the display visibility filter.

## Example

Run the checked-in reflection demo with:

```powershell
build\mparser.exe --run-bytecode samples\class_metadata_demo.m
```

The demo creates a derived handle object and verifies:

- `?MetadataChild == metaclass(object)`
- `?MetadataChild < ?MetadataBase`
- inherited property, method, event, and superclass discovery
- hidden-member filtering in `properties`, `methods`, and `events`
- current and legacy metadata class names
- `Class.fromName` and method-form `metafunction`

With the inherited v0.68 handle methods and `ObjectBeingDestroyed` metadata,
the current final value is `summary = 18`.

## Validation

`class_metadata_smoke` covers class and object lookup, scalar class operators,
metadata member access, metadata-array indexing, current and legacy names,
visibility filtering, method introspection, read-only diagnostics, unknown
classes, runtime type identity, and metadata display.

`class_metadata_bytecode_cli_smoke` executes the complete sample. Both tests
are included in the portable Linux AArch64 QEMU CI selection in addition to
the normal Windows x64 and Linux x64 suites.

For a local Windows release check:

```powershell
cmake --build build --clean-first --parallel
ctest --test-dir build --output-on-failure
build\mparser.exe --run-bytecode samples\class_metadata_demo.m
```

Use one clean-first rebuild after changing public runtime headers or replacing
an older Ninja tree configured under a different MSVC environment.

## Remaining Boundary

- Full class reflection is currently authoritative in the bytecode VM. The HIR
  reference interpreter still does not construct or dispatch class objects.
- Metadata is built from the source graph loaded for the current compilation
  plus a small built-in catalog. It does not dynamically discover arbitrary
  installed MATLAB classes.
- Source comments are not yet retained as `Description` or
  `DetailedDescription`, and built-in member inventories are incomplete.
- Metadata arrays can be indexed, but full heterogeneous handle-array
  assignment, concatenation, and elementwise comparison semantics are not yet
  implemented.
- `methods(...,'-full')` reports that full descriptions are not implemented
  instead of silently returning simplified names.
- `metafunction` currently supports loaded class methods identified with
  `ClassName/MethodName`. Function, constructor, local-function, dotted static
  identifiers, `Arguments=`, `ArgumentTypes=`,
  `matlab.metadata.Function`, and complete `CallSignature` metadata remain
  future work.
- The original v0.63 boundary did not synthesize built-in handle lifecycle
  metadata. Current v0.68 execution adds `ObjectBeingDestroyed` and inherited
  handle methods; dynamic properties and property listeners arrived in v0.65
  and v0.66 respectively.
