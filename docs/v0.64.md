# MParser v0.64 Scope

MParser v0.64 makes loaded MATLAB function and method signatures available to
executable reflection code. It builds on the v0.63 class metadata model and
uses the same platform-neutral runtime descriptors on Windows x64, Linux x64,
and Linux AArch64.

## Milestone Contract

- Project and CLI version are `0.64.0`.
- `metafunction` resolves loaded ordinary functions, namespace functions,
  same-file local functions, explicit constructors, `Class/Method` methods,
  dotted static methods, and instance methods selected from argument values or
  argument class names.
- Function lookup returns `matlab.metadata.Function`; constructor and method
  lookup returns `matlab.metadata.Method`.
- Function descriptors expose `Name`, empty `Description` and
  `DetailedDescription`, the loaded source-unit `FullPath`, `NamespaceName`,
  and a typed `Signature`.
- Method descriptors expose the same typed `Signature` plus their loaded
  source-unit `FullPath`.
- `matlab.metadata.CallSignature` exposes row-shaped `Inputs` and `Outputs`
  arrays and reports whether input or output `arguments` blocks exist.
- `matlab.metadata.Argument` exposes its identifier, required/repeating and
  name-value flags, validation, default value, and class-derived name-value
  source class.
- Validation metadata exposes the declared class, fixed or unrestricted
  dimensions, validator names, and referenced argument identifiers.
- Default metadata exposes the retained source expression and referenced
  argument identifiers.
- `matlab.metadata.Namespace.FunctionList` returns the loaded non-local
  functions in that namespace.
- Reflection descriptors are read-only and share the v0.63 metadata equality,
  indexing, dimensions, `isa`, and display behavior.

## Metafunction Selection

The supported forms are:

```matlab
metafunction("ordinaryFunction")
metafunction("pkg.namespaceFunction")
metafunction("pkg.namespaceFunction>localFunction")
metafunction("ClassName")
metafunction("ClassName/methodName")
metafunction("ClassName.staticMethod")
metafunction("methodName", Arguments={object, value})
metafunction("methodName", ArgumentTypes={"ClassName", "double"})
```

`Arguments=` uses the same invocation normalizer and runtime validation service
as an actual function call. It understands positional defaults, repeating
inputs, modern and legacy name-value arguments, class validation, dimensions,
and validators without executing the selected function body.

`ArgumentTypes=` checks positional arity, receiver compatibility, declared
classes, and inheritance. MParser currently accepts a character vector or a
Cell array of character vectors because the runtime does not yet have a
distinct MATLAB string-array value.

When multiple loaded path functions reduce to the same public identifier,
lookup reports an ambiguity diagnostic instead of choosing one by map order.

## Runtime Representation

Each descriptor is an ordinary object-shaped `RuntimeValue` containing a
canonical `matlab.metadata.*` class and a stable textual identity. Function
identities refer back to the loaded function catalog. Signatures and their
child descriptors extend that identity with structural path components such
as input index, validator index, or dimension index.

Member access resolves the identity on demand. Metadata values therefore do
not retain raw pointers into VM maps, HIR nodes, source buffers, or executable
memory. The implementation is C++20 and is independent of SLJIT, Windows APIs,
pointer width, and host endianness.

Source-unit names and namespaces are copied into `SemanticResult`. This lets
function and method metadata retain their source ownership after syntax and
HIR lowering without coupling the runtime to the source loader.

## Example

Run the checked-in demo with:

```powershell
build\mparser.exe --run-bytecode samples\function_metadata_demo.m
```

The demo reflects a local function, its validated signature, a constructor, an
instance method, and a static method. It also selects the instance method from
argument class names. The final value is `summary = 17`.

## Validation

`function_metadata_smoke` compiles a multi-source graph and covers:

- ordinary, namespace, and local function identity
- function path and namespace ownership
- constructor, slash-form method, and dotted static lookup
- instance-method selection by `Arguments=` and `ArgumentTypes=`
- input/output block flags and row-shaped argument arrays
- required, repeating, and name-value classification
- validation classes, fixed and unrestricted dimensions, and validators
- default expressions and referenced argument identifiers
- class-derived name-value `SourceClass`
- namespace `FunctionList`, runtime type identity, display, and diagnostics

`function_metadata_bytecode_cli_smoke` executes the complete sample. Both
tests are part of the portable Linux AArch64 QEMU CI selection as well as the
normal Windows x64 and Linux x64 suites.

For a local Windows release check:

```powershell
cmake --build build --config Release --clean-first --parallel
ctest --test-dir build -C Release --output-on-failure
build\mparser.exe --version
build\mparser.exe --run-bytecode samples\function_metadata_demo.m
```

Use one clean-first rebuild after changing a public runtime or semantic header.
Mixing old and new MSVC objects after a public layout change can otherwise
produce an ABI mismatch rather than a source-level diagnostic.

## Remaining Boundary

- Function and signature reflection is authoritative in the bytecode VM. The
  HIR reference interpreter still does not construct metadata or class
  objects.
- The callable catalog contains loaded user functions and methods. A built-in
  MATLAB function signature catalog is not implemented yet.
- `FullPath` is the loaded source-unit name. It is absolute only when the
  source loader supplied an absolute path.
- Source comments are not retained as `Description` or
  `DetailedDescription`.
- `ArgumentValidator.Function` and
  `DefaultArgumentValue.evaluate` are not implemented.
- Validator reflection records statically referenced declared arguments. It
  does not yet expose arbitrary function handles or reproduce every MATLAB
  parser edge case inside validator expressions.
- Fixed dimension lengths use the runtime's scalar double representation
  rather than a distinct `uint64` value.
- Metadata handle arrays support read-only indexing and comparison, but not
  full heterogeneous concatenation, assignment, lifecycle events, or listener
  behavior.
- Implicit constructors without a declared constructor do not yet produce a
  method descriptor.
