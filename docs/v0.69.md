# MParser v0.69 Scope

MParser v0.69 makes ordered scalar MATLAB structures a first-class runtime
contract. The milestone connects the existing dynamic-member syntax to HIR,
bytecode, both baseline engines, ordered `RuntimeValue` storage, common field
builtins, diagnostics, a production sample, and ARM-focused CI. It does not
represent a scalar structure as a partial stand-in for a structure array.

## Major Capability

- `struct()` creates an empty 1-by-1 structure.
- `struct(field1, value1, ..., fieldN, valueN)` creates an ordered scalar
  structure from character-vector or string-scalar field names.
- A scalar Cell constructor value is unwrapped as MATLAB does. A nonscalar or
  empty Cell is diagnosed because it would create a structure array, which is
  outside this milestone.
- `s.field` and `s.(expression)` read and write fields in the HIR interpreter
  and bytecode VM. The dynamic expression must return a character vector or
  string scalar containing a valid MATLAB field identifier.
- `s.field = value` and `s.(name) = value` create `s` as an empty scalar
  structure when the direct variable does not yet exist.
- Dynamic member names use the same bytecode member path for class objects, so
  declared and runtime-added object properties retain their normal access,
  validation, listener, and setter behavior.
- `fieldnames`, `isfield`, `rmfield`, and `isstruct` are executable in both
  baseline engines. `isfield` accepts a scalar name or a Cell of names and
  preserves the name collection shape; non-structure first inputs return
  logical false.

## Ordered Representation

`RuntimeValue::fields` remains a `std::map` for deterministic lookup and value
ownership. A separate `fieldOrder` vector records definition order. New fields
append once, overwriting an existing field leaves its position unchanged, and
`rmfield` removes the name from both representations. A compatibility helper
reconstructs deterministic order for older externally created values that have
a field map but no order metadata.

Name-value argument roots now use the same field insertion helper. This keeps
their observable order compatible with ordinary structures and prevents a
second hidden structure representation from developing before the v0.80
builtin-registry work.

## Builtin Contract

The shared `runtime_struct` module owns pure scalar-structure operations and
returns a value-or-error result. The HIR interpreter and bytecode VM add their
own source spans and execution-tier diagnostic prefixes, but do not duplicate
constructor, ordering, query, or removal semantics.

Constructor diagnostics cover odd argument counts, nontext field names,
invalid identifiers, duplicate fields, and Cell values that require structure
arrays. Dynamic access diagnoses nontext or invalid field names before member
lookup. `rmfield` validates every requested name before modifying the copy, so
a failing multi-field removal cannot return a partially modified value.

## Example

Run the production sample with:

```powershell
build\mparser.exe --run samples\struct_runtime_demo.m
```

Expected result:

```text
summary = 2193
```

The sample verifies pair construction, constructor order, static and dynamic
assignment, implicit structure creation, scalar-Cell unwrapping, dynamic read,
Cell-shaped `isfield`, non-structure `isfield`, copy-preserving `rmfield`, and
`isstruct`. The same sample runs under `--run-hir` and `--run-bytecode`.

## Validation

The dedicated `struct_runtime_smoke` test executes one source through the HIR
interpreter and bytecode VM and compares values, logical shape/class, field
order, display order, source-copy preservation, and diagnostics. A bytecode-
only class fixture verifies dynamic property reads and writes. Separate CLI
tests cover HIR, baseline bytecode, and production `--run` entry points.

Configure and validate a native-JIT build:

```powershell
cmake -S . -B build -DMPARSER_ENABLE_NATIVE_JIT=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Repeat with `MPARSER_ENABLE_NATIVE_JIT=OFF` for the portable-only build. Scalar
structure storage contains no native pointers and is never required to enter a
typed region; legal structure code remains on the bytecode VM when a region is
not eligible. Linux AArch64 QEMU CI runs the focused structure test and
production sample in native-JIT and portable-only builds.

The Windows x64 Release validation passed `121/121` tests with native JIT
enabled and `115/115` tests with it disabled.

## Current Boundary

- Only 1-by-1 structures are represented. Structure arrays, `struct([])`,
  nonscalar Cell-driven construction, structure indexing, and comma-separated
  field lists are not supported.
- `struct(obj)`, `getfield`, `setfield`, `orderfields`, `struct2cell`, and
  `cell2struct` are not implemented yet.
- Direct member writes are supported. Nested value writes such as
  `s.inner.value = x` still require a general copy-back lvalue path; nested
  reads already work.
- Runtime text values currently combine MATLAB character vectors and string
  scalars. String arrays are not represented separately.
- Field names use the traditional 63-character MATLAB identifier boundary.

These boundaries will become explicit entries in the v0.70 compatibility
matrix rather than expanding implicitly.
