# MParser v0.71 Scope

MParser v0.71 closes the first framework-sensitive language gap identified by
the v0.70 compatibility audit: MATLAB-style structure arrays and
comma-separated field results. The milestone establishes one canonical
structure representation and one shared list-expansion contract across the HIR
interpreter, bytecode VM, and production `--run` interface. Typed and native
regions remain conservative and fall back to the VM for these dynamic values.

## Canonical Structure Runtime

Every structure is now represented as an array, including a scalar structure:

- `RuntimeValue::structElements` stores one field map per array element.
- `fieldOrder` defines the common schema and stable display/query order.
- runtime dimensions define the N-dimensional array shape.
- a scalar structure has shape 1-by-1 and one element.
- an empty typed structure may have zero elements while retaining its schema.

MATLAB-visible traversal remains column-major. The C++ payload follows the
runtime's existing storage convention, and all visible linear indices pass
through shared coordinate/offset conversion helpers. Scalar structure APIs
therefore use the same storage and schema rules as indexed arrays instead of a
parallel special case.

## Construction And Indexing

`struct(name, value, ...)` accepts scalar values and Cell field values. A
nonscalar Cell establishes the result shape; other nonscalar Cells must have
the same shape, and scalar values or scalar Cells broadcast to every element.
An empty Cell produces an empty typed structure, while `struct([])` produces an
empty structure without fields.

The shared runtime layer now supports:

- linear and multidimensional structure-array reads, including colon indices.
- selection-shape preservation and MATLAB column-major element order.
- whole-element assignment with matching field schemas.
- scalar right-hand expansion to multiple selected elements.
- common linear and multidimensional growth with schema-shaped empty gaps.
- linear deletion from vector structures.
- array-aware `fieldnames`, `isfield`, `rmfield`, and `isstruct` behavior.

Both baseline engines call the same helpers for construction, indexing,
assignment, deletion, schema checks, and field queries. This keeps diagnostics
and resulting shapes aligned between `--run-hir`, `--run-bytecode`, and
production `--run`.

## Comma-Separated Results

Reading a field from a nonscalar structure produces an internal
`CommaSeparatedList`. It is an evaluation result, not an ordinary value that
can be stored in a variable. Shared expansion rules apply it to:

- function and builtin argument lists.
- matrix and Cell literal elements.
- indexing argument lists.
- multiple assignment outputs.

Contexts that require exactly one value reject a list containing zero or more
than one value. Member access lowering carries the requested output count, so
`[left, right] = selected.value` behaves consistently in HIR and bytecode.

## Example

Run the production sample with:

```powershell
build\mparser.exe --run samples\struct_array_demo.m
```

Expected result:

```text
summary = 1760
```

The sample verifies Cell-driven construction, linear and multidimensional
selection, static and dynamic field-list packing, function-call and index-list
expansion, multiple outputs, whole-element replacement, scalar expansion,
multidimensional batch assignment, growth with empty-double field defaults,
deletion, empty typed structures, and field removal. The same source runs
through `--run-hir` and `--run-bytecode`.

## Validation

Configure and validate a native-JIT build:

```powershell
cmake -S . -B build -DMPARSER_ENABLE_NATIVE_JIT=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

Repeat with `MPARSER_ENABLE_NATIVE_JIT=OFF` for the portable-only build. The
focused `struct_runtime_smoke` executable compares HIR and bytecode values,
shapes, assignments, deletions, expansion contexts, and diagnostics. Three CLI
tests execute the runnable sample through the HIR, bytecode, and production
interfaces. Windows x64 Release validation passed `129/129` tests with native
JIT enabled and `123/123` tests with it disabled. The production sample
returned `summary = 1760` in both configurations.

Linux AArch64 QEMU CI includes the production structure-array sample in both
its native-JIT and portable-only focused suites. Full Windows x64 and Linux x64
jobs continue to execute the complete test suite; all three jobs are required
at the pushed-commit release gate.

## Current Boundary

- `S(index).field = value`, deeper chained index/member stores, and equivalent
  value-object updates require the v0.72 general root-and-path lvalue copy-back
  contract.
- Structure deletion currently accepts one linear subscript and vector-shaped
  targets. General N-dimensional null assignment remains open.
- Cell parenthesis indexing and vector brace selections do not yet emit
  comma-separated lists.
- Structure schema changes are scalar direct-member operations; bulk field
  assignment over selected arrays is part of the nested-lvalue work.
- Typed and native regions do not lower structure or comma-separated-list
  operations; legal code falls back to bytecode execution.

## Next Ordered Gaps

1. v0.72: general nested root-and-path lvalue resolution and transactional
   copy-back for arrays, Cells, structures, and value objects.
2. v0.73: complete exception stack arrays, cause chains, and propagation
   contracts.
3. v0.74-v0.79: dynamic call/handle closure, text representation, object-array
   and reflection boundaries, and the `RuntimeValue` contract freeze.
4. v0.80: unified builtin registry and representative function migration.
