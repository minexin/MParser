# MParser v0.72 Scope

MParser v0.72 closes compatibility gap `G-LVALUE-001` with a shared,
transactional root-and-path assignment contract. Mixed member, parenthesis,
and brace paths no longer update only a detached leaf. The HIR interpreter and
bytecode VM now rebuild every copied parent and publish the root only after the
complete assignment succeeds.

This milestone extends the target MATLAB-like subset; it does not claim every
MATLAB subscripted-assignment edge. In particular, an intermediate selection
must produce one value, class execution remains VM-only, and dynamic path
operations deliberately fall back from typed/native regions.

## Shared Transaction

`runtime_lvalue` represents each path segment as one of:

- a static or dynamic member name;
- parenthesis subscripts plus colon metadata;
- brace subscripts selecting Cell contents.

Descent stores a detached parent and its evaluated segment. The final write is
then replayed from the leaf back to the root. This provides one implementation
for examples such as:

```matlab
root.inner.data(end) = 77;
root.items(3).(field_name) = 31;
root.cells{2}.value = 50;
root.grid(1, 2) = {33};
```

Dynamic names and subscript expressions are evaluated once. `end` uses the
shape of the current path value, not the original root. A failed leaf write or
reverse copy-back does not publish a partially modified value root. VM
try/catch recovery also restores the lvalue and index-context stack depths.

## Container Semantics

The transaction delegates actual storage work to shared runtime layers:

- `runtime_index` provides common numeric reads and existing numeric mutation.
- `runtime_cell` implements Cell `()` selection, `{}` content selection,
  subset/content assignment, common growth, and linear vector deletion.
- `runtime_struct` provides indexed intermediate growth and schema alignment
  when a nested assignment introduces a field.

Structure growth creates schema-shaped empty gaps. Assigning a new field to
one selected structure element appends that field to the common structure
schema and gives untouched elements empty-double values. A missing path can
infer an empty numeric array, Cell, or structure from the remaining segments,
which permits paths such as `root.created(3).value = 6` and
`root.more_cells{3}.value = 12`.

## Bytecode And Objects

Direct one-segment indexed stores still lower to `StoreIndex`; this preserves
the established typed/native scalar-loop recognition path. Multi-segment
targets use:

- `BeginLvalue` and `BeginLvalueIndexContext`;
- `LvalueDescendMember`, `LvalueDescendIndex`, and
  `LvalueDescendBrace`;
- `StorePathMember`, `StorePathIndex`, or `StorePathBrace`.

The VM connects object segments to its existing property getter/setter path,
including access checks, validation, dependent accessors, and observable
events. Scalar value objects are copied back through their owner, while handle
aliases continue to observe shared identity. The HIR reference interpreter
does not execute classdef objects, so object behavior is validated through the
bytecode/production tier.

All new path instructions are explicitly ineligible for typed/native region
execution. Legal scripts execute in the VM rather than being rejected because
an optimization backend cannot lower the dynamic operation.

## Examples

Run the cross-engine container sample:

```powershell
build\mparser.exe --run-hir samples\lvalue_copyback_demo.m
build\mparser.exe --run-bytecode samples\lvalue_copyback_demo.m
build\mparser.exe --run samples\lvalue_copyback_demo.m
```

Each mode prints:

```text
summary = 572
```

Run the VM object copy-back sample:

```powershell
build\mparser.exe --run samples\lvalue_object_demo.m
```

Expected result:

```text
summary = 839
```

## Validation

The focused `lvalue_runtime_smoke` test compares HIR and bytecode results,
asserts all path opcode families are emitted, and checks rollback, `end`,
dynamic fields, numeric deletion, Cell selection/mutation/deletion, structure
growth/schema extension, missing-path inference, and VM value/handle object
copy-back. Four CLI tests execute the two runnable samples through their
supported interfaces.

Use the native and portable-only release gates:

```powershell
cmake -S . -B build -DMPARSER_ENABLE_NATIVE_JIT=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit --config Release --parallel
ctest --test-dir build-nojit -C Release --output-on-failure
```

Linux AArch64 QEMU CI includes the lvalue runtime and production/object samples
in both native-JIT and portable-only focused suites. Windows x64 and Linux x64
jobs run the complete test registry.

The local Windows x64 release gates passed `134/134` tests with native JIT
enabled and `128/128` tests with native JIT disabled. The portable-only
executables also produced `summary = 572` and `summary = 839` for the two
milestone samples.

## Current Boundary

- Intermediate path selections must resolve to one value. MATLAB bulk field
  distribution over nonscalar intermediate values is not implied.
- Direct multi-output Cell brace expressions do not yet carry requested output
  arity through every bytecode lowering context.
- General N-dimensional Cell/structure null assignment remains narrower than
  numeric-array deletion.
- Object arrays and heterogeneous arrays remain assigned to the v0.76 gate.
- User property setters and handle-object writes may have observable side
  effects; the value-root transaction does not roll back arbitrary user code.
- Typed/native optimization does not lower dynamic path operations.

## Next Ordered Gaps

1. v0.73: full exception stack arrays, cause chains, warning/assert, and stable
   propagation contracts.
2. v0.74: dynamic call/index resolution and function-handle conversion rules.
3. v0.75-v0.79: text, object-array/reflection, workspace, and RuntimeValue
   contract closure before the builtin registry migration.
4. v0.80: unified builtin descriptors, call/result contracts, and
   representative family migration.
