# MParser v0.73 Scope

MParser v0.73 closes compatibility gap `G-EXC-001` by turning exception and
warning behavior into a shared, embedding-visible contract. The HIR reference
interpreter and bytecode VM now expose the same severity, identifier, message,
source stack, and recursive cause data. A warning is observable without being
treated as a failed run.

This milestone implements the declared MATLAB-like exception subset. It does
not claim MATLAB correction objects, byte-for-byte MATLAB report formatting,
or process-global warning persistence.

## Diagnostic Contract

Public `Diagnostic` values carry:

- `Error` or `Warning` severity;
- a stable identifier and message;
- the primary `SourceSpan`;
- an innermost-first vector of `file`, `name`, and `line` frames;
- recursively nested causes.

Runtime errors and warnings are stored separately while execution is active.
This prevents warnings from triggering `catch`, terminating a VM stream,
blocking adaptive workspace publication, or failing a CLI command. They are
combined only when the public result is returned. Runtime consumers use
`hasErrorDiagnostics` when they need a success/failure decision.

Call frames are captured at central invocation boundaries and therefore cross
local, path, private, package, class-method, function-handle, and source-graph
calls without encoding stack behavior into individual builtins. Uncaught
diagnostics returned from `CompiledModule::invoke` retain the same frames as a
caught `MException.stack` value.

## MException

`MException.stack` is an N-by-1 structure array with `file`, `name`, and
`line` fields.

The public structure array is also the canonical frame store. Embedding and
runtime code do not synchronize a second hidden stack representation.

The stack policies are explicit:

- `throw` replaces the stack at the current throw site;
- `rethrow` preserves the previously captured stack;
- `throwAsCaller` replaces the stack and removes its own frame.

`addCause` returns a value copy with the cause appended to the column Cell.
Diagnostic conversion preserves nested causes in both directions. `getReport`
supports MParser-defined `basic` and `extended` text; the optional
`"hyperlinks", "default"|"on"|"off"` pair is validated but does not add
terminal hyperlinks.

The public `Correction` property is a Missing placeholder. `addCorrection`
raises `MParser:UnsupportedExceptionCorrection`. This is a stable compatibility
boundary until a correction object model can be implemented without inventing
partial semantics.

## Warning And Assert

`warning` supports message emission, identifier-specific and global
`on`/`off`/`query`, `last`, `backtrace`, `verbose`, and setting-structure
save/restore within one runtime invocation. Suppressed warnings still update
`lastwarn`. `lastwarn` gets or sets the message and optional identifier with up
to two outputs.

`assert` accepts the shared numeric/logical truth contract. A false condition
raises `MParser:AssertionFailed` with `Assertion failed.` by default, or uses a
caller-provided identifier, format, and replacement values. Assertions are
ordinary catchable exceptions.

Standalone HIR calls now request zero outputs, matching bytecode lowering.
This fixes no-output local functions and context builtins such as `warning`
without changing assignment or output-list call arity.

## Example

Run the diagnostics sample through every baseline interface:

```powershell
build\mparser.exe --run-hir samples\exception_diagnostics_demo.m
build\mparser.exe --run-bytecode samples\exception_diagnostics_demo.m
build\mparser.exe --run samples\exception_diagnostics_demo.m
```

Each mode emits the nonfatal warning `MParserDemo:Notice`, exits successfully,
and reports:

```text
summary = 111111
```

The earlier `samples/exception_runtime_demo.m` remains a checked compatibility
sample for creation, catch inspection, explicit throw, and rethrow.

## Validation

`exception_runtime_smoke` runs the same fixtures through HIR and bytecode and
checks full stack order, source lines, cause Cells, reports, all three throw
policies, warning suppression/save/restore, `lastwarn`, assert, severity, and
the correction boundary. `exception_source_graph_smoke` creates three `.m`
files and verifies cross-file stack data through both `CompiledModule::invoke`
and the HIR interpreter. Eight focused exception/CLI tests cover both samples.

Use the native and portable-only release gates:

```powershell
cmake -S . -B build -DMPARSER_ENABLE_NATIVE_JIT=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit --config Release --parallel
ctest --test-dir build-nojit -C Release --output-on-failure
```

Linux AArch64 QEMU CI includes `exception_runtime_smoke`,
`exception_source_graph_smoke`, and the production diagnostics sample in both
native-JIT and portable-only focused suites. Windows x64 and Linux x64 run the
complete registry.

The local Windows x64 release gates passed `138/138` tests with native JIT
enabled and `132/132` tests in the portable-only build. The production
diagnostics sample completed successfully in both builds with
`summary = 111111`.

## Current Boundary

- Correction objects and correction suggestions are unsupported.
- Warning settings and `lastwarn` reset for each runtime invocation; a future
  persistent workspace/context contract may provide longer lifetime.
- Extended report text is stable MParser output, not byte-identical MATLAB
  display text, and hyperlinks are not emitted.
- `backtrace` and `verbose` settings are retained but human display policy is
  intentionally narrower than MATLAB's Command Window behavior.
- Typed/native regions do not lower exception or warning control flow; legal
  code falls back to the bytecode VM.
