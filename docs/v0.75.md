# MParser v0.75 Scope

MParser v0.75 closes compatibility gap `G-TEXT-001` by separating MATLAB-like
character arrays from string arrays throughout the runtime. It replaces the
former shared scalar text payload with explicit UTF-16 storage, one shared text
operation layer, and differential behavior across the HIR interpreter,
bytecode VM, production runner, class-property validation, and CLI display.

This milestone stabilizes the representation and engine rules needed by later
builtins. It does not attempt to complete MATLAB's full text function library,
Unicode normalization, locale-sensitive collation, or optimized text lowering.

## Runtime Value Contract

`RuntimeValue` now lives in `runtime_value.h`, independent of either execution
engine. Its two text kinds are:

- `CharacterArray`: one rectangular array whose elements are UTF-16 code units;
- `StringArray`: one shaped array of variable-length UTF-16 strings, each with
  an explicit missing-state bit.

Single quotes create character arrays and double quotes create string arrays.
Consequently, `'abc'` has shape 1-by-3 while `"abc"` is a 1-by-1 string scalar.
The empty character literal `''` is 0-by-0, while the empty string `""` remains
1-by-1. `numel` measures character code units for char arrays and string
elements for string arrays. `strlength` measures the UTF-16 code units inside
each text value, matching MATLAB behavior for supplementary characters.

Source and user-facing boundaries use explicit UTF-8/UTF-16 conversion with
replacement behavior for malformed sequences. The implementation does not use
`wchar_t`, platform code pages, or locale-dependent conversion, so Windows,
Linux x64, and Linux AArch64 share the same payload contract.

## Shared Text Semantics

`runtime_text` is the common implementation used by both baseline engines. It
provides:

- MATLAB-visible column-major `()` indexing for char and string arrays;
- string `{}` content extraction and assignment;
- indexed scalar expansion, growth, deletion, logical masks, colon, and `end`;
- row/column/N-dimensional concatenation and char-to-string promotion;
- string `+` append and comparison with general implicit expansion;
- character relational operators and `strcmp`/`strcmpi` text comparison;
- transpose, `reshape`, `permute`, `ipermute`, `squeeze`, `repmat`, `cat`,
  `horzcat`, and `vertcat` through the common array layer;
- `char`, `string`, `strings`, `cellstr`, `strlength`, `double(char)`,
  `ischar`, `isstring`, `isStringScalar`, and `ismissing`;
- distinct `class`/`isa`, runtime metadata, argument conversion, diagnostics,
  exception/warning fields, dynamic function names, and CLI formatting.

Logical and numeric results are constructed from column-major logical order
before mapping to the runtime's row-major physical payload. This keeps matrix
positions stable for comparisons, `strlength`, and `double(char)`, including
implicit expansion between row and column string arrays.

Numeric `char` conversion truncates toward zero, clamps finite values to the
UTF-16 range, and maps `NaN` to a blank. String-array growth fills new elements
with missing strings, while character growth fills with spaces.

## Class And Optimization Integration

Validated `char` and `string` properties can retain or infer fixed and wildcard
dimensions, reshape equal-element-count assignments in MATLAB column-major
order, and use the existing text and shape validators. This protects classdef
code from depending on the removed scalar text representation.

Typed and native regions treat text as an unsupported optimized value kind and
fall back before executing the region. Legal scripts therefore remain correct
in the bytecode VM with native JIT enabled or completely absent. Cache keys and
native code contain no text payload address or platform string representation.

## Example

Run the text sample through every public execution interface:

```powershell
build\mparser.exe --run-hir samples\text_runtime_demo.m
build\mparser.exe --run-bytecode samples\text_runtime_demo.m
build\mparser.exe --run samples\text_runtime_demo.m
```

Each mode reports:

```text
summary = 36
```

The sample covers quote and empty distinctions, UTF-16 supplementary code
units, type predicates, char and string indexing/mutation, growth/deletion,
brace contents, concatenation, implicit expansion, storage layout,
numeric/text conversion, missing strings, transforms, and Cell conversion.

## Validation

`text_runtime_smoke` parses and lowers the sample once, runs it through HIR and
bytecode, and checks both workspaces. It verifies runtime kinds and dimensions,
Unicode supplementary-pair storage, UTF-8 round trips, string growth/deletion,
and the 36 semantic assertions. Three CLI tests independently protect
`--run-hir`, `--run-bytecode`, and production `--run`.

`property_validation_smoke` adds fixed-shape char and string properties and
checks equal-element-count reshaping. The existing exception, warning,
metadata, function-handle, structure, argument-validation, lvalue, array,
benchmark, typed, adaptive, and embedding tests protect every migrated text
consumer.

Use the release gates:

```powershell
cmake -S . -B build -DMPARSER_ENABLE_NATIVE_JIT=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit --config Release --parallel
ctest --test-dir build-nojit -C Release --output-on-failure
```

The local Windows x64 Release gates pass `146/146` tests with native JIT and
`140/140` in a clean portable-only build. Linux x64 runs the complete registry.
Linux AArch64 QEMU now includes `text_runtime_smoke`, the production text
sample, and compatibility-matrix validation in both native and portable
focused suites.

## Current Boundary

- `strcmpi` currently performs deterministic ASCII case folding; full Unicode
  case conversion, normalization, locale collation, and grapheme algorithms
  are not implemented.
- The long-tail MATLAB text library, regex family, categorical/table text,
  datetime conversion, and multi-input `char` padding remain future work.
- Missing strings are represented and observable through `ismissing`, but a
  complete general missing-value constructor/conversion family is not present.
- Typed/native JIT does not lower text operations and intentionally falls back.
- RuntimeValue remains a C++ internal contract; the stable external array/text
  ownership ABI belongs to the v0.90 embedding stage.
