# MParser v0.76 Scope

MParser v0.76 closes compatibility gap `G-CLASS-001` with a shared runtime
contract for MATLAB-like value, handle, and heterogeneous object arrays. The
milestone extends the existing scalar class VM without replacing its class
tables, call frames, property validation, lvalue transaction, or guarded JIT
fallback path.

This is an object-array foundation, not a claim that every MATLAB object
protocol is complete. The supported behavior and remaining differences are
recorded in the machine-validated compatibility matrix.

## Runtime Storage Contract

`RuntimeValue` retains the existing scalar-object representation and adds an
`objectElements` payload for nonscalar arrays. The rules are:

- a scalar class object remains a direct field map or shared handle field map;
- a nonscalar array stores scalar object values in row-major physical order;
- all visible indexing uses MATLAB column-major logical coordinates;
- an empty object array has no placeholder elements but retains its class,
  handle/value category, and complete dimensions;
- metadata descriptors and `MException` values remain outside the class-object
  array path.

`runtime_object` owns object element access, class-compatible construction,
indexing, assignment, growth, deletion, concatenation, equality, and
elementwise comparison. `runtime_index` now supplies the same resolved
selection plan to numeric, text, and object operations, avoiding a third copy
of colon, vector, logical-mask, and result-shape rules.

## Array Semantics

The bytecode VM supports:

- linear, vector, logical, multidimensional, empty, and repeated-subscript
  indexing in logical order;
- scalar-expanded and element-count-compatible indexed assignment;
- transactional growth through a zero-argument/defaulted class constructor;
- linear vector deletion and one-dimension-at-a-time slice deletion;
- horizontal, vertical, and general-dimensional concatenation;
- transpose, `reshape`, `permute`, `ipermute`, `squeeze`, `repmat`, and `cat`;
- object-aware `size`, `numel`, `class`, `isa`, `metaclass`, display, `isequal`,
  and elementwise `==`/`~=` with scalar expansion.

Value-object elements are copied when an array or selection is copied. A nested
write such as `copy(1).Value = 9` commits the modified scalar through the shared
lvalue path and leaves the original value array unchanged. Handle selections
retain their shared identity. Growth creates distinct default handle elements,
and any constructor, shape, class, or assignment failure leaves the target
array unchanged.

Property access on a nonscalar array returns a comma-separated list in logical
order, so `[objects.Value]` collects the values. A method reference retains the
whole array as its receiver, allowing vectorized methods such as
`objects.total()`. MATLAB does not broadcast a simple
`objects.Value = value` assignment; MParser now diagnoses that form and
requires explicit scalar element indexing.

## Heterogeneous Classes

`matlab.mixin.Heterogeneous` is recognized as a non-executable built-in
superclass. The VM propagates one heterogeneous root through each legal class
hierarchy and rejects classes that combine distinct roots.

Concatenation and indexed assignment resolve the most-specific common user
superclass for elements from one heterogeneous hierarchy. Selecting or deleting
elements can narrow the visible array class again. Ordinary unlike classes and
mixed value/handle categories remain deterministic diagnostics instead of
being silently coerced.

## Handle Lifetime

`isvalid` returns a logical array with the same shape as a handle array.
`delete` walks elements in logical order, invalidates an identity before
callbacks and destructors, runs derived-to-base destructors, and skips a
repeated alias after the first destruction. Existing event-listener and dynamic
property cleanup remains attached to the scalar handle identity.

Array copies and transforms preserve aliases. Default-filled growth creates
independent handles for the missing positions. Reachability-based automatic
destruction and cyclic collection are not part of this milestone; explicit
`delete` remains the stable lifecycle boundary.

## Optimization Boundary

Object arrays are legal VM values but are not typed/native operands. Typed
regions accept only their declared supported double scalar or dense linear
array inputs. An object input therefore fails a guard or executor input check
before any optimized mutation, and execution resumes in the bytecode VM.

No object payload address, field map, class-table pointer, or handle identity is
placed in SLJIT code or a native cache key. Native-enabled and portable-only
builds consequently share the same object behavior.

## Example

Run the checked object-array sample through the baseline bytecode VM or the
production interface:

```powershell
build\mparser.exe --run-bytecode samples\object_array_demo.m
build\mparser.exe --run samples\object_array_demo.m
```

Both commands report:

```text
summary = 14
```

The sample covers default-filled value growth, property lists, whole-array
method dispatch, value-copy isolation, N-dimensional layout and transforms,
slice deletion, handle aliasing and validity, explicit destruction, and
heterogeneous common-class resolution and narrowing.

## Validation

`object_array_runtime_smoke` directly verifies physical/logical layout, empty
and logical selection, repeated-index ordering, N-dimensional access,
transactional assignment and failed growth, value copies, handle aliases,
independent defaults, heterogeneous resolution, deletion, and metadata
isolation.

`object_array_vm_smoke` parses and lowers complete class definitions and covers
property comma-separated lists, array methods, nested copy-back, transforms,
slice deletion, handle comparison and lifecycle arrays, `isequal`, ordinary
mixed-class rejection, default-constructor rollback, and nonscalar property
assignment rejection. Two CLI gates execute the sample through
`--run-bytecode` and production `--run`.

The Windows x64 native release suite passes 150/150 tests, and the clean
portable-only release suite passes 144/144 tests. Both retain the existing
class, inheritance, property, listener, metadata, lvalue, array, benchmark,
typed, adaptive, embedding, and compatibility-matrix regressions. Linux
AArch64 QEMU focuses object runtime/VM tests and the production sample in both
JIT-enabled and portable configurations.

## Current Boundary

- HIR parses and analyzes class syntax but does not execute class objects;
  production execution uses the bytecode VM and guarded JIT fallback.
- MParser invokes the default constructor independently for each missing growth
  element. MATLAB can call it once and copy the resulting default state, so
  constructor side-effect counts and random defaults can differ.
- Heterogeneous `getDefaultScalarElement` and `convertObject` hooks are not yet
  implemented. Growth currently requires the visible array class itself to be
  constructible with no arguments.
- Ordinary unlike classes are rejected. MATLAB class-dominance conversion and
  user `horzcat`/`vertcat`/`cat`, `subsref`, and `subsasgn` overrides remain
  future dispatch work.
- Direct nonscalar property assignment is rejected; general comma-separated
  assignment-list distribution is not yet implemented.
- Value-object structural `==`/`~=` is an MParser subset convenience; complete
  user overload dispatch remains outside this milestone.
- Automatic handle destruction, cyclic collection, full listener-array
  operations, and external object ownership ABI are later gates.

## Next Ordered Gaps

1. v0.77: freeze the supported `meta.*` graph, reflection access, dynamic
   dispatch hooks, and explicit unsupported metadata members.
2. v0.78-v0.79: close workspace/state and remaining `RuntimeValue`, call-frame,
   ownership, and output-arity contracts before registry migration.
3. v0.80: land unified builtin descriptors, call/result/error contracts,
   extension-author rules, and representative function-family migration.
