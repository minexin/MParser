# MParser v0.77 Scope

MParser v0.77 closes compatibility gap `G-REFLECT-001` by freezing one
documented reflection contract for the supported MATLAB-like subset. Metadata
class names, legacy aliases, direct inheritance, class flags, public members,
runtime `isa`, `properties`, `methods`, and VM member dispatch now derive from
the same `RuntimeMetadataTypeDescriptor` table.

This milestone does not claim the complete MATLAB metadata API. It makes the
implemented graph stable, tests its dynamic behavior, and turns every
remaining omission listed below into an explicit compatibility boundary.

The class-related descriptors through `Function` retain the MATLAB
`MetaData`/handle relationship. The R2026a function-signature support
descriptors, property-validation descriptors, and dimension descriptors do
not claim that relationship merely because the runtime stores them in an
object-shaped `RuntimeValue`. `isa` follows the table instead of the storage
representation.

## Supported Members

The runtime schema declares these read-only query surfaces:

| Descriptor | Supported properties or methods |
| --- | --- |
| `Class` | `Name`, descriptions, class flags, `InferiorClasses`, `Namespace`, `Aliases`, member lists, `SuperclassList`; `fromName` and class relation operators |
| `Property` | names/descriptions, access and behavior flags, default fields, `Validation`, accessor placeholders, `DefiningClass` |
| `DynamicProperty` | inherited `Property` fields plus mutable supported attributes, `delete`, and `isvalid` |
| `Method` | name/descriptions, access/static/abstract/sealed/hidden flags, inputs, outputs, signature, path, defining class |
| `Event` | name/descriptions, hidden/listen/notify access, defining class |
| `EnumerationMember` | name/descriptions, hidden flag, defining class |
| `Namespace` | name/descriptions, class/function/inner-namespace lists, outer namespace |
| `Function` | name/descriptions, path, namespace name, signature |
| `CallSignature` | inputs, outputs, input/output validation-block flags |
| `Argument` | identifier, descriptions, required/repeating/name-value flags, validation, default, source class |
| `ArgumentIdentifier` | name and group name |
| `ArgumentValidation` | class, size, and structured validator descriptors |
| `ArgumentValidator` | name, function placeholder, referenced arguments |
| `DefaultArgumentValue` | expression and referenced arguments |

`properties`, `methods`, `isprop`, `ismethod`, `class`, `isa`, `metaclass`,
`?ClassName`, `matlab.metadata.Class.fromName`, and their documented legacy
names consume this schema. String values now participate in built-in
metaclass lookup as class `string`.

## Query And Array Semantics

Metadata lists remain object arrays with MATLAB-visible logical order.
Accessing a property on a nonscalar list produces a comma-separated list, so
an output list can project all names directly:

```matlab
[firstName, secondName] = classInfo.PropertyList.Name;
```

`findobj(source, name, value, ...)` supports one or more direct
property-name/value pairs joined with AND for metadata arrays and handle
object arrays. It preserves descriptor or handle identity, returns an empty
typed array for no matches, a scalar for one match, and a column array for
multiple matches. Metadata queries see inherited public/protected members,
exclude inherited fully private members, and can inspect private members
through their declaring class metadata. Static method state is reported by
the selected `Method.Static` field.

Unsupported fields produce stable metadata-specific diagnostics. Metadata
methods that require a scalar descriptor reject nonscalar arrays explicitly.

## Property Validation

`matlab.metadata.Property.Validation` now returns:

- an empty 0-by-0 `PropertyValidation` array when no class, size, or function
  restriction exists;
- otherwise, a scalar descriptor whose `Class` and `Size` fields reuse the
  same parsed `PropertySpec` as actual property assignment;
- a 1-by-N Cell array of callable validation-function handles;
- `isValidValue(value)`, which runs the complete assignment validation path,
  discards the probe diagnostic, and returns a logical result;
- `validateValue(value)`, which produces no output and raises the same
  property-validation diagnostic as assignment.

Validation-function handles invoke the individual validator represented by
their Cell entry. They are bound to the owning `CompiledModule`, so they can be
reused across invocations of that module but are rejected by a different
module instead of resolving an equal-looking class name accidentally.

Dynamic-property descriptors now match the frozen contract by defaulting
`NonCopyable` to true and returning empty `Validation` metadata. Their existing
`WeakHandle` support remains part of the MParser subset.

## Optimization Boundary

Metadata values, descriptor arrays, comma-separated projections, dynamic
queries, and validation methods execute in the bytecode VM. Typed and native
regions do not embed class-table pointers, metadata identities, property
specifications, or validation handles. A legal script that reaches reflection
therefore follows the existing guarded fallback path.

The HIR interpreter still parses and analyzes class syntax but does not execute
class objects or reflection. Production `--run` uses the bytecode VM behind the
stable CLI and remains the user-facing execution path.

## Example

Run the checked sample through the baseline VM or production interface:

```powershell
build\mparser.exe --run-bytecode samples\reflection_contract_demo.m
build\mparser.exe --run samples\reflection_contract_demo.m
```

Both commands report:

```text
summary = 22
```

The sample covers metadata-array projection, direct `findobj` selection,
static method metadata, modern and legacy validation names, size descriptors,
callable validators, value probing, dynamic-property defaults, direct handle
filtering, and string metaclass lookup.

## Validation

`reflection_contract_smoke` verifies the schema directly and then parses,
lowers, and executes complete class definitions. It covers canonical and
legacy names, nuanced `MetaData`/handle inheritance, namespace flags,
inherited and private-owner property queries, static methods, one- and
multi-result `findobj`, logical-order projections, supported and unsupported
members, property-validation aliases, size descriptors, valid/invalid probes,
catchable validation errors, callable validator handles, same-module reuse,
cross-module rejection, dynamic-property defaults, and string reflection.

The bytecode and production CLI tests execute
`samples/reflection_contract_demo.m`. The ARM64 workflow runs the focused test
and both sample gates in native-JIT and portable-only QEMU configurations.
The Windows x64 Release validation passed all 153 native-SLJIT tests and all
147 portable-only tests. The portable CLI also reported `MParser 0.77.0` and
completed the production sample with `summary = 22`.

## Explicit Boundaries

- Metadata constructors cannot be called directly.
- User class aliases and `InferiorClasses` are not populated.
- Source comments are not yet extracted into `Description` or
  `DetailedDescription`; those fields return empty character vectors.
- Reflected `GetMethod`, `SetMethod`, and `ArgumentValidator.Function` values
  remain placeholders.
- `findobj` does not yet implement recursive ordinary-handle graph traversal,
  depth flags, regular-expression matching, or every MATLAB search option.
- `Class` instance lifecycle events and every metadata event/listener behavior
  are not implemented.
- Metadata serialization and a stable external metadata ABI are future
  embedding work.
- The complete MATLAB metadata graph and release-specific long-tail members
  outside the table above are not implied.
- HIR class execution remains unsupported; typed/native tiers fall back to the
  VM.
