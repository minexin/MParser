# MParser v0.79 Scope

MParser v0.79 closes compatibility gap `G-RUNTIME-001` by freezing the
engine-facing runtime value, workspace, call-frame, and optimization-fallback
contracts needed by the v0.80 builtin extension layer.

This is an internal source-contract freeze. It deliberately does not freeze the
public C++ ABI, define the future narrow C ABI, introduce serialization, or
claim every MATLAB value class. Those external boundaries remain part of the
v0.90 embedding and v1.0 release gates.

## RuntimeValue Boundary

`runtime_value.h` is now independent of either execution engine and owns:

- `RuntimeValue`, `RuntimeFunctionHandle`, and `RuntimeWorkspace`;
- shared factories for Missing, double/logical scalar, vector, matrix, Cell,
  scalar structure, name-value transport, callable context, and function
  handle values;
- runtime kind and ownership names;
- the storable-value rule;
- function-handle text and metadata projection;
- runtime display formatting;
- recursive invariant validation.

Runtime utility headers include the value and diagnostic contracts they
actually use instead of importing `interpreter.h` transitively. The reference
interpreter and bytecode VM therefore consume the same value layer, and the
v0.80 registry can do so without depending on either engine.

## Ownership Contract

`RuntimeValueOwnership` describes the copy and lifetime rule for each runtime
kind:

| Category | Runtime values | Contract |
| --- | --- | --- |
| `Immediate` | numeric/logical scalar | Payload is carried directly |
| `Value` | numeric arrays, text, Cell, structure, value object | Copy owns independent value containers; contained handles retain their own identity rules |
| `SharedHandle` | handle object | Copies alias one shared property store |
| `Callable` | function handle | Copies share one identity-bearing descriptor and callable context |
| `Transient` | Missing, comma-separated list, name-value argument | Internal transport value, not an ordinary stored workspace value |

Nested Cell, structure, and value-object containers copy their value payloads
without mutating their source. A handle or callable stored inside such a
container still retains its own shared identity. Handle-object copies retain
aliases. Function-handle copies retain identity; separately constructed
handles receive different identities. Module-bound handles continue to retain
their compiled callable context.

Handle property graphs and function captures may be recursive. Contract
validation tracks shared nodes and terminates on cycles; v0.79 does not add
automatic cycle collection or handle reachability destruction.

## Shape And Payload Invariants

Explicit dimensions are normalized to at least two dimensions, trailing
singleton dimensions beyond the second are removed, and their product is
checked for `size_t` overflow. When dimensions are explicit:

- `rows` and `columns` match the first two dimensions;
- numeric, character, string, Cell, and comma-separated-list payload counts
  match the element count;
- numbers and function handles are scalar;
- Missing is empty;
- structure elements share one ordered schema;
- object arrays contain scalar elements with consistent value/handle storage;
- module-backed function handles have a callable context and consistent
  identity.

`validateRuntimeValueContract` returns a path and explanatory error rather than
throwing. It is intended for tests, embedding guards, and extension
conformance checks. Existing runtime operations remain responsible for
MATLAB-specific type, indexing, conversion, and access policy.

The shared Cell factory also fixes an argument-evaluation-order bug discovered
during the clean MSVC rebuild: the element count is captured before moving the
payload, so a nonempty Cell cannot acquire a spurious 1-by-0 shape.

## Call-Frame Contract

The HIR interpreter and bytecode VM now use one `RuntimeCallFrame`:

- `Script` frames contain a workspace but no synthetic arity variables.
- `Function` and `AnonymousFunction` frames record callable identity, source
  span, supplied positional argument count, requested output count, workspace,
  `nargin`, and `nargout`.
- `Initializer` frames isolate class/property initialization without exposing
  function arity variables.

Entry functions, local functions, methods, anonymous functions, constructors,
and property initializers use these shared factories. Multiple outputs and
ignored outputs still follow the existing function signature contract; v0.79
removes duplicate per-engine arity initialization rather than changing the
language behavior.

## Structured Fallback

Human-readable fallback text remains available, but it is no longer the only
way to classify optimization behavior. `RuntimeFallbackKind` distinguishes:

- unavailable or non-closed regions;
- calls, unsupported mutation, control flow, or operations;
- invalid contracts, missing stack values, and unsupported runtime values;
- unsupported ranges, missing inputs, and unsupported inputs;
- typed-kernel rejection;
- backend unavailable/unsupported, native compilation failure, and runtime
  failure;
- adaptive retraining rejection.

The code is propagated through bytecode-region contracts,
`TypedRegionExecutionResult`, VM typed-region profiles, native fallback
metadata, and adaptive events. CLI JIT details print `fallbackKind=` and, when
automatic native execution falls back successfully to portable execution,
`nativeFallbackKind=`. The latter does not mark the overall portable execution
as failed.

This preserves the central JIT rule: optimization coverage or backend
availability never prevents legal target-subset code from continuing in the
bytecode VM.

## Example

Run the checked sample through all public execution modes:

```powershell
build\mparser.exe --run-hir samples\runtime_contract_demo.m
build\mparser.exe --run-bytecode samples\runtime_contract_demo.m
build\mparser.exe --run samples\runtime_contract_demo.m
```

Each command reports:

```text
summary = 11023
```

The sample uses a local function with three outputs, `nargin`, `nargout`, Cell
contents, structure fields, and deterministic output composition.

## Validation

`runtime_contract_smoke` covers:

- valid factory values across scalar, array, text, Cell, structure, object,
  transport, and function-handle kinds;
- normalized N-dimensional shape and payload invariants;
- malformed numeric, structure, function-handle, and handle-object values;
- deep Cell/structure/value-object copies and shared handle aliases;
- a cyclic handle graph;
- function-handle identity and ownership;
- script, function, and initializer frame arity rules;
- every stable fallback name;
- 2,048 invocations of one compiled persistent, multi-output function, with
  every returned and persistent value revalidated.

`bytecode_region_smoke`, `typed_region_executor_smoke`, and
`adaptive_bytecode_vm_smoke` assert machine fallback kinds at each layer.
Three CLI tests prove HIR, bytecode, and production parity for the sample.
The focused AArch64 native and portable workflow includes all of these runtime
contracts.

Windows x64 Release validation covers 161 native-SLJIT tests and 155
portable-only tests. The production sample reports `summary = 11023` in both
configurations, and the executable reports `MParser 0.79.0`.

## Explicit Boundaries

- The in-memory C++ struct layout and exported symbol ABI are not frozen.
- The narrow C ABI and versioned machine-readable result protocol are not yet
  implemented.
- RuntimeValue does not yet represent complex, sparse, table, categorical,
  GPU, or every MATLAB numeric class.
- Contract validation proves representation invariants, not every semantic
  rule or class access policy.
- Handle cycles are validated safely but not automatically collected.
- Textual fallback reasons remain explanatory; machine consumers should use
  the structured kind once the v0.90 protocol exposes it.
- Exception and source diagnostics keep their existing contract; host resource
  limits and exception containment remain v0.90 work.

## Next Ordered Gaps

1. v0.80: implement `BuiltinRegistry`, `BuiltinDescriptor`, and shared
   call/result/error structures over this runtime foundation.
2. Migrate representative math, reduction, scan, array, multi-output, and
   context functions, with HIR/VM/typed/native conformance tests.
3. Publish extension-author rules and a reusable conformance-test template.
4. v0.90: freeze embedding APIs, the narrow C ABI, resource boundaries, and
   versioned machine protocol.
