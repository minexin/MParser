# MParser v0.83

MParser v0.83 adds the first narrow C embedding ABI over the engine-neutral
execution and resource-control contracts completed in v0.81-v0.82. A pure C
host can now compile once, invoke statelessly or through a persistent session,
transport representative MATLAB-like values, inspect owned diagnostics and
execution summaries, cancel work, and release every resource without observing
C++ types or exceptions.

This milestone is a substantial v0.90 embedding step. It is ABI candidate 1,
not the final v1.0 ABI freeze, an installed SDK, or the machine-readable CLI
protocol.

## Public Boundary

`include/mparser/c_api.h` is a C11-compatible public header. It defines:

- `MPARSER_C_ABI_VERSION`;
- component-version and stable API-status queries;
- opaque module, session, result, value, cancellation, and diagnostic handles;
- versioned invocation-options and execution-summary structures;
- explicit retain/release functions;
- UTF-8 metadata and UTF-16 value views;
- scalar, array, text, Cell, and Struct constructors/accessors;
- object/function-handle inspection and module-ownership checks.

`mparser_c_api` builds a shared library named `mparser_c`. `mparser_core` and
the bundled SLJIT static target are position-independent where required, so
the same source graph links on Windows and ELF platforms.

The complete ownership, array-order, error, and threading rules are specified
in [embedding-c-api.md](embedding-c-api.md).

## Value And Lifetime Contract

External arrays use MATLAB column-major order regardless of internal storage.
Dimensions and constructor payloads are copied into immutable value handles.
Returned accessor views remain valid for the lifetime of their value handle.

Result output/variable getters and Cell/Struct element getters return owned
handles. Composite construction copies runtime values, so child handles may be
released immediately after construction.

Object values and module-defined handles retain their compiled module. They
remain callable after the producing result is released, but a preflight owner
guard rejects use with another module. Ownership propagates recursively
through Cells and Structs. Independent builtin handles remain portable between
modules.

## Execution And Failure Contract

Both module and session calls project the existing `ModuleInvocationRequest`
and `ModuleInvocationResult` model:

- explicit entry, arguments, output arity, initial workspace, and backend;
- owned outputs, result workspace, phase-aware diagnostics, and summary;
- instruction, wall-time, call-depth, array-payload, and diagnostic limits;
- cross-thread cooperative cancellation;
- automatic/portable/native guarded execution with mandatory VM fallback.

An API `OK` status means a result exists; language success remains explicit in
the result. Compilation failure returns an inspectable invalid module so the
host can read source-linked diagnostics. Host argument, owner, type, and ABI
errors fail before execution and do not return a result.

The C boundary catches every C++ exception. `std::bad_alloc` becomes the
allocation-failed API status rather than crossing the ABI.

## Runnable C Host

Build and run:

```powershell
cmake --build build --target mparser_c_embedding_demo
build\mparser_c_embedding_demo.exe
```

Expected summary:

```text
sumTo(100) = 5050
limited stop = instruction-limit
recovered = 42
summary = 5050,instruction-limit,42
```

The sample demonstrates compile-once stateless invocation, a persistent
session, an exact instruction stop, and reuse of the stopped session.

## Validation

`c_api_smoke` is compiled as C rather than C++. It covers API/version
validation, source diagnostics, single/multiple outputs, column-major numeric
and UTF-16 arrays, missing strings, Cells, Structs, initial workspaces,
result variables, object pass-through, closure lifetime, owner mismatch,
independent builtin handles, limits, cancellation, summaries, session reset,
and retain/release.

`c_embedding_demo_smoke` runs the host sample and requires its deterministic
summary. Both tests run in the complete Windows x64 and Linux x64 suites and
the focused native/portable Linux AArch64 QEMU jobs.

Local validation:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit
ctest --test-dir build-nojit --output-on-failure
```

## Deliberate Boundary

v0.83 does not close `G-EMBED-001`. The following remain v0.90 release gates:

1. final C++/C API and symbol/version compatibility freeze;
2. multi-source/load-path C compilation;
3. a versioned machine-readable result protocol;
4. install/export targets and external package-consumer tests;
5. optional external array views/adapters with proven ownership;
6. repeated load/unload, stress, sanitizer, and platform package evidence.
