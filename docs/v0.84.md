# MParser v0.84

MParser v0.84 adds source-graph compilation and filesystem loading to the
narrow C embedding ABI. A pure C host can now either provide an ordered set of
owned in-memory sources or load an entry `.m` file with ordered search paths.
The latter route uses the same `SourceLoader` as the CLI and C++ API, including
ordinary path functions, private functions, package namespaces, class folders,
and separated class methods.

This closes the multi-source/load-path part of the v0.90 embedding gate. The C
ABI remains candidate 1: installation/export packages, the machine-readable
protocol, forward-compatible tail negotiation, and final platform ABI review
are still open.

## C Source Graph Contract

`mparser_source_unit` is a versioned descriptor containing a source name and
UTF-8 source buffer. Initialize every element with
`mparser_source_unit_init`, then call `mparser_module_compile_sources`.

The compiler:

- requires at least one source and treats the first source as the entry source;
- copies every name and source buffer before returning;
- preserves source order and source-linked diagnostics;
- supports top-level scripts, functions, and classes across source units;
- returns an inspectable invalid module on a language compilation failure.

This explicit route does not infer MATLAB filesystem identity from source
names. Hosts that need `+package`, `@Class`, `private`, path precedence, or
separated-method behavior use the filesystem loader instead.

## UTF-8 Filesystem Loading

Initialize `mparser_source_load_options`, provide zero or more ordered
`mparser_utf8_view` search paths, and call
`mparser_module_load_file_utf8`. Entry and search paths are length-delimited
UTF-8 and are converted to the native filesystem representation without
passing through the Windows local code page.

The loader searches the entry location before host-supplied paths and reuses
the existing source-graph dependency rules. Loaded source names are retained
as UTF-8. `mparser_module_source_count` and
`mparser_module_source_name` expose the resulting ordered graph as borrowed
module-owned views.

A missing or unreadable entry/dependency returns
`MPARSER_API_STATUS_SOURCE_LOAD_FAILED` and still returns an invalid module
with one `MParser:SourceLoadFailed` compilation diagnostic. Invalid descriptor
or option layouts return `INVALID_ARGUMENT` or `ABI_MISMATCH` without creating
a module. No C++ exception crosses the boundary.

## Lifetime And Execution

Both compilation routes return the same `mparser_module` handle used by v0.83.
The module owns copied sources, compiled artifacts, source names, and
diagnostics. Sessions, values, resource controls, guarded native/portable
execution, and VM fallback are unchanged. Loaded but unoptimized code remains
valid VM input.

The original `mparser_module_compile_utf8` remains source and binary
compatible and is the shortest one-source convenience entry.

## Runnable Example

The new pure C host loads the existing package class-folder sample, including
`+folderpkg/@Counter` and its separated public, private, static, and helper
methods:

```powershell
cmake --build build --target mparser_c_source_graph_demo
build\mparser_c_source_graph_demo.exe `
  samples\class_folders\app\run_demo.m `
  samples\class_folders\lib
```

Expected summary:

```text
source-count = 7
summary = 21,107,12,12
```

## Validation

`c_api_smoke` remains a C11 translation unit and now additionally covers:

- versioned source and load-option initialization;
- explicit two-source script/class execution;
- ownership after host source/name buffers are modified;
- source enumeration and out-of-range views;
- diagnostics attributed to a non-entry source;
- filesystem package/class-folder/search-path loading;
- stable invalid-option, ABI-mismatch, and load-failure behavior.

`c_source_graph_demo_smoke` executes the real filesystem sample. Both tests are
joined by `c_api_utf8_source_graph_smoke`, which creates non-ASCII entry and
library directories and verifies retained UTF-8 source names. All are included
in the focused Linux AArch64 native-JIT and portable-only QEMU jobs as well as
the complete Windows x64 and Linux x64 suites.

Local validation:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit
ctest --test-dir build-nojit --output-on-failure
```

## Remaining Embedding Gate

v0.84 closes source-graph loading but does not close `G-EMBED-001`. The
remaining v0.90 work is:

1. install/export packages and external C/C++ consumer tests;
2. a versioned machine-readable result protocol with golden compatibility
   tests;
3. forward-compatible structure and symbol/version policy;
4. repeated load/unload, stress, sanitizer, and allocation-failure evidence;
5. final supported-platform ABI and package review.
