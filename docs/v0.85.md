# MParser v0.85

MParser v0.85 turns the narrow C embedding boundary into an installable SDK.
A host project can consume an installed prefix through
`find_package(MParser CONFIG)` and the exported `MParser::c_api` target,
without including MParser source directories or rebuilding the runtime.
The installed `MParser::cli` executable target exposes the matching command
line runtime.

This closes the installable-C-consumer part of the v0.90 embedding gate. The
C ABI remains candidate 1. The public C++ SDK, machine-readable protocol,
forward-compatible ABI policy, release archives, and final platform freeze
remain later work.

## Installed Layout

Configure a production-only build with the standard CMake testing switch:

```powershell
cmake -S . -B build-sdk -DBUILD_TESTING=OFF
cmake --build build-sdk --config Release
cmake --install build-sdk --config Release --prefix C:\mparser-sdk
```

The prefix contains:

- `include/mparser/c_api.h`;
- `bin/mparser` and the platform runtime part of `mparser_c`;
- the platform library/import-library files under `lib`;
- `lib/cmake/MParser/MParserConfig.cmake`, its version file, and exported
  targets;
- the README, C embedding guide, third-party notices, and runnable C examples.

The source project does not yet carry a project distribution license file.
That policy and the final archive/signing layout must be settled before a
formal v1.0 binary release. The bundled SLJIT notice is installed through
`THIRD_PARTY_NOTICES.md`.

## CMake Consumer Contract

An independent C11 project consumes the SDK with:

```cmake
find_package(MParser 0.85.0 EXACT CONFIG REQUIRED COMPONENTS C CLI)

add_executable(host main.c)
target_link_libraries(host PRIVATE MParser::c_api)
```

The package exports:

- `MParser::c_api`, with the installed include directory and shared-library
  import information;
- `MParser::cli`, pointing to the installed command line executable;
- `MParser_VERSION` and its major, minor, and patch components;
- `MParser_C_ABI_VERSION`;
- `MParser_C_INCLUDE_DIR` and `MParser_CLI_DIR`.

The package version file uses same-minor compatibility while the project is
pre-1.0. Hosts that need an exact candidate should request `0.85.0 EXACT` and
still query `mparser_c_abi_version()` at runtime.

On Windows the consumer must deploy `mparser_c.dll` beside its executable or
make the SDK `bin` directory available to the loader. The shipped validation
consumer copies the imported DLL beside its executable. Linux consumers
deploy `libmparser_c.so` according to their normal runtime-library policy.

## Relocation And Isolation

`MParserConfig.cmake` derives every path from the prefix that contains the
package file. The installation smoke first installs to one directory, renames
the complete prefix, and only then configures the consumer against the moved
location.

`tests/installed_c_consumer` is a separate C-only CMake project. It sees only
the installed package, links only `MParser::c_api`, compiles and repeatedly
invokes a two-output MATLAB-like function, verifies version and ABI queries,
and invokes the imported CLI target. This guards against accidental source
include paths, build-tree targets, and absolute install-prefix leaks.

Expected consumer output:

```text
installed-consumer = 0.85.0,42,36,abi-1
```

## Cross-Platform Validation

`installed_c_consumer_smoke` runs the full install, prefix relocation,
independent configure/build, C ABI execution, and CLI version test in the
native Windows x64 and Linux x64 suites.

The Linux AArch64 CI job performs the same install and external C11
cross-build separately for:

- the SLJIT-enabled native backend package;
- the no-native-JIT portable fallback package.

Both consumers and both installed CLIs execute under QEMU. Correct execution
therefore remains available whether or not native JIT was compiled in.

Local validation:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit
ctest --test-dir build-nojit --output-on-failure
```

## Remaining Embedding Gate

v0.85 does not close `G-EMBED-001`. The remaining v0.90 work includes:

1. the versioned machine-readable result protocol and golden compatibility
   tests;
2. the public C++ SDK/export decision and external C++ consumer;
3. forward-compatible C structure, symbol, and deprecation policy;
4. repeated load/unload, stress, sanitizer, and allocation-failure evidence;
5. macOS x64/ARM64 package consumers and final release packaging review.
