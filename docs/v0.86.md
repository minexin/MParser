# MParser v0.86

MParser v0.86 adds the first stable machine-readable execution boundary above
the engine-neutral `CompiledModule::execute()` contract. Automation can run a
source graph once and receive one versioned JSON document for success,
compilation failure, request rejection, or runtime failure without scraping
human display text.

This closes the machine-protocol sub-gate of the v0.90 embedding milestone.
It does not freeze the public C++ SDK or C ABI, add a persistent remote
protocol, expose object internals, or complete final platform packaging.

## Production Interface

Run the checked sample with:

```powershell
build\mparser.exe --run --result-format=json-v1 samples\machine_protocol_demo.m
```

Select a backend with the existing production policy:

```powershell
build\mparser.exe --run --jit=off --result-format=json-v1 `
  samples\machine_protocol_demo.m
build\mparser.exe --run --jit=portable --result-format=json-v1 `
  samples\machine_protocol_demo.m
build\mparser.exe --run --jit=native --result-format=json-v1 `
  samples\machine_protocol_demo.m
```

The machine path compiles the normal source graph and invokes the existing
`ModuleInvocationRequest`/`ModuleInvocationResult` boundary. It does not
construct a second VM result model. Human `--run` behavior remains unchanged.

## Protocol Contract

Protocol `mparser.result` major 1 minor 0 includes:

- engine and protocol versions;
- invocation status, entry, requested output count, named outputs, and
  workspace;
- staged diagnostics with source ranges, stack frames, and recursive causes;
- the complete engine-neutral execution summary;
- recursive serialization of every current `RuntimeValueKind`.

Numeric, logical, character, string, Cell, Struct, comma-separated-list, and
name-value payloads retain shape and MATLAB column-major order. Non-finite
doubles remain valid JSON through named string tokens. Function handles expose
stable callable metadata without captures or process identities. Objects are
explicit opaque descriptors.

The channel and schema are specified in
[machine-result-protocol.md](machine-result-protocol.md).

## Failure And Channel Rules

stdout is exactly one compact JSON document plus a newline after machine mode
has been selected. Language diagnostics, source-load failures, and CLI
validation failures stay inside that document; stderr remains empty.

Status-specific exit codes are 0 for success, 1 for compilation failure, 2 for
request rejection, and 3 for runtime failure. `--native-cache-stats` is
rejected in machine mode because it would otherwise add human stdout.

## Regression Evidence

`machine_protocol_smoke` compares a deterministic synthetic result with
`tests/golden/machine_result_v1.json`. The fixture covers every RuntimeValue
kind, column-major projection, logical and non-finite payloads, Unicode and
malformed UTF-8 handling, opaque objects, function-handle descriptors,
diagnostic source/stack/cause trees, and every execution-summary field.

`machine_protocol_cli_smoke` parses real CLI documents for:

- successful execution of `samples/machine_protocol_demo.m`;
- compilation failure;
- missing-entry request rejection;
- catchless language runtime failure;
- source-load failure;
- missing CLI input and incompatible cache-stat options.

`machine_protocol_production_cli_smoke` gives cross-compiled CTest jobs a
direct emulator-aware production probe. The focused Linux AArch64 native and
portable jobs include all three protocol tests.

Local validation:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit
ctest --test-dir build-nojit --output-on-failure
```

## Remaining Embedding Gate

v0.86 does not close `G-EMBED-001`. Remaining v0.90 work includes:

1. the public C++ SDK/export decision and an isolated C++ consumer;
2. forward-compatible C structure, symbol, and deprecation policy;
3. repeated load/unload, stress, sanitizer, and allocation-failure evidence;
4. macOS x64/ARM64 package consumers and final release packaging review;
5. a final compatibility review before freezing v1.0 API/ABI/protocol
   candidates.
