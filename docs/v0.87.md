# MParser v0.87

MParser v0.87 turns the pre-release C boundary into an explicitly evolvable
ABI-major-1 candidate. It fixes a forward-compatibility hazard before the
public C++ SDK is built on top of that boundary.

Earlier initializers wrote `sizeof(struct)` as seen by the library. If a later
library appended fields, an old host binary could provide a smaller object
while the newer initializer wrote the larger layout. v0.87 freezes the old
write range and adds caller-sized initialization for structures that may grow.

## ABI Tuple

The current boundary reports:

```text
ABI major    1
ABI revision 1
Engine       0.87.0
```

The major identifies binary-breaking generations. The revision identifies
additive ABI-major-1 capabilities. The engine version identifies language and
runtime behavior.

## Safe Structure Initialization

Current C source initializes extensible structures with:

```c
mparser_invocation_options request;
MPARSER_INVOCATION_OPTIONS_INIT(&request);

mparser_execution_summary summary;
MPARSER_EXECUTION_SUMMARY_INIT(&summary);

mparser_source_load_options loading;
MPARSER_SOURCE_LOAD_OPTIONS_INIT(&loading);
```

These macros call new `*_init_sized` exports with the host compiler's storage
size and ABI major. A successful call clears the full declared storage,
records its capacity, and initializes known defaults.

The frozen minimum-prefix constants are:

- `MPARSER_INVOCATION_OPTIONS_V1_SIZE`;
- `MPARSER_EXECUTION_SUMMARY_V1_SIZE`;
- `MPARSER_SOURCE_LOAD_OPTIONS_V1_SIZE`.

Execution and source loading accept a larger structure and read only fields
known to this library. Execution-summary output writes only its known prefix
within the caller's capacity, so a future tail remains at its initialized
default.

The original initializer functions remain exported. They always write exactly
the ABI-major-1 prefix, preserving binaries built with the v0.83-v0.86 header.

## Fixed-Stride Descriptors

`mparser_source_unit` is an array element, so its compiled size determines
descriptor stride. Appending fields would make an old library index a newer
array incorrectly. v0.87 therefore seals this layout and requires
`struct_size == MPARSER_SOURCE_UNIT_V1_SIZE`.

Other view and array-element records are also sealed. A future extensible
source descriptor must use a new function with an explicit stride or pointer
list. The full policy is in
[c-abi-compatibility.md](c-abi-compatibility.md).

## Runnable Sample

Build and run the future-tail sample:

```powershell
cmake --build build --target mparser_c_abi_compat_demo
build\mparser_c_abi_compat_demo.exe
```

Representative output:

```text
abi = 1.1, result = 42, request-bytes = 144
```

The byte count is architecture-dependent. The sample allocates request and
summary storage larger than the current public structures, executes a real
function, and verifies that the unknown tails remain zero.

## Regression Evidence

`c_api_smoke` now covers:

- null, undersized, and wrong-major initialization failures;
- old initializers leaving enclosing future tails untouched;
- sized initializers clearing complete host-declared storage;
- an oversized invocation executing `sumTo`;
- oversized source-load options loading a real package/class-folder graph;
- oversized summary storage receiving execution data without tail writes;
- rejection of an oversized fixed-stride source unit.

`c_api_v1_compat_smoke` includes only `tests/c_api_v1_snapshot.h`, copied from
the v0.86 release. It links the current library, compiles a two-source module,
invokes it, and reads a v1 execution summary using only old symbols.

The installed C consumer uses revision-1 initialization, checks ABI `1.1`, and
runs after the package prefix is relocated. Focused Linux AArch64 native and
portable jobs include the two ABI tests and compatibility sample under QEMU.

Local validation:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure

cmake -S . -B build-nojit -DMPARSER_ENABLE_NATIVE_JIT=OFF
cmake --build build-nojit
ctest --test-dir build-nojit --output-on-failure
```

The Windows x64 Release runs passed `179/179` tests with native JIT enabled
and `173/173` tests with native JIT disabled.

## Remaining Embedding Gate

v0.87 does not freeze the final v1.0 binary interface. The next embedding work
is an installed C++20 RAII SDK over the narrow C ABI, followed by lifecycle
stress, macOS consumers, external-adapter decisions, shared-library version
freeze, and the final v0.90 compatibility review.
