# MParser v0.88

MParser v0.88 adds an installable C++20 embedding SDK over the evolvable
ABI-major-1 C boundary. Hosts now get RAII ownership and ordinary C++ value,
request, result, diagnostic, session, cancellation, and resource-summary
types without depending on internal compiler or VM layouts.

## Public SDK

`include/mparser/cpp_api.hpp` is a header-only facade in `mparser::sdk`.
Installed consumers link `MParser::cpp_api`, which carries the C++20 feature
requirement and the shared `MParser::c_api` dependency.

The facade covers:

- engine and C ABI version queries;
- one-source, ordered multi-source, and UTF-8 filesystem graph compilation;
- stateless compile-once/invoke-many execution and persistent sessions;
- optional output counts, initial workspace, backend selection, and profiling;
- cancellation and all current resource limits;
- double/logical, character, string, Cell, Struct, object, function-handle,
  and missing values;
- copied compilation/runtime diagnostic trees and complete execution
  summaries.

RAII wrappers retain opaque C handles. Values extracted from results or
composites remain valid independently, and module-bound values continue to
enforce owner compatibility.

Compilation and source-load failures remain inspectable invalid modules.
MATLAB-like validation/runtime failures and resource stops remain inspectable
results. `ApiError` is reserved for invalid host arguments, type/range or
ownership errors, allocation failures reported by the C boundary, and
internal transport failures.

## Structure Order Correction

The C structure constructor previously collected fields in `std::map` order,
which made index-based enumeration alphabetical instead of preserving the
caller descriptor order. v0.88 records the supplied schema explicitly. C and
C++ hosts now observe stable caller order through construction, invocation,
and result extraction.

## Installation And Isolation

The package now installs:

- `include/mparser/cpp_api.hpp`;
- imported `MParser::cpp_api` and existing C/CLI targets;
- `MParser_CPP_FOUND` and `MParser_CPP_INCLUDE_DIR` metadata;
- `samples/cpp_embedding_demo.cpp`;
- `docs/embedding-cpp-api.md`.

`installed_cpp_consumer_smoke` installs the project to a temporary prefix,
moves the complete prefix, and configures an independent C++20 project against
only that relocated package. The project links only `MParser::cpp_api` and
checks version/ABI parity, multi-output execution, retained value lifetime,
Struct order and round-trip, runtime diagnostics, persistent sessions, and the
matching imported CLI.

Focused Linux AArch64 CI installs and cross-builds the C and C++ consumers for
both SLJIT-enabled and portable packages, then runs them under QEMU. The full
Windows x64 and Linux x64 suites cover the relocated consumer path.

## Runnable Sample

```powershell
cmake --build build --target mparser_cpp_embedding_demo
build\mparser_cpp_embedding_demo.exe
```

Representative output:

```text
cpp sdk = 5050,5,abi-1.1
```

The sample compiles one module, performs a stateless invocation, creates a
persistent session, and invokes the same module repeatedly.

## Validation

The focused source-tree tests are:

- `cpp_api_smoke` for the complete facade surface and UTF-8 source graph;
- `cpp_embedding_demo_smoke` for the runnable host sample;
- `installed_cpp_consumer_smoke` for installed relocation and isolation;
- the existing C API tests, including old-header ABI compatibility.

Windows x64 Release validation completed with:

- `182/182` tests passing with native JIT enabled;
- `176/176` tests passing with native JIT disabled;
- a clean `BUILD_TESTING=OFF` production build and install;
- `2/2` tests passing in a separately configured C++20 consumer against only
  that production install;
- direct sample output `cpp sdk = 5050,5,abi-1.1` and CLI version output
  `MParser 0.88.0`.

All platform CI jobs remain the final milestone closure gate.

## Next Gate

v0.88 establishes the public C++ packaging candidate but does not freeze it.
v0.89 adds repeated lifecycle and resource stress, concurrent stateless and
serialized-session evidence, macOS x64/ARM64 package consumers, and the open
adapter/array-view/licensing/shared-library-version decisions needed before
the v0.90 API candidate freeze.
