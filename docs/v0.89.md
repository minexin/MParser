# MParser v0.89

MParser v0.89 hardens the installed embedding SDK under concurrency and
establishes its release-platform shared-library boundary. It adds executable
lifecycle, shared-object, cancellation, resource, unload, symbol, and macOS
consumer evidence without widening the public C++ binary surface.

## Concurrency Contract

Pure stateless calls with value-only inputs retain independent runtime state
and may execute concurrently.

Objects and module-defined function handles can carry mutable shared graphs.
Requests containing those values now acquire a graph lock owned by the
producing module. Every execute, clear, and reset operation on every session
from that module acquires the same graph lock before its per-session lock.
This fixed order protects:

- concurrent mutation of one escaped MATLAB-like handle object;
- module-bound values shared between stateless calls and sessions;
- objects retained only in session global or persistent state;
- concurrent operations on one session;
- clearing or resetting state while another call retains an escaped object.

The current policy conservatively serializes distinct sessions from one
module. Finer object-grained locking may relax that cost later without
changing results or the host API. Invocation wall-time and cancellation
accounting starts after lock admission; queue wait is not charged to the
runtime wall-time limit.

Each host thread must own a retained C handle or an independent C++ wrapper
copy. Retain/release is atomic while a live reference remains. Concurrent
assignment, move, reset, or destruction of the same host wrapper variable is
outside the contract.

## Shared-Library ABI

The C boundary remains ABI major 1 revision 1. Its binary naming now follows
that ABI instead of the engine release:

- implementation version: `1.1.0`;
- ELF SONAME: `libmparser_c.so.1`;
- macOS install name: `libmparser_c.1.dylib`;
- Windows output: `mparser_c.dll` plus the import library.

Core compiler/VM code, the header-only C++ facade, and SLJIT use hidden
visibility. `tests/c_api_abi1_symbols.txt` freezes the complete 90-name
`mparser_*` export candidate. `c_api_shared_library_abi` compares the actual
dynamic symbol table with that manifest and checks the platform ABI-major
name.

This is still a v0.90 candidate. An incompatible correction before the final
freeze must change the ABI major rather than silently replacing major 1.

## Stress Evidence

`c_api_lifecycle_stress` performs 160,000 concurrent retain/release cycles for
modules, sessions, results, values, and cancellation tokens. It then proves a
retained session can execute after its public module handle is released and a
module-bound function handle remains readable after its producing result and
session are released.

`cpp_api_concurrency_stress` covers:

- 800 concurrent pure stateless invocations;
- 800 mutations of one shared handle object with exact sequence `1..800`;
- 800 calls through one copied session with exact persistent sequence;
- 200 calls from two sessions sharing one object retained only in globals;
- four isolated sessions with independent persistent state;
- eight calls stopped by one shared cancellation token;
- eight calls stopped at distinct exact instruction budgets.

`embedding_unload_stress` loads, queries, and unloads the shared library 256
times without linking to it. Existing API, ABI-prefix, old-header, installed
consumer, source-graph, and resource tests remain in the same regression.

## Platform Matrix

The GitHub Actions matrix now includes:

- Windows x64 with MSVC and native SLJIT;
- Linux x64 with GCC and native SLJIT;
- macOS x64 with Apple Clang and native SLJIT;
- macOS ARM64 with Apple Clang and native SLJIT;
- Linux ARM64 cross builds under QEMU for native SLJIT and portable fallback.

Each macOS job runs the full source suite, builds a production
`BUILD_TESTING=OFF` install, moves its prefix, and configures independent C11
and C++20 consumers against only that relocated package. The job also checks
the installed CLI/library architecture and engine version.

## Extension And Array Decisions

The v1.0 extension routes are now explicitly bounded:

1. ordinary `.m` functions through the source graph;
2. C++ builtins compiled into the engine through `BuiltinRegistry`;
3. a versioned pure-C external callback table after v1.0.

The future callback table must define ABI negotiation, ownership, allocator
and unload lifetime, errors, threading, side effects, context permissions,
and resource cooperation. It cannot expose C++ or VM layouts.

Host-created arrays remain copy-in for v1.0. Numeric and character result
accessors are readonly runtime-owned spans tied to one retained `Value`.
Borrowed host input and writable external views require a new additive
descriptor after the ownership and release-callback rules are designed.
