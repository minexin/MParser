# MParser v0.9 Scope

MParser v0.9 adds a small typed optimization IR layer. It consumes the v0.8
optimization plan and emits typed regions with guards and explicit fallback
operations.

## Added Since v0.8

- New `BytecodeTypedIrBuilder` module.
- New public typed IR data structures:
  `BytecodeTypedIrModule`, `BytecodeTypedIrRegion`,
  `BytecodeTypedIrGuard`, `BytecodeTypedValue`, and
  `BytecodeTypedIrOperation`.
- CLI option `--typed-ir-bytecode`.
- Scalar region classification for candidates whose guards are all
  `number(1x1)`.
- Typed region classification for stable non-scalar candidates.
- Explicit typed IR operations:
  `guard-values`, `specialize-loop`, `specialize-call`,
  `specialize-index`, `specialize-store`, and
  `deopt-on-guard-failure`.
- Dedicated `typed_ir_smoke` CTest coverage.
- Project version and CLI version bumped to `0.9.0`.

## Why This Matters

Before v0.9 the system could execute bytecode, profile it, and identify
optimization candidates. v0.9 adds the compiler-facing handoff:

```text
bytecode profile -> optimization plan -> typed IR regions
```

The typed IR is intentionally small. It does not rewrite bytecode or emit
machine code yet. Its purpose is to make specialization decisions explicit,
testable, and separated from VM execution.

## CLI Example

```powershell
build\mparser.exe --typed-ir-bytecode samples\bytecode_profile_demo.m
```

Expected typed IR signal:

```text
Bytecode typed IR:
  regions: 4
    region=0, kind=scalar-loop, sourcePc=7, target=i, executions=12
      guard source=loop, role=variable, kind=number, shape=1x1
      op specialize-loop target=i
      op deopt-on-guard-failure fallback=bytecode-vm
    region=1, kind=scalar-call-site, sourcePc=11, target=kernel
      guard source=call-site, role=arg0, kind=number, shape=1x1
      guard source=call-site, role=result0, kind=number, shape=1x1
      op specialize-call target=kernel
```

## Current Pipeline

The current optimization pipeline is now:

```text
HIR -> bytecode -> bytecode VM profile -> optimization plan -> typed IR
```

This is still an interpreter-first pipeline. The bytecode VM remains the
correctness baseline, and every typed IR region carries a deoptimization
fallback operation.

## Gaps Before v1.0

The project should not be considered a MATLAB-compatible v1.0 runtime yet.
Important missing pieces remain:

- Typed IR execution or LLVM lowering.
- Guard checking at runtime.
- Actual deoptimization mechanics.
- Loop body range modeling and region extraction.
- Broader MATLAB runtime features such as objects, cells, structs, complex
  numbers, sparse arrays, and full dynamic dispatch.

## Validation

Validated on Windows with MSVC Build Tools:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
build\mparser.exe --version
build\mparser.exe --typed-ir-bytecode samples\bytecode_profile_demo.m
build\mparser.exe --plan-bytecode samples\bytecode_profile_demo.m
```

Expected version output:

```text
MParser 0.9.0
```

## Next Iterations

The next high-value work is to turn typed IR from a description into an
executable optimized path:

- Add guard evaluation helpers.
- Add a tiny typed IR interpreter for scalar numeric regions.
- Route eligible regions through the typed path and fall back to bytecode VM on
  guard failure.
- Keep bytecode output, profile output, plan output, and typed IR output as
  regression-visible debug surfaces.
