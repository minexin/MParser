# v0.90.1 Release Authentication Hardening

MParser 0.90.1 is a publication-only patch to the frozen v1 candidate. It
does not change Parser, HIR, bytecode, RuntimeValue, VM, typed execution, JIT,
C ABI, C++ source API, CLI, machine protocol, or builtin semantics.

## Trigger

Annotated tag `v0.90.0` binds revision
`54abd3e41ca2b831a3f00005c7ab06cf101f9753`. GitHub Actions run
[30735920452](https://github.com/minexin/MParser/actions/runs/30735920452)
passed all seven Windows, Linux, native ARM64, AArch64/QEMU, macOS, and Linux
sanitizer execution jobs. The release-authentication job then rejected its
input before Cosign installation or OIDC certificate issuance.

The package upload used `build-*/packages/*`. That wildcard included CPack's
`_CPack_Packages` staging tree as well as the intended top-level release set,
so the authentication job found two copies of the Windows archive. No subject
was signed and no Sigstore bundle was produced by that run.

## Boundary Fix

- `v0.90.0` remains fixed at its original revision; it is not moved or
  force-updated.
- Platform upload steps allowlist only the archive, its `.sha256` sidecar, the
  unsigned `.provenance.json` statement, and `SHA256SUMS`.
- The authentication-input validator can require that exact four-file
  directory and rejects staging directories or any other extra input.
- `release_archive_smoke` constructs the exact set and proves that an added
  file is rejected before signing.
- Candidate version `0.90.1` and the immutable `0.90.0` JIT performance
  evidence version are validated independently.
