# MParser v0.90

MParser v0.90 closes the embedding and release-candidate API gate. It freezes
machine-checkable v1 candidates for the narrow C ABI, the header-only C++20
source API, and the one-shot machine result protocol. It also adds
allocation-failure containment, cache/concurrency stress, sanitizer CI, and
checksummed release archives that are exercised only through their unpacked
public SDK.

This is an API candidate freeze, not the v1.0 release. Language support and
optimization remain governed by `docs/compatibility-matrix.json`; legal code
outside typed/native coverage continues through the bytecode VM.

## Public Contract

`docs/public-contract-v1.json` is the review manifest for the public boundary.
It records:

- engine version `0.90.0`;
- C ABI major 1, revision 1, library version `1.1.0`, and 90 exports;
- C++ source API `1.0`, delivered as a header-only C++20 facade;
- machine result protocol `mparser.result` version `1.0`;
- Apache-2.0 and `Copyright 2026 Wang Xin`;
- normalized-LF SHA-256 values for each frozen header, snapshot, schema, export
  manifest, and protocol fixture;
- the compatibility review required before a frozen artifact changes.

`public_contract_smoke` recomputes every hash and verifies that live artifacts
match the immutable snapshots. A compatible additive change must update the
applicable ABI revision or API/protocol minor version and add old-client
evidence. A breaking change requires a new major.

Manifest artifact paths are repository-relative release-review evidence.
Installed packages expose their deployable headers, schema, and manifest
through checked CMake package variables; they do not install the source-tree
test snapshots.

## C ABI Candidate 1.1

The existing ABI-major-1 evolution policy remains unchanged: exported
functions and constants are additive, extensible root structures grow only at
the tail through sized initialization, sealed fixed-stride records do not
grow, and ownership meaning is stable.

v0.90 adds three independent freeze probes:

- `c_api_v1_1_compat_smoke` compiles against an exact v0.90 ABI 1.1 header
  snapshot and links to the current shared library;
- `c_api_layout_contract` freezes public 64-bit structure sizes, offsets,
  status values, and enum-like ranges;
- `c_api_shared_library_abi` rejects every unexpected externally defined
  symbol, including accidental exports that do not start with `mparser_`.

The v0.86 ABI-major-1 snapshot consumer remains in the suite, so both the
legacy prefix and the current 1.1 boundary execute against the same library.

## C++ Source API 1.0

`include/mparser/cpp_api.hpp` now declares `sourceApiVersion()` and source API
version `1.0`. It remains a header-only facade over `mparser_c`; MParser does
not promise a C++ binary ABI or export standard-library layouts.

`cpp_api_v1_compat_smoke` compiles an exact API 1.0 snapshot against the
current C library. The installed C++ reference consumer spans multiple
translation units and verifies both the header declaration and installed
CMake metadata. The runnable `cpp_embedding_demo` reports both ABI 1.1 and
source API 1.0 while exercising compile-once and persistent-session calls.
Hosts should constrain the MParser package version, compile against the public
header, and link only to `MParser::cpp_api`.

## Machine Result Protocol 1.0

`docs/machine-result-v1.schema.json` publishes a recursive JSON Schema for the
protocol. The existing complete golden fixture is copied into an immutable
1.0 snapshot, and `machine_protocol_contract_smoke` acts as an independent
reference consumer:

- exact unsigned 64-bit counters remain JSON integers;
- an additive future minor member is accepted;
- a wrong major, missing required member, invalid status, or wrong field type
  is rejected.

When stdout accepts the complete write, machine mode now guarantees one
compact UTF-8 JSON document, exactly one terminal LF byte on every platform,
empty stderr, and no leading or trailing bytes. Combining
`--help` or `--version` with `--result-format=json-v1` produces a structured
`request-rejected` document in either argument order instead of leaking human
output.

If ordinary serialization storage cannot be allocated, the CLI writes a
static allocation-free `request-rejected` document with
`MParser:ProtocolFailure` and exits with code 4. This
last-resort record preserves framing but intentionally contains no partially
constructed execution result. Its exact document is frozen independently in
`tests/golden/machine_result_emergency_v1.json`.

## Failure And Resource Boundary

The pure C boundary still prevents every C++ exception from escaping. v0.90
adds deterministic named fault points around source copying, module/session
publication, execution, result/diagnostic/value publication, external value
caches, Cell/Struct composition, and cancellation-token construction.

The regression proves:

- `std::bad_alloc` maps to `MPARSER_API_STATUS_ALLOCATION_FAILED`;
- other internal exceptions map to `MPARSER_API_STATUS_INTERNAL_ERROR`;
- failed constructors publish null output handles and keep parent handles
  usable;
- injection state is thread-local;
- a failure before execution does not commit session changes;
- a failure after runtime execution but before result publication may leave
  language-visible side effects committed.

The last case is deliberately nontransactional. A host must not blindly retry
an invocation whose C call failed after execution began unless the operation
is known to be idempotent.

`max_array_bytes` limits the recursive payload of each observed runtime value;
it is not an aggregate heap, RSS, or process-memory limit. Runtime wall-time
starts after module/session lock admission, so hosts that require queue
deadlines or admission limits must enforce them outside MParser. The C++ facade
converts C status failures to `ApiError`, but host-side vector/string copies
can still throw `std::bad_alloc`; applications should catch both.

## Process-Local Native Cache

The v1.0 candidate keeps generated native code in a bounded process-local
cache. `native_scalar_jit_cache_smoke` now churns compilation, lookup, clear,
and limit reconfiguration concurrently and continuously verifies entry and
code-byte bounds.

A disk cache is deferred. It will not be exposed until atomic persistence,
resource bounds, corruption recovery, and complete source, target
architecture, C ABI, compiler/options, and MParser-version invalidation are
implemented together. This decision preserves a compatible future extension
without placing unverified executable code on disk for v1.0.

## Release Archives

`MPARSER_ENABLE_RELEASE_PACKAGING=ON` enables the
`mparser_release_package` target. It creates one platform/architecture-named
archive and SHA-256 sidecars:

- Windows: `mparser-0.90.0-windows-x86_64.zip`;
- Linux: `mparser-0.90.0-linux-x86_64.tar.gz` or
  `mparser-0.90.0-linux-aarch64.tar.gz`;
- macOS: the corresponding `macos-x86_64` or `macos-arm64` archive.

The archive has one top-level directory and contains the CLI, shared C
library, public C/C++ headers, CMake package metadata, protocol schema,
contract manifest, samples, license, notice, and third-party notices.
`release_archive_smoke` packages the same built payload twice with a fixed
`SOURCE_DATE_EPOCH`, verifies identical archive SHA-256 values, rejects unsafe
paths, unpacks the SDK, and builds independent C11 and multi-translation-unit
C++20 consumers. It also executes the unpacked CLI and validates exact
machine-protocol framing without source-tree or loader-path assistance.

This proves archive reproducibility for a fixed compiled payload. It does not
claim bit-for-bit reproducible compilation across separate toolchain builds.
SHA-256 proves artifact integrity, not publisher identity; release signing or
provenance attestation remains a v1.0 publication operation.

## CI And Validation

Release CI builds the archive target and uploads packages for Windows x64,
Linux x64, Linux AArch64, macOS x64, and macOS ARM64. Linux Clang additionally
runs the full no-native-JIT suite under AddressSanitizer and
UndefinedBehaviorSanitizer with frame pointers and nonrecovering failures.
The AArch64 lane verifies the package checksum, unpacks the release SDK,
checks its frozen contract artifacts, and executes its CLI machine protocol
under QEMU before upload.

The local release gate is:

```powershell
cmake --build build/windows-msvc-release --parallel
ctest --test-dir build/windows-msvc-release --output-on-failure

cmake --build build/windows-msvc-release-nojit --parallel
ctest --test-dir build/windows-msvc-release-nojit --output-on-failure

cmake --build build/windows-msvc-release-package --target mparser_release_package
ctest --test-dir build/windows-msvc-release-package `
  -R release_archive_smoke --output-on-failure
```

The final Windows x64 Release validation for this milestone passed:

- native-JIT build: 194/194 tests;
- clean no-native-JIT build: 188/188 tests;
- release archive: reproducible fixed payload, relocated C11/C++20/CLI
  consumers, and matching SHA-256 sidecars.

The cross-platform Actions run is the final v0.90 closure gate.

## Next Gate

v1.0 remains responsible for final public CLI/API/extension versioning and
deprecation policy, support/manual completeness, fuzz and stress closure,
performance and memory characterization, release provenance, and the final
packaging checklist. Broader typed/JIT coverage remains guarded and additive;
long-tail builtin and toolbox growth remains the v1.x roadmap.
