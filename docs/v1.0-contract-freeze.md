# MParser v1.0 Contract Freeze

This milestone is the second gate in the post-v0.90 v1.0 sequence. It freezes
the command-line, C ABI, C++ source API, machine-result, and builtin-extension
boundaries under one versioning and deprecation policy. The final freeze sets
the engine and package version to 1.0.0; hosted tag authentication is now
complete and release-page publication remains separate. It does not broaden
the long-tail MATLAB function scope.

The implementation is frozen at engine version `1.0.0` and public-contract
state `frozen-v1`. Parser, HIR, Bytecode, `RuntimeValue`, and embedding
architecture are unchanged from the accepted candidate except for local
correctness and release-contract fixes.

## CLI 1.0

`docs/cli-contract-v1.json` freezes `--run` as the production command and
records the diagnostic-mode stability boundary.

- Every execution/inspection mode and scalar option is accepted at most once.
- More than one mode is rejected.
- An option outside the modes that consume it is rejected instead of ignored.
- Production `--run` accepts `--jit=auto|off|portable|native` and rejects the
  diagnostic `--typed-backend` selector.
- `--entry-function`, `--argument`, and `--outputs` are rejected by
  `--run-hir`, whose reference interpreter does not consume them.
- The undocumented pre-v1 `--run-interpreter` alias is removed; use
  `--run-hir`.
- Human CLI usage errors return 2. Source, compilation, and runtime failures
  remain exit 1 on the human channel.
- Machine mode remains one JSON document plus LF on stdout, empty stderr, and
  protocol exits 0 through 4.

`production_run_cli_contract_smoke` exercises duplicate modes/options,
production/diagnostic selector separation, invocation-option rejection,
adaptive/benchmark/module option scoping, cache/path scoping, the removed
alias, and the `--` source separator.

## Machine Result Schema

`docs/machine-result-v1.schema.json` is now explicitly a Draft-7 tolerant
major-1 consumer profile. Exact producer 1.0 remains frozen by the golden and
public snapshots.

The test-only vendored `nlohmann/json` 3.12.0 and Modern C++ JSON Schema
Validator 2.4.0 validate:

- golden, emergency, and immutable 1.0 snapshot documents;
- every dynamically emitted success and failure CLI document;
- requested `auto`, `off`, `portable`, and `native` backend documents;
- recursive diagnostic causes;
- numeric versus logical payload types and nonfinite tokens;
- additive future-minor fields and wrong-major/shape negative cases.

A supplemental semantic pass enforces unsigned 64-bit fields because common
Draft-7 implementations represent numeric limits with signed host integers.
These libraries are test dependencies only; the runtime serializer remains
self-contained.

## C ABI Prefix Safety

The versioned C record initializers clear only `storage_size` bytes and write
the frozen prefix fields. They no longer assign a current-library aggregate
over caller storage after the bounded clear. This preserves deliberately
smaller legacy prefixes when a future library structure grows.

The compile-time layout assertions permit additive tail growth while retaining
the existing legacy-prefix canary and future-tail tests in `c_api_smoke`.
`tests/c_api_v1_snapshot.h` is now a hashed public-contract artifact alongside
the current C ABI 1.1 snapshot.

## Builtin Source Contract 1.0

`kBuiltinSourceContractMajor` and `kBuiltinSourceContractMinor` identify
source contract 1.0. It is for C++ builtins compiled together with the engine,
not an installed plugin ABI.

`BuiltinDescriptor` now declares positional `outputConstraints` in addition
to input constraints. The registry validates them after generic
`RuntimeValue` ownership and shape checks and reports extension mistakes as
`MParser:BuiltinContractViolation`. A typed lowering requires explicit numeric
first-input and first-output constraints.

`builtin_catalog_snapshot_smoke` generates a normalized view of every default
descriptor and compares it with
`tests/public_contract/builtin/1.0/default_catalog.json`. The snapshot covers
118 names plus aliases, arity, input/output constraints, implementation kind,
purity, determinism, thread safety, side effects, context permissions, error
identifier, and typed lowering.

The shared conformance helper now compares recursive `RuntimeValue` content and
diagnostics instead of display strings. The registry smoke also proves output
constraint enforcement, custom aliases, context, exception conversion,
shadowing, function handles, portable typed execution, and native execution
when available.

## Unified Policy

`docs/versioning-and-deprecation.md` defines independent version domains for:

- engine/package semantic versions;
- CLI contract 1.0;
- C ABI major 1 revision 1;
- header-only C++ source API 1.0;
- machine result protocol 1.0;
- builtin source contract 1.0.

Stable v1 elements remain supported throughout v1.x. A deprecation records its
replacement and first notice, remains for at least one subsequent minor and
the rest of major v1, and is removed only in the next major. The `1.0.0`
release changes CMake package compatibility from the current pre-v1
`SameMinorVersion` policy to `SameMajorVersion`.
