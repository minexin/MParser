## Release Decisions

This run supplies the previously deferred candidate confirmation for:

- the frozen CLI, C ABI 1.1, header-only C++ API 1.0, machine protocol 1.0,
  builtin descriptor contract, and compatibility matrix;
- deterministic frontend/bytecode verification, invoke-many, lifecycle,
  resource, cache, allocation, unload, concurrency, and Linux sanitizer
  reliability evidence;
- installed and archived documentation, C11/C++20 consumers, CLI protocol,
  platform/architecture naming, checksum generation, and unsigned provenance
  metadata on the advertised release matrix.

Accordingly, `G-RELIABILITY-001` and `G-DOCUMENTATION-001` are closed. The
candidate remains version 0.90.0 and the public contract remains
`frozen-v1-candidate`; final versioning, tag, and publication are separate
operations.

## Remaining Boundaries

This run does not close:

- `G-PERFORMANCE-001`: committed reports remain Windows x86-64 evidence;
  additional cross-platform reports and physical ARM characterization are not
  produced by this functional workflow;
- `G-PROVENANCE-001`: uploaded statements are deterministic unsigned audit
  metadata, not hosted or publisher-authenticated provenance;
- `G-SANITIZER-001`: Linux TSan and macOS ARM64 sanitizer feasibility still
  require focused evaluation, while local Windows MSVC ASan remains evidence
  rather than a recurring lane;
- final `1.0.0` artifacts, tag, release-page publication, and provenance
  authentication.

The release-candidate readiness test freezes the remaining Must-have set to
`G-PERFORMANCE-001` and `G-PROVENANCE-001`, keeps `G-SANITIZER-001` as a
bounded Should-have, and keeps broader JIT coverage deferred to v1.x.
