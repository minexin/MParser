# MParser v1.0.0 Release Freeze

MParser v1.0.0 freezes the first stable release of the documented
MATLAB-like subset runtime. This milestone changes the engine and package
version from 0.90.1 to 1.0.0 without broadening the language, value, JIT, or
embedding scope accepted by the v1 compatibility matrix.

Publication contract: **frozen v1**. Final tag status: **authenticated**. The
release commit is tagged as `v1.0.0`; final tag-scoped Sigstore authentication and
independent artifact verification are complete. GitHub Release asset
publication is the remaining hosted operation.

## Frozen Interfaces

The release preserves these public versioned boundaries:

- production CLI 1.0 with `mparser --run` and `--result-format=json-v1`;
- C ABI major 1, revision 1, shared-library version 1.1.0 and SOVERSION 1;
- header-only C++20 source API 1.0 over the C ABI;
- `mparser.result` protocol 1.0 and its tolerant major-1 schema;
- `BuiltinRegistry` and `BuiltinDescriptor` source extension contract 1.0;
- Apache-2.0 licensing with Copyright 2026 Wang Xin.

The combined machine-readable authority is
`docs/public-contract-v1.json`. Exact syntax, runtime, tier, platform, and
unsupported boundaries remain in `docs/compatibility-matrix.json`.

## Runtime Scope

The supported subset includes documented numeric/logical N-D arrays, text,
cells, structures and structure arrays, functions and multiple outputs,
function handles, persistent sessions, structured diagnostics and exceptions,
and the bounded `classdef` object model recorded in the support matrix. The
verified bytecode VM remains the semantic authority. Portable typed and SLJIT
native execution remain guarded optimizations with correct VM fallback.

MParser v1.0.0 is not a complete MATLAB, toolbox, desktop, graphics, Simulink,
MEX, sparse, complex, GPU, or distributed-computing implementation. Those
limits are release contracts rather than implied future behavior.

## Post-v1.0 Growth

Broader typed/JIT specialization, persistent native-code disk cache, long-tail
builtins, additional value families, external compiled builtin adapters, and
complete MATLAB/toolbox compatibility remain additive v1.x or later work.
They do not weaken the v1 fallback, ABI, protocol, ownership, or diagnostic
contracts.

See `release-notes-v1.0.md`, `release-process.md`,
`release-authentication.md`, and `roadmap-v1.x.md` for user-visible changes,
publication procedure, verification commands, and the bounded continuation
plan.
