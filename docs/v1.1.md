# MParser v1.1.0

MParser v1.1.0 is the first additive release on the frozen v1 contract line.
It closes six high-impact language/runtime mismatches found by the external
`MParserV1.0Test` differential suite. The CLI 1.0, C ABI major 1 revision 1,
C++ source API 1.0, machine result protocol 1.0, and builtin source contract
1.0 remain compatible. The published v1.0.0 authentication and release
evidence remains immutable historical evidence.

## Scope

The milestone closes:

- MATLAB-compatible left association for chained `^` and `.^`, while unary
  power precedence remains unchanged;
- comma-separated one-line `if`, `switch`, `for`, and `while` forms without
  treating commas inside calls, matrices, Cells, or output lists as statement
  boundaries;
- MATLAB matrix `for` semantics, where each iteration receives one column and
  a row vector therefore continues to yield scalar loop values;
- column-shaped `A(:)` results for numeric, Cell, Struct, text, object, and
  shared nested-index read paths.

These changes close external cases `cap_007_syntax_precedence`,
`cap_010_syntax_one_liner_if`, `cap_011_syntax_one_liner_switch`,
`cap_012_syntax_one_liner_loops`, `cap_077_arr_for_matrix`, and
`cap_085_arr_linear_colon`.

## Runtime Design

Parser statement collection now accepts comma as a separator only where a
MATLAB statement or control header permits it and only at zero delimiter
depth. Power chains use the same left-associative precedence-climbing rule as
the other binary operators; prefix parsing still leaves power above unary
minus.

`runtimeNumericForLoopColumns` is the shared Interpreter/VM authority for
numeric loop iteration. It preserves numeric class, extracts values by logical
column-major index, folds trailing N-D dimensions into the column count, and
represents every nonscalar iteration value as a rows-by-1 array. Typed scalar
regions validate that every runtime column is scalar before execution. A
nonscalar column records `UnsupportedRuntimeValue`, leaves the range on the VM
stack, and executes the verified bytecode loop instead.

The shared indexing layer now carries an explicit single-colon shape contract.
`A(:)` returns `numel(A)`-by-1 even when `A` is a row vector, while ordinary
linear subscripts preserve the existing target/subscript orientation rules.
Old internal runtime overloads remain available and delegate to the original
non-colon behavior, so existing static objects do not acquire an accidental
symbol break.

## Runnable Evidence

Run the combined sample through the production engine:

```text
mparser --run samples/v1_1_core_compatibility_demo.m
```

The stable result is `summary = 188`. CTest runs the same source through the
HIR interpreter, no-JIT bytecode VM, and production `--run` path. Focused C++
tests also validate parser shape, row-vector `v(:)`, final matrix-loop column
shape, and typed runtime-shape fallback. The original six external scripts
must continue to exit successfully under `--run --jit=auto`.

The complete 223-point rerun on 2026-08-09 reused the unchanged MATLAB R2024b
baseline and produced 140 matches plus 83 gaps. Compared with v1.0.0, exactly
the six named cases moved from gap to match and no prior match regressed.

Installed C and C++ consumers request the original `1.0.0` package baseline
and consume the `1.1.0` SDK through CMake's `SameMajorVersion` policy. They
still verify the exact installed engine version and the frozen CLI, C ABI,
C++ source API, machine protocol, and builtin source contracts. Release
archives include this milestone document, the external gap plan, and the
combined v1.1 sample.

## Compatibility

This milestone changes incorrect MATLAB-like behavior rather than a public
host interface. Existing source that depended on right-associated power,
scalar element iteration of a matrix, or row-shaped `A(:)` observes the
corrected behavior. Legal but unoptimized loops remain executable in the VM;
native or portable typed eligibility is never a correctness prerequisite.

The complete imported gap inventory and later v1.x sequence are tracked in
[v1.x-external-gap-plan.md](v1.x-external-gap-plan.md). Long-tail builtin and
toolbox breadth remains later v1.x work.
