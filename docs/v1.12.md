# v1.12: Script Interaction And Reflection

Status: development batch; platform validation remains open.

The interaction implementation provides invocation-owned input callbacks through
the C and C++ SDK and console input through human-readable CLI execution.
`input` evaluates expressions in the calling workspace or returns literal text;
`keyboard` permits inspecting and changing that workspace before continuing.
See [interactive input](interactive-input.md) for callback ownership,
cancellation, pending polling, capability checks, and diagnostics.

`superclasses` uses the shared class catalog to traverse visible ancestors.
See [superclass reflection](superclasses.md) for ordering, hidden ancestors,
metadata values, and source-graph boundaries. The active builtin source contract
is 1.18, with 331 descriptors and 333 registered names. Historical catalogs
remain frozen and are included alongside the new snapshot in the release SDK.

## Local Evidence

On 2026-09-08, Windows MSVC Release no-JIT passed 322/322 tests. The fresh
native build passed 339/340; correcting the archive verifier's active catalog
version/count/hash made the sole failed test pass on a focused retest. Installed
and relocated C/C++ consumers passed in both configurations.

The external V1.0 inventory ran against the native executable with
`tools/run_external_catalog.ps1`: 222/223 cases passed. Only
`cap_291_out_graphics` failed with `MParser:UnsupportedBuiltin` for `plot`, the
then-declared graphics exclusion. The subsequent user scope update includes
headless Graphics Object semantics in V1.x, so this remaining case is now an
open requirement; see [graphics-object-model.md](graphics-object-model.md).
Evidence is in
`build/v1.12-external-catalog-verified/mparser_results.json`, with executable,
manifest, and case-source SHA-256 hashes and per-case raw output. Comparing to
the saved MATLAB results from `build/v1.3-differential-current` yields 222 matches
and one gap. MATLAB was not rerun; this comparison reuses historical MATLAB
outcomes and does not prove a fresh differential run against current sources.

The runner reads the external manifest without regenerating it, closes stdin,
drains stdout/stderr asynchronously, enforces per-process timeouts, and uses
an isolated working directory with a distinct temporary subdirectory. The
catalog assumes the initial directory is nonempty and differs from tempdir.
Two earlier runner attempts exposed those environment prerequisites; their
results are retained in adjacent build directories for diagnosis.

## Remaining Work

The first [platform run](https://github.com/minexin/MParser/actions/runs/34212502183)
for `b041090` passed all five native jobs. Its Clang ASan/UBSan job failed the
input callback's invalid-status test: loading status 999 through a C enum was
undefined before the explicit validation could reject it. The correction uses
the SDK's existing `uint32_t` status convention and preserves the negative test.
Corrected-platform validation and milestone delivery checks remain pending. The host
notes dated 2026-09-06 also retain selected-frame expression evaluation, local
assignment, conditional breakpoints, and source-level debugger commands.
Those requirements remain part of the broader V1.x objective. Script keyboard
interaction does not establish selected-frame SDK debugger support.

On 2026-09-09, the corrected input status/mode representation passed 10/10
focused Windows native tests after the clean rebuild: input runtime, CLI, C
callback negatives, C++ facade, C ABI layout, input sample, installed C/C++
consumers, documentation, and release archive. The build directory's generated
MSVC include-prefix encoding was corrected for subsequent dependency tracking.
The sanitizer correction still requires new platform CI evidence.
