# v1.13: Debugger Evaluation And Control

Status: development; C/C++ pause-event evaluation and conditional breakpoints
and the documented source debugger command subset are implemented. Local
native/no-JIT acceptance has passed; platform validation remains open.

The internal debugger now accepts source evaluation for a selected frame of
the current pause event. The event sequence and execution thread must match,
and recursive evaluation is rejected. Resume invalidates the frame evaluators.
Nested execution during an authorized evaluation suppresses debugger callbacks
while preserving the invocation's execution control and system capabilities.

Interpreter and bytecode frames reuse their dynamic source evaluation paths.
Expression results and captured output are returned independently of the
interrupted program's result. Zero requested outputs permits assignments.
The selected workspace includes its live nested captures and global/persistent
bindings; updated captures are written back to their current nested owner.
Evaluation errors do not themselves abort the interrupted program. Existing
dynamic source restrictions and partial-effect semantics still apply.

## Current Evidence

On 2026-09-09, the native MSVC focused `runtime_debugger_smoke` and
`runtime_input_smoke` tests passed 2/2. Debugger coverage includes both HIR and
bytecode parent execution, selected caller and current-frame assignment,
local function calls, output capture, expression-error recovery, nested
capture edits, global/persistent edits, capability denial and cancellation.
Control tests reject expired event sequences, wrong threads, invalid frames,
and recursive evaluation, and exercise exception recovery without extra pauses.

The expanded native debugger regression also evaluates and modifies a callee
in a separately compiled module while assigning a variable in its caller.
Resumed execution verifies both the new return value and the caller variable.
Three nested function frames verify that a selected outer-frame capture edit
is visible from intermediate and innermost frames and survives all returns.
An assignment followed by an evaluation error preserves that executed
assignment, matching the existing dynamic-evaluation partial-effect behavior.
These checks pass in both interpreter and VM nested-frame runs; the
cross-module case uses the native callable-dispatch path.

Dynamic-frame evaluation exposed an additional synchronization defect: while
`eval` calls an inherited function, the parent workspace is authoritative and
is copied back when the call returns. Debug edits to the temporary VM frame
were consequently overwritten. A scoped borrowed workspace alias now directs
paused-frame snapshots and evaluation synchronization to that authority.
The regression modifies both the eval frame and its callee and confirms the
edited value, new variable, and return value survive eval completion under
both interpreter and VM parents. The focused debugger/input suite passes 2/2
after this correction.

## Public Evaluation And Conditional Breakpoints

Internal breakpoints now accept a condition evaluated in the current live
frame. Empty conditions retain unconditional behavior. False numeric/logical
conditions continue without a host pause; evaluation errors and invalid truth
values pause with `conditionDiagnostics` on the event. Frame snapshots are
refreshed after condition evaluation. Matching breakpoints are checked in
configuration order until an unconditional, true, or erroneous condition is
reached. Condition evaluation uses the same capability and execution controls
as explicit debug evaluation, with the same partial-effect semantics.

The native focused suite passes 2/2 with new HIR/VM cases: `k==3` pauses once
in a four-iteration loop; an unknown identifier or a text-valued condition
pauses with diagnostics on each hit; resumed execution retains the correct
sum. Public SDK coverage now also checks condition ordering, retained
diagnostics, capability denial, and false conditions during stepping.

The C API now provides `mparser_debug_event_evaluate` on the borrowed pause
event. It returns an owned `mparser_result`, preserving output values, captured
text, and diagnostic stacks/causes. Evaluation requires the invocation's
`MPARSER_SYSTEM_CAPABILITY_DYNAMIC_EVALUATION` capability. Frame snapshots do
not change after assignment. The C regression checks invalid frame rejection,
expression-error recovery, local assignment followed by resumed execution,
captured output retained after the callback, and the unchanged sized-option
prefix. The active additive ABI revision is 4; revision 3's manifest is retained.
On 2026-09-09, native MSVC `runtime_debugger_smoke`, `debugger_c_api_smoke`,
`c_api_layout_contract`, and `c_api_shared_library_abi` passed 4/4. The shared
library check verified all 135 exports. This is focused evidence, not a full
SDK or cross-platform acceptance run.

C++ `DebugEvent::evaluate` now wraps the C result with `Result`. A shared
callback-lifetime guard expires even when the host callback throws. Copies of
the event reject wrong-thread or post-callback evaluation before touching the
borrowed C event. The SDK regression covers assignment/resume, error recovery,
retained results, normal and exceptional expiration, and shared Runtime export
of an evaluated function handle into another module, including evaluation of
its captured values while that module calls it.
Evaluation lifetime checks run through Module, Session, and Runtime entry
points. On 2026-09-09 the focused native C/C++ debugger, runtime debugger,
layout, and shared-library ABI suite passed 5/5.

Public C/C++ conditional-breakpoint configuration and event diagnostics are
implemented. C11 tests cover true/false/error conditions and reject malformed
replacement input without disturbing the previous configuration. C++ tests
cover loop-variable conditions, errors and invalid truth values, capability
denial, ordered same-line conditions, retained diagnostic source metadata, and
false conditions that must not swallow single stepping. The latest focused
native suite passed 5/5 and verified the expanded 138-symbol ABI manifest.

## Source Commands And Acceptance Evidence

Source breakpoint configuration now supports `dbstop in SOURCE at LINE`, its
conditional string-argument form, `dbclear in SOURCE [at LINE]`, `dbclear all`,
and `dbstatus`. HIR/VM regressions cover command syntax, same-line replacement,
conditional execution, invalid-input atomicity, paused evaluation, and an
unattached debugger. The source contract is 1.19; the six source commands now
bring it to 337 descriptors and 339 names; the subsequent `dbstack` addition
brings the development catalog to 338 descriptors and 340 names.
The configuration batch passed native full regression 340/340, recorded in
`build/v1.13-source-native-ctest.log`; later no-JIT results below supersede
that intermediate build status.

Internal resume-action arbitration is now available for the remaining command
handlers: only explicit evaluation on the paused host callback thread may
queue an action. Condition evaluation cannot resume execution. Host stop wins
over source actions, and a queued source stop cannot be undone by a subsequent
continue request. The action takes effect only when the host callback returns.
The dedicated runtime debugger regression passes after this addition. Source
`dbcont`, `dbquit`, `dbstep`, `dbstep in`, and `dbstep out` handlers are connected
and the HIR/VM command tests pass, checking pause locations and stop behavior.
The SDK demo queues step-out through the source command. Native
debugger, builtin catalog/CLI, example, and installed C/C++ consumer checks
passed 11/11 after wiring the commands; the no-JIT full build
recorded in `build/v1.13-resume-nojit-build.log` completed, and its
full regression passed 322/322 (`build/v1.13-resume-nojit-ctest.log`). The newer
`dbstack` query retains the original paused stack, excludes temporary evaluation
frames, and is available only during explicit pause-event evaluation. Its
source-level HIR/VM regression passed in `build/v1.13-stack-source-ctest.log`;
Native stack/SDK/catalog/example and installed-consumer checks passed 7/7
(`build/v1.13-stack-sdk-ctest.log`). The SDK regression reads the owned stack
schema and line after normal and exceptional callbacks through Module, Session,
and Runtime. Full no-JIT validation of the stack addition passed 322/322
(`build/v1.13-stack-nojit-ctest.log`). Later frame-navigation evidence follows.

The internal debugger now retains a selected frame for each host pause. The
selection starts at the innermost frame, supports bounded caller/callee moves,
and can drive subsequent evaluation independently of explicit frame-index
evaluation. It is execution-thread-only and inaccessible after resume. Internal
regression covers two pause cycles, both navigation boundaries, explicit-index
independence, and thread rejection; `build/v1.13-navigation-ctest.log` passed.
Public selected-frame evaluation now uses `MPARSER_DEBUG_SELECTED_FRAME` in C
and `DebugEvent::selectedFrame` in C++. `dbup`/`dbdown` move one frame for the
next selected-frame request. The SDK regression switches to a caller, modifies
its variable, switches back, modifies a function parameter, and checks the
resumed result. It also checks both navigation boundaries. Native
`debugger_api_smoke` passed (`build/v1.13-navigation-sdk-ctest.log`). The active
1.19 development catalog now has 340 descriptors and 342 names. Native full
regression passed 340/340 (`build/v1.13-navigation-full-ctest.log`). The added
C11 selected-frame regression passed separately, verifying caller assignment
and return to the current frame (`build/v1.13-navigation-c-ctest.log`). The
no-JIT full rebuild and regression passed 322/322
(`build/v1.13-navigation-nojit-ctest.log`); platform acceptance remains pending.
The external inventory refresh passed 222/223 against the current native
executable (`build/v1.13-navigation-external-catalog/mparser_results.json`).
The sole failure is `cap_291_out_graphics` (`plot` remains unsupported), which
is assigned to V1.14. This is an executable/manifest/source-hashed inventory run, not a new MATLAB
differential run. Applicable platform CI still needs validation, followed
by the complete milestone acceptance gates. This internal batch does not close
`SRV-DEBUG-001` or the milestone.
