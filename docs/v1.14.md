## Implemented working-tree slice

The session owns a `RuntimeGraphicsGraph` containing Figure/Axes/Line nodes.
Nodes have monotonically increasing IDs and containment edges contain IDs only.
Parent validation enforces Figure -> Axes -> Line. Reparenting updates both
sides; deletion detaches the entire subtree. Deleted IDs are never reused.
Exported runtime values retain the graph, not the session or compiled module.
Session reset replaces its graph; previously exported handles retain their
original graph until released. Explicit deletion invalidates those aliases.

`plot(y)` and `plot(x,y)` execute through a shared contextual builtin in both
HIR and bytecode. Inputs are real dense numeric vectors (row or column),
scalars, or empty arrays; complex, sparse, matrix and unequal-length inputs
are rejected before graph mutation. Each call creates a new Figure/Axes/Line
tree. Implicit x coordinates are `1:numel(y)`. The optional result is the Line
handle. A call without outputs still stores its graph in the session.
Current-axes reuse and matrix-as-multiple-series overloads are not implemented.

Runtime values use MATLAB class names for Figure, Axes and Line. Their ordinary
field maps stay empty; parent/child references never introduce strong cycles.
Equality compares graph and node identity, including independent wrappers and
deleted aliases. The value contract rejects incompatible graphics storage.

Source property access includes `Parent`, `Children`, Figure Name/Visible,
Axes XLim/YLim/XLabel/YLabel/Title, and Line XData/YData/Color/LineStyle/DisplayName.
Parent assignment rejects foreign graphs and invalid hierarchy. Children is
read-only; empty relations currently return an empty double matrix. Numeric
properties accept real dense vectors, text properties accept scalar text.
RGB values, limits and enumerated styles/visibility are validated. `delete(h)`
and `isvalid(h)` support scalar graphics handles in both execution paths.
Array lifecycle operations and method-call forms are not yet covered.

Graph-level plot construction builds a complete tree before insertion, so
coordinate validation or allocation failure during construction leaves the
existing graph unchanged. Limits enclose finite data, pad constant data, and
use [0,1] for empty/nonfinite-only data.

## Serialization

Internal serialization emits `mparser.graphics` version 1 JSON. Objects follow
creation order with consecutive record-local IDs, so deleted historical IDs
do not affect equivalent graph output. Parent/Children links are validated in
both directions. Properties use canonical sorted names. Numeric nonfinite data
uses `NaN`, `Inf`, `-Inf` strings; signed zero is normalized. Invalid UTF-8 is
rejected. Scalar graphics values now expose this record through machine
protocol outputs/workspace values using `representation: "graphics"`. The
snapshot includes validity and a record-local handle reference; deleted handles
have a null reference. Graphics arrays use a deduplicated graph table and
logical-column-major element references, preserving shape and deleted aliases.

The working-tree C API adds `mparser_value_graphics_json`, returning an owned
character-array snapshot that is released with `mparser_value_release`.
`Value::graphicsJson()` returns the same JSON as an owned C++ string. Unicode
is escaped, making the JSON text ASCII without losing property content.
Scalar graphics values do not retain the originating module/runtime owner.
Their graph has its own recursive mutex; mutations and snapshot serialization
are ordered independently of session lifetime. Raw internal node views require
the graph guard for the entire duration of access.

## No-Output Delivery

Interpreter and module results now capture an immutable session graph after
execution, including runtime failure. The C accessor
`mparser_result_graphics_json` exposes borrowed result-owned UTF-8 bytes;
`Result::graphicsJson()` copies them. Protocol 1.2 exports the same optional
record at root `graphics`. Empty graphs and unavailable snapshots are distinct.
Later execution, reset and owner destruction do not mutate prior snapshots.
Export errors become `MParser:GraphicsExportFailed`; allocation failures retain
the existing boundary behavior. Debugger-evaluation results do not capture this
session snapshot.

## Graphics Arrays

The value-level C/C++ JSON accessor and machine protocol now support graphics
arrays, including `Children` collections. Records preserve dimensions and
column-major order, deduplicate graphs in first-occurrence order, and retain
alias/deleted state through graph/valid/reference elements. Empty arrays are
supported. Graph locking uses address order internally without exposing it.
Array payload/shape mismatches and dimension overflow are rejected.

Native graphics/SDK/protocol/ABI tests passed 9/9 in
`build/v1.14-graphics-array-ctest.log`, including HIR/VM source arrays, deleted
aliases, multi-graph and empty arrays, malformed shapes, opposite-order
concurrent snapshot reads, and SDK reads after original owner release.

`build/v1.14-nojit-graphics-array-ctest.log`. The documentation gate also passed.
