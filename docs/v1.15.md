# MParser 1.15 Host Integration Development

Status: development, not frozen or published. The product, CLI version banner,
shared library and installed SDK report 1.15.0. The C/C++ source API is 1.15
and the CLI contract remains 1.0. C ABI remains generation 2,
revision 13 (158 exports); builtin source contract is 1.23 (356 descriptors,
358 registered names). The machine-result protocol remains 1.2. Graphics v3
is an explicitly selected snapshot format, not a new product version. Opt-in
graphics v4 additionally freezes explicit per-Figure host layout environments.

## Kernel Changes

- C++ numeric scalar factories use explicit real/complex construction paths
  for GCC warnings-as-errors compatibility, preserving signed zero, component
  types and logical-complex rejection.
- Axes Position/InnerPosition properties and preservation across plot
  replacement. A new ABI 2.12 host environment setter supports six-unit
  conversion without guessed geometry; opt-in v4 snapshots freeze the metrics
  and their revision. See [layout development](axes-layout-development.md).
- Side-effect-free current runtime graphics snapshots, identity lookup and
  atomic identity-targeted property writes. The owning current graph and live
  object are checked under the same locks as mutation; see
  [writeback contract](graphics-writeback-contract.md).
- Explicit source-graph class-method ownership through a new C/C++ compile
  entry point, preserving declaration/implementation source locations and
  the original source-unit ABI. Downstream integration validation is ongoing.
- Function-form method dispatch after argument evaluation, with
  variable/local-function precedence and existing method access checks.
  R2024b-backed cases include external implementations, non-first object
  arguments, multiple outputs, inheritance and builtin overloads. See
  [validated scope and remaining gaps](function-method-dispatch.md).
  Objects registered in a shared Runtime retain their original owner across
  commands, including output-count routing, visibility and deletion lifecycle.
  Session event listeners survive owner-VM recreation; weak source links and
  closure reachability prevent registry-only retention without dropping live
  coupled callbacks. Cross-owner event access/data validation preserves the
  actual source/data class ownership and diagnostic provenance.

- Compile-time rejection and diagnostics for empty assignment RHS and keyword
  assignments, plus side-effect-free SDK identifier validation.
- Authoritative SystemContext search-path snapshots/replacement without source
  execution; hosts can compile later commands/files against the actual path.
- Internal opt-in assignment display recording with committed root labels,
  frozen text/structured values, suppression and source/order metadata; multi-output writes now
  commit left to right, and uncaught HIR failures stop later statements.
  A shared internal journal orders those events with text/warnings/diagnostics
  across module/eval boundaries, retaining nested capture and caught-error state.
  Expression labels/ans now follow actual variable loads versus computed
  values in scripts and functions, with ordered comma-list results, correct
  suppression and implicit nargout. Legacy public script-only projection
  remains separate from the internal complete transcript.
  An explicit opt-in read-only SDK result collection now exposes protected
  snapshots and ordered records with retained-result limits. It is not live
  delivery or bounded in-flight recording. See
  [ordered execution events](ordered-display-events.md) and
  [development boundaries](assignment-display-development.md).
- R2024b-reference-backed contextual identifier handling for transpose,
  function handles, argument blocks, name-value calls and property declarations,
  preserving declaration-context rejections rather than accepting all names
  indiscriminately.
- Compiler-produced function/local/nested/method definition metadata with
  hierarchy, source identity and UTF-8 byte ranges.
- Current Figure/Axes lifecycle, matrix plotting and handle arrays, bound Text
  labels, grids, automatic Legend entries and per-Line Clipping properties.
- Stateful Legend membership, AutoUpdate and String property labels with
  original Line DisplayName updates; see [Legend scope](graphics-legend-contract.md).
- Floating colon length/endpoint planning and symmetric element construction
  fix the host-reported `0:0.05:10` missing sample in actual XData. The same
  numeric plan drives Portable/Native nested loops; see
  [reference and boundaries](graphics-colon-contract.md).
- Opt-in graph/object identities in immutable result snapshots and value
  snapshots, without changing legacy v1/v2 output.
- Kernel-normalized Line/Text Color names, hex, none and numeric class rules;
  Line alpha is preserved in rendering snapshots while source reads stay RGB.
  See [Color contract](graphics-color-contract.md) for R2024b evidence/boundaries.
- [Figure export](graphics-export-contract.md): owning/current Figure resolution,
  PNG/PDF filename checks, optional ABI 2.13 renderer callbacks, and explicit
  headless renderer-unavailable errors;
  no PNG/PDF encoder or browser-based command substitution is provided.

## Contract Selection

Builtin contract 1.23 adds measured `print`/`saveas` target and filename
validation. ABI 2.13 exposes the adapter through an optional invocation tail
without adding symbols. A bounded SDK probe produces genuine PNG/vector PDF,
but no production encoder is installed by the SDK. The isolated source-copy
MExecServer now also verifies real REST execution and session-file publication
through that callback. A separate ABI 2.13 Tabbit replay verifies actual
current-view PNG downloads and lifecycle states; it does not implement browser
PDF downloads or substitute for kernel `print`/`saveas`. See the
[export contract](graphics-export-contract.md) and
[browser evidence](host-browser-acceptance.md#abi-213-browser-png-replay).

The [host definition navigation candidate](host-definition-navigation-candidate.md)
uses real single/multi-source compiler metadata for exact editor selections.
Actual Tabbit interaction covers repeated nested names, method declarations
and implementations, CRLF and edit/undo freshness on isolated copies only.

The [ordered display client candidate](host-ordered-display-candidate.md)
consumes the existing read-only event collection through a default-OFF checkbox.
Installed-SDK REST and actual browser interaction/DOM checks now cover historical
assignment order, suppression and failure-prefix display. Screenshot capture,
debugger/live delivery and production deployment remain separate gates.

The explicit-layout Canvas source-copy candidates consume v4 environments,
measure host metrics and draw multiple Axes. A bounded actual Tabbit run checks
metrics, dual-Axes pixels, DPR/resize, selection/zoom and close/reload. Its old
390px failure is closed by the later compact source-copy candidate, not by a
kernel workaround. See [Canvas candidate boundaries](host-canvas-layout-candidate.md).

Builtin contract 1.22 adds variadic Legend creation labels, ordered/duplicate/
cross-Axes Line subsets, supported name-value forms and correct graphics-array
delete/isvalid dispatch. Eighty actual R2024b cases anchor this slice; full
Legend text/layout, deployed adoption and release acceptance remain separate;
bounded actual repeated/cross-Axes browser workflows now pass.

The active installed MParser_PUBLIC_CONTRACT_FILE points to
host-integration-contract-development.json, which is explicitly development
state and pins live SDK artifacts. MParser_BASELINE_PUBLIC_CONTRACT_FILE points
to immutable public-contract-v1.14.json. The v1.14 release tag, frozen C/C++
headers and historical protocol/catalog snapshots are unchanged.

No v1.15 tag, GitHub release, authenticated release archive or production SDK
update is established merely by this version increment.
