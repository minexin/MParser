# MParser v1.3.0 Candidate

MParser v1.3 is the system, dynamic-language, persistence, and broad standard
library train built on the v1.2 numeric/runtime foundation. It is a stable
MATLAB-like subset candidate, not a claim of complete MATLAB or toolbox
compatibility. Fifteen implementation batches form one release milestone;
individual function groups were not published as separate product versions.

## Scope

The completed train provides:

- a session-owned system context for current/search/temporary paths,
  environment, filesystem, process, clock, sleep, random, and file-handle
  services, with explicit host capabilities and deterministic test adapters;
- workspace inspection and mutation, contextual `current`/`caller`/`base`
  evaluation, command syntax, warnings, output capture, path management,
  filesystem metadata and mutation, process execution, date/platform queries,
  and reproducible random state;
- rooted C and C++ system-context embedding over C ABI generation 2 revision 1,
  including retained ownership, caller-sized options, allocation/fault
  containment, and independent installed consumers;
- formatted text and binary file operations, text conversion/query functions,
  N-dimensional ordering, collection and set operations, higher-order
  `cellfun`/`arrayfun`, array transforms, number theory, and random utilities;
- exact wide-integer formatting and ordering, dense real/complex numeric class
  preservation, shaped missing values, Cell text, and variable-block
  N-dimensional `cell2mat` assembly through shared runtime authorities;
- Cell `switch` cases, active-scope nested lexical functions, bytecode Cell
  comma-list outputs, and implicit indexed Struct creation without adding
  engine-specific execution paths;
- transactional `save`/`load` through a repository-owned, resource-bounded MAT
  v5 codec for dense numeric, logical, complex, character, Cell, and Struct
  values, with checked MATLAB R2024b interchange evidence;
- repository-owned C++20 advanced numerical implementations for statistics,
  dense linear algebra, eigensystems, FFT/IFFT, convolution, and polynomial
  fitting, without Eigen or a platform-specific numeric dependency;
- guarded bytecode authority and portable/native fallback for every legal
  value or call shape not represented by Typed IR.

The registry is the single builtin catalog and invocation authority. Its
implementations are organized by numeric, array, text, conversion, callback,
and system responsibility; the HIR interpreter and bytecode VM do not carry
parallel builtin implementations.

## Candidate Contract

The v1.3 boundary is frozen in `docs/public-contract-v1.3.json`:

| Boundary | Candidate identifier |
| --- | --- |
| Product and installed SDK | 1.3.0 |
| Production CLI | 1.0 |
| C source API | 1.3.0 |
| C ABI | generation 2, revision 1; 117 symbols; SOVERSION 2 |
| C++ source API | 1.3, header-only C++20 |
| Machine result protocol | `mparser.result` 1.1 |
| Builtin source contract | 1.12; 275 descriptors, 277 registered names |

Product and source API versions advance together. The C ABI generation,
machine protocol, CLI contract, and builtin source contract remain independent
compatibility identities and advance only when their own contract changes.
The v1.0 and v1.2 contracts and snapshots remain immutable historical evidence.

The candidate validator locks the current C/C++ headers, ABI 2.1 symbol list,
C++ 1.3 snapshot, machine protocol fixtures/schema, builtin 1.12 catalog,
extension guide, package metadata, and normalized SHA-256 values. Installed
C11 and C++20 consumers verify that package metadata reports the same product,
source API, ABI, protocol, and builtin contract versions.

## Runnable Evidence

Representative production commands are:

```text
mparser --run samples/system_services_demo.m
mparser --run samples/dynamic_workspace_demo.m
mparser --run samples/filesystem_management_demo.m
mparser --run samples/file_io_demo.m
mparser --run samples/standard_library_demo.m
mparser --run samples/utility_library_demo.m
mparser --run samples/advanced_numeric_demo.m
mparser --run samples/dynamic_language_semantics_demo.m
mparser --run samples/mat_file_demo.m
mparser --run samples/file_metadata_demo.m
mparser --run samples/conversion_set_callback_demo.m
```

Each slice has direct C++ tests plus applicable HIR, bytecode, and production
CLI execution. System tests cover denied and injected capabilities; callback
tests cover multiple outputs, error handlers, and cancellation; numeric and
set tests cover exact 64-bit, complex, N-dimensional, large-input, and
shape-only missing boundaries.

## Differential Evidence

MATLAB R2024b accepts all 223 imported capability cases. The latest complete
rerun at
`MParserV1.0Test/results/20260823-091751-v1.3-candidate` records 219
MParser matches and 4 categorized gaps, with no earlier match regressing. The
remaining observed cases require `datetime`, `table`, `sparse`, and graphics
families; they are not hidden by scalar shims or reclassified as v1.3 support.

Repository tests generalize beyond those individual scripts through exact
integer boundaries, N-dimensional shapes, malformed source/file inputs,
resource stops, callback failure, host denial, session reuse, concurrency,
MATLAB MAT-file interchange, and guarded optimization fallback.

## Validation Boundary

The local candidate gate passes warnings-as-errors native Release `278/278`,
fresh no-JIT Release `270/270`, and MSVC ASan no-JIT `270/270`. Native and
no-JIT release archive checks build independent C11/C++20 consumers from the
unpacked SDK and verify CLI protocol/version metadata. The 223-case
differential rerun records `219/223` matches with the same four categorized
gaps. The candidate commit must additionally pass the project's Windows,
Linux x64, native Linux ARM64, macOS x64/ARM64, and Linux Clang ASan/UBSan CI
lanes; their run identifier is recorded after the source commit.

## Later V1.x Work

v1.4 owns benchmark-driven advanced mathematics and wider Typed/JIT coverage,
including straight-line and dense-array regions, fusion, reductions, and
function specialization where measured evidence justifies them. v1.5 owns
coherent sparse, datetime/duration, categorical, table/timetable, ownership,
and inspection slices. Graphics, Live Scripts, MEX, Simulink, and complete
toolbox compatibility remain explicitly outside this candidate.
