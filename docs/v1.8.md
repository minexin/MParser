# MParser v1.8 Rich Tabular Data Batch

v1.8 is the current rich-data development batch on the MParser 1.3 candidate
contract line. It completes a coherent categorical value family, closes the
most important rectangular table gaps left by v1.7, and adds the first
timetable vertical slice without changing the public C/C++ value ABI.

## Scope

This batch advances the builtin source contract to 1.16 with 324 descriptors
and 326 registered names. The new values use repository-owned portable C++20
implementations and the existing `RuntimeValue`, `BuiltinCall`, bytecode VM,
embedding, and transactional fallback contracts. No Eigen dependency or
parallel runtime path is introduced.

### Categorical values

`categorical` stores an N-dimensional shape, an ordered category dictionary,
and one `uint32` code per logical element. Code zero represents undefined.
The runtime supports:

- construction from numeric, text, Cell, missing, or existing categorical
  values, including explicit value/category sets and `Ordinal`/`Protected`;
- parenthesis indexing, indexed growth and deletion, horizontal/vertical/N-D
  concatenation, copy-on-write mutation, and undefined fill for gaps;
- equality/inequality, ordered comparison for ordinal values, conversion to
  string or category codes, and `ismissing`/`isundefined` masks;
- `categories`, `countcats`, `addcats`, `removecats`, `renamecats`,
  `reordercats`, `mergecats`, `isordinal`, and `isprotected`;
- categorical table variables, nested table member assignment, and
  categorical-aware `sortrows`.

Category dictionaries remain internal runtime data. Categorical values cross
the C API and machine protocol as immutable opaque objects rather than a new
public payload layout.

### Table completion

The shared tabular layer now additionally supports:

- row deletion with `T(rows, :) = []`;
- arbitrary rectangular multi-variable brace assignment;
- horizontal and vertical table concatenation with name/shape checks;
- stable `sortrows` with variable-name or numeric selectors and an order
  output;
- categorical variables and transactional nested copy-back.

The v1.7 table storage is generalized into `RuntimeTabularStorage`; table and
timetable retain distinct runtime classes while sharing variable, metadata,
row-axis, validation, and copy-on-write machinery.

### Timetables

`timetable` stores datetime or duration `RowTimes` alongside named variables.
The current slice supports:

- construction from an explicit first temporal input or `RowTimes`, plus
  `array2timetable`, `table2timetable`, and `timetable2table`;
- duplicate, out-of-order, and `NaT` row times;
- ordinary numeric/logical/colon row selectors and exact datetime/duration
  selectors, where one requested time selects every matching duplicate row;
- variable/member access, brace extraction and assignment, row deletion,
  horizontal/vertical concatenation, and `sortrows`, which defaults to
  RowTimes and also accepts the row-time dimension name as a key;
- `Properties.RowTimes`, direct first-dimension access (default name `Time`),
  copy-on-write RowTimes assignment, and synchronized row transforms;
- shared `height`, `width`, `table2array`, HIR/VM behavior, and production CLI
  execution.

When source-expression names are unavailable, MParser uses stable generated
names such as `Time` and `Var1`; it does not claim MATLAB caller-expression
name inference.

## Execution And Embedding

Categorical, table, and timetable values are semantic VM values. HIR and
bytecode paths share the same runtime operations. Typed/portable/native
execution does not lower these rich values; legal scripts use the existing
guarded fallback to the bytecode VM, with no partial state committed on a
failed optimized attempt.

The C API recursively detects module-bound data inside table/timetable
variables, RowTimes, properties, and user data. Module-independent rich values
may be retained and passed between modules as opaque objects. Machine results
publish class and dimensions without exposing internal dictionaries or
tabular storage.

## Runnable Evidence

```text
mparser --run samples/categorical_demo.m
mparser --run --jit=portable samples/categorical_demo.m
mparser --run --jit=native samples/categorical_demo.m
mparser --run samples/timetable_demo.m
mparser --run --jit=portable samples/timetable_demo.m
mparser --run --jit=native samples/timetable_demo.m
```

The categorical sample prints `categorical summary=9` and
`tabular summary=29`. The timetable sample prints
`timetable summary=45`. Registered tests cover direct runtime operations,
HIR/bytecode/production parity, portable/native fallback, C API retention,
machine-protocol opacity, source layout, catalog snapshots, and release
archive contents.

## Explicit Limits

This batch does not yet provide joins, grouping, `rows2vars`, `stack`,
`unstack`, `retime`, `synchronize`, `timerange`, calendar-duration row times,
timezone databases, table/timetable MAT persistence, exact MATLAB display, or
MATLAB `TableProperties` object identity. Empty timetables with no variables
have a deliberately narrow conversion boundary. Categorical locale/collation
behavior and the complete MATLAB conversion surface remain later work.

Graphics, GPU arrays, complex-integer arrays, MEX, Simulink, Live Scripts,
and complete MATLAB/toolbox compatibility remain outside this milestone.
