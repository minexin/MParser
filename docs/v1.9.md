# MParser v1.9 Relational Table Batch

v1.9 is the relational-table development batch on the MParser 1.3 candidate
contract line. It adds a coherent join and grouped-summary vertical slice on
the shared table storage introduced in v1.7-v1.8, without changing the public
C/C++ value ABI or creating a separate execution engine.

## Scope

This batch advances the builtin source contract to 1.17 with 328 descriptors
and 330 registered names. The implementation uses repository-owned portable
C++20 code, shared `RuntimeValue` table storage, the normal
`BuiltinRegistry`/`BuiltinCall` path, and cooperative execution control. It
does not add Eigen or another numerical dependency.

### Table joins

`innerjoin` and `outerjoin` accept two tables and support:

- common-name key inference or explicit `Keys` and paired
  `LeftKeys`/`RightKeys` selectors;
- `LeftVariables` and `RightVariables` projections;
- `outerjoin` `MergeKeys` plus `Type` values `left`, `right`, and `full`;
- up to three outputs: the joined table and one-based left/right row maps,
  with zero representing an unmatched outer row;
- stable duplicate-key Cartesian expansion in left-row then right-row order;
- MATLAB-style `_L`/`_R` conflict suffixes and deterministic suffixing when a
  generated name already exists;
- empty tables and explicit zero-variable projections without losing row
  count;
- numeric keys across MATLAB numeric classes, including exact integer and
  complex comparison, plus char/string, categorical, datetime, duration,
  missing, and scalar numeric/text/missing Cell keys.

Numeric `NaN` and temporal `NaT` do not match during joins. When keys are
merged, right-only key rows are converted to the left key class; the operation
fails deterministically if a value cannot be represented by that class.
Unmatched non-key values use class-appropriate missing data such as `NaN`,
missing string, blank character, undefined categorical, `NaT`, or missing
Cell elements.

### Grouping and summaries

`groupcounts` accepts a table or timetable and one or more grouping variables.
It returns the sorted group keys, `GroupCount`, and `Percent`. Missing and
`NaN` keys coalesce into deterministic groups rather than being discarded.

`groupsummary` accepts the same grouping selectors. With no method it returns
the group keys and counts. With methods and optional data-variable selectors,
it delegates `sum`, `prod`, `mean`, `min`, `max`, `median`, `std`, `var`,
`any`, and `all` to their existing registry implementations and emits names
such as `mean_X`. Summary method names and join option names are ASCII
case-insensitive. Empty inputs preserve zero-row output shapes.

The current summary slice requires numeric data variables. Keeping reductions
on the registry path preserves their existing numeric-class, complex,
diagnostic, and execution-control behavior instead of introducing a tabular
copy of each algorithm.

## Execution And Fallback

Join and grouping work remains a semantic VM operation. HIR and bytecode
execution share the same runtime implementation. Portable and native JIT modes
fall back through the existing guarded bytecode path, so unsupported rich
values do not make a legal script fail or expose partial state.

The four descriptors are context builtins with `ExecutionControl` permission.
Index construction, matching, duplicate expansion, row materialization,
grouping, and per-group reduction cooperate with cancellation and resource
limits. A stopped operation reports `MParser:ExecutionStopped`.

## Runnable Evidence

```text
mparser --run-hir samples/table_relational_demo.m
mparser --run-bytecode samples/table_relational_demo.m
mparser --run samples/table_relational_demo.m
mparser --run --jit=portable samples/table_relational_demo.m
mparser --run --jit=native samples/table_relational_demo.m
```

Every mode prints `table relational summary=115.5`. Registered tests cover
duplicate and unmatched order, row maps, option parsing, variable-name
conflicts, empty tables, cancellation, exact cross-class numeric and complex
keys, char/string conversion, categorical and temporal keys, Cell missing
groups, summary dispatch, all five CLI paths, catalog snapshots, and release
archive contents.

## Explicit Limits

Joins currently accept table/table inputs; timetable joins and row-time-aware
joining remain later work. `groupsummary` provides fixed builtin method names
and numeric data variables, not arbitrary function handles or rich-value
aggregations. Locale-aware text collation, tolerance-based numeric keys,
stack/unstack, `rows2vars`, `retime`, `synchronize`, `timerange`, distributed
or out-of-core algorithms, and exact MATLAB display/property identity remain
open.

Graphics, GPU arrays, MEX, Simulink, Live Scripts, and complete MATLAB/toolbox
compatibility remain outside this milestone.
